### Stage1-D1 OOPSLA-adapted 处置开发预检结果

#### 结论

`D1_COMPLETE`，`scientific_go=false`。OOPSLA 2026 论文描述的三规则与两类处置可以在真实 mini-swe-agent loop 中因果执行：Plan/Oscillation 在工具执行前抑制当前 action，Stagnation 保留已执行 action 与历史后追加阶段建议。该实现明确是论文规则忠实适配，不是官方 OMI 复现。

本次 `django__django-11265` 未解决任务。Agent 到达20次模型调用上限，形成19个 action attempt，其中17个真实执行、2个在执行前抑制；最终无代码 patch。独立 evaluator 完整运行1个 F2P与30个P2P，共31项测试，rc=1。该任务仅为开发预检，不计入 Stage1 自然 Pilot 样本。

#### 干预证据

- attempt 0：`pwd && ls -la && find ... 2>/dev/null` 被官方 phase mapper 判为 `patch`，在无 prior localization 时触发 `patch_before_localization`，未调用工具。
- attempt 1：`ls -la` 使 raw Process View 最新 exec edge 构成有向环，触发 `latest_exec_edge_closes_cycle`，未调用工具。
- attempt 5：连续五个 localization/navigation attempt 无 patch，当前 action 已执行并保留，随后追加一次 phase advice。
- 19/19 attempt prefix 的 occurrence/exec-edge projection 与最终图同长切片一致。
- proposed action 的空 observation 仅供官方 parser 构造当前结构，均显式记录 `hypothetical_observation_for_structure_only=true`，不作为执行证据。

#### 有价值的负结论

首个被抑制 action 实际是只读定位复合命令，却因 `2>/dev/null` 再次命中 C2 已发现的官方 phase fallback，被误当作 patch。OOPSLA-adapted raw baseline 因而会实施一次明显可疑的早期抑制；随后对重复 `ls` 的 raw cycle 抑制也不检查 workspace progress。这不是实现错误，而是事前冻结的“without Evidence”强基线边界。

该自然证据支持修订版 M2 的分层，而不是授权改变方向：Process View 只生成 candidate；本文 Hybrid 必须用真实 workspace diff、return code与 probe transition限制事实和回退权限。正式 Pilot 必须保留 OOPSLA-adapted 原样比较，不能事后替它增加 Evidence 来提高成绩。
