### 研究主线偏移审计

日期：2026-08-20
结论：本目录暂停，降级为基础设施预检，不计入 RQ1 可行性 Go 证据；其中已排除实现错误、数据泄漏和未完整执行后得到的负结果仍作为方向排除与适用边界证据保留。

#### 1. 与修订版主线的偏移

修订版将 RQ1 定义为“过程证据驱动的在线故障检测与纠偏”，要求在不读取未来事件和终局结果的条件下，检验故障是否能及时被发现、纠偏是否改善真实 Agent 任务结果，并控制误报、误干预、延迟与成本。

当前 DEV 实现偏向了这个研究任务：

1. 固定故障位置和固定探针暴露位置，只能检查数据与管线是否可运行，不能回答及时检测、可恢复故障或自然故障。
2. API 调用固定为零，且没有在真实 Agent loop 中执行建议或回退，无法验证修订版 M2/M3 的互补性与净收益。
3. 两个无关编辑与固定依赖边会先验性地让 graph slice 比 flat window 更窄，不能作为方法增益证据。
4. 当前 `ProcessEvidenceGraph` 是自定义的逐事件图与验证依赖切片，不是 OOPSLA 2026 Graphectory 的忠实实现；因此不能用该论文的结论为当前方法成绩背书。
5. 快照、Git 提交、JSON 合同、Hook、固定预算和泄漏审计属于实验协议或实现细节，可以保证可复现性，但不是研究方法或可行性结论。

#### 2. 本目录仍可保留的用途

- 验证前缀不变性、无未来泄漏和结构化事件序列化；
- 预检仓库快照、轻量探针、日志和脱敏链路；
- 在正式论文方法复现完成后，作为新方法的工程承载层候选。

上述用途均不得被写成论文贡献，也不得与 P1/P2 成绩混合汇报。

本次降级是结论口径修正，不是删除证据。完整且有效的实验应分别记录为：正向可行性证据、方法/模块的无增益或适用边界证据、以及对错误研究路线的排除证据。只有执行不完整、实现有错、存在泄漏或比较不公平的运行，不得用于方向判定。

#### 3. 恢复研究主线的顺序

1. 先复现 OOPSLA 2026 *Process-Centric Analysis of Agentic Software Systems* 的正式工件，核验 Graphectory 表示、阶段映射、在线监测规则和干预语义。
2. 以复现证据冻结 RQ1 研究假设，再定义本文相对 OOPSLA/SAFE 的可证伪增量，不先拼装自定义管线。
3. 在真实 SWE-Gym/SWE-bench Agent loop 上运行 P2，比较 Vanilla、OOPSLA 方法、同预算 Periodic API 和本文方法，先验证自然任务的方向性收益。
4. 再按修订版 P1 构建注入位置分散的三类受控故障与干净对照，专门测量告警时机和候选区间。
5. RQ1 的方法、阈值和原始输出冻结后，才允许 RQ2 消费预测区间、检查点和证据。

#### 4. 可接受的下一个可行性证据

下一步不追求 Go 数字，而追求“论文方法能否忠实落地”：使用 OOPSLA 官方 Graphectory 工件的固定版本，复现过程表示与在线监测样例，并证明其能在本地真实软件 Agent 轨迹上增量运行。该复现通过后，才进入本文增量方法实验。
