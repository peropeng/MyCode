# 结论47：RQ1 到 RQ2 桥接审计与 Exp122 正式阻塞

日期：2026-08-31

状态：历史证据形成限定性结论；Exp122 联合正式实验因外部资产缺失而阻塞，未消耗正式次数

## 一、审计裁决

1. Exp113J 的 `rankings` 是 Exp112/112C 的 RQ1 模型在 E02 八步窗口上的完整 `0..7` 排序，可作为“原始 RQ1 完整排序”。
2. Exp116E/121 的 native order 不是原始 RQ1 完整排序。它只保护 RQ1 Top-1，尾部由 outer-train-only 的 RQ2 candidate posterior 重新排序。因此，“RQ2 继承 RQ1 完整排序”的旧表述过强；当前能严格成立的是“RQ2 保护并继承 RQ1 Top-1”。
3. Exp120 的 `a_plus_b_prime` 确实把原始 RQ1 完整排序用于 dependency pool，得到 9/34 个成功任务；但其 `a_deletion`、`a_shuffle` 在 original singleton pool 上运行，不能作为同池排序消融。
4. Exp121 的 native dependency condition 得到 14/34。Exp120/121 的七组共享条件在全部稳定科学字段及实际预算前二位上逐 task×seed 一致，说明跨运行环境具有可比性；但这仍是 posthoc cross-run 证据，不能替代一次联合正式实验。

## 二、当前可报告的定量边界

原始 RQ1 完整排序 dependency 与 Top-1+RQ2 posterior dependency 的历史配对结果为：

- 成功任务：9/34 对 14/34，净差 +5/34；6 个任务获益、1 个任务损失。
- 102 个 task×seed 行中：18 胜、3 负、81 平；两臂 Top-1 在 102/102 行完全相同。
- task-group bootstrap 均值为 0.1471，95% CI 为 [0.0000, 0.2941]。下界触及 0，不能宣称 posterior tail 已被统计证明优于 raw RQ1 tail。
- 两臂 attempts、cost、probes 完全相同，分别为 183、3357、183；harmful recovery 为 raw 57、posterior 63。后验臂成功更多，但伤害计数也多 6，不能只报告收益端。

Exp121 内部的范围/身份分解为：native singleton 7/34、extent 12/34、dependency 14/34。相对 singleton 的主要增量来自扩大恢复范围（+5/34）；同等 extent 下的 dependency identity 仅再增加 +2/34，bootstrap 下界触及 0。故现有证据支持“范围扩张是主要来源，依赖身份可能有附加收益”，不支持把全部提升归因于依赖闭包身份。

## 三、对两章主线的安全表述

- RQ1 已提供可冻结、可部署的 Top-1 诊断入口，并产出完整排序；完整排序作为 RQ2 恢复顺序时存在 9/34 的历史恢复信号。
- RQ2 的当前强证据是：在保护 RQ1 Top-1 后，outer-train-only 的 RQ2 posterior tail 与依赖切片范围共同把历史成功任务提升到 14/34。
- 不能写成“RQ2 的全部恢复收益来自 RQ1 完整排序”，也不能写成“RQ2 posterior 已正式显著优于 RQ1 完整排序”。
- RQ1→RQ2 的完整因果桥仍需 Exp122 同池、同缓存、同预算、同一次 held unseal 的联合正式结果闭合。

## 四、Exp122 已冻结的联合验证

Exp122 同时注册 raw RQ1 full rank、protected-Top1+RQ2 posterior tail、protected-Top1+canonical tail、full-rank rotation、fixed、uniform，以及 singleton/extent/dependency 范围条件。所有非 Oracle 条件预算为 2；每条件必须恰有 102 个共同 task×seed 键；五组成对 task-group bootstrap 在协议中预注册。

其中 full-rank rotation 会移动原 RQ1 Top-1，只是完整排序身份/顺序 null；真正隔离尾部价值的是 raw-vs-canonical 与 posterior-vs-canonical 两个 protected-Top1 对比。候选缓存按每个 task×seed 各构造一次 original、extent、dependency，并由运行时审计推导条件到缓存的复用关系。

## 五、真实阻塞与继续条件

当前主机缺少历史 SFT parquet、34 个本地 repository source，活动 Python 也没有 `pyarrow`，因而无法加载 34-task visible projection。迁移说明明确禁止猜测下载 URL，所以本轮没有伪造资产、没有运行 `--run`、没有写 attempt claim；授权文件仍为 `authorized=false`，正式 invocation count 仍为 0。
