# 结论44：核心论文局限交叉复核与“动态授权”候选方向

> 状态：`V1 REJECTED_OVERLAP；只保留为待重定义问题簇`
> 日期：2026-08-21  
> 用途：在 A/B/C 已 STOP、D 仍在隔离重评的情况下，从核心论文作者自述局限中反推下一个可检验方向。本文不把文献推理写成实验正结果。

## 0. 最新重叠性更正：本文第4节的 V1 两章不能直接进入数据 Gate

在完成本文首版后，又核对了两篇直接重叠的 2025 年正式论文：

1. [The Task Shield，ACL 2025 Long](https://aclanthology.org/2025.acl-long.1435/) 已经把“每个指令和工具调用是否服务用户目标”定义为 test-time task alignment，并在 AgentDojo 上评估 utility/security。这与第4.2节“动作级策略授权”的主任务几乎直接重合。
2. [IPIGuard，EMNLP 2025 Main](https://aclanthology.org/2025.emnlp-main.53/) 已经用 Tool Dependency Graph 把规划与外部数据交互解耦，通过 pending node、argument estimation、node expansion 处理前序工具返回才能决定后续动作的 dynamic planning task。这与第4.3节“依赖感知的动态最小权限”在输入、执行依赖和阻断机制上高度重合。

因此，第4节的 V1 题目和两章合同当前裁决为 **`REJECTED_OVERLAP`**，不得按原定义执行 AgentDojo Gate0/1，也不得宣称为可开题方向。下文保留为第一轮推理记录，但被本节覆盖。

两篇论文自述的剩余缺口是：

- Task Shield 依赖强 defender LLM，弱模型或对抗探测会产生误放/误拦；每个 assistant response 和 tool output 都要额外 LLM call；主实验仅 GPT 家族和 AgentDojo，未验证开源 backbone。
- IPIGuard 只防干预 tool usage 的 injection，不防只篡改文本输出的攻击；因 LLM 调用成本而规模受限；依赖较强的 planning model。
- USENIX Security 2026 SoK 进一步指出，当前 Agent IAM/access-control 工作主要集中在 RAG/vector database，对多工具、多数据源和多 Agent 的 runtime-adaptive policy 仍缺少统一框架，但这只能证明问题簇存在，不能自动变成两章可行方案。

剩余缺口目前仍不足以进入实验，原因是：

1. “更轻量/少调 LLM”容易退化为成本优化，不足以支撑两个独立研究问题；
2. “短期 lease/撤销/多任务 context drift”尚未找到同时具备正式 CCF A 方法站台和公开、可执行、有程序化 Gold 的多任务轨迹；
3. 仅用固定 AgentDojo response 做 block 干预，会面临 off-policy suffix，无法验证 IPIGuard 已经覆盖的真正 replanning/dynamic traversal；
4. Task Shield 未释放可确认的官方代码，IPIGuard 官方代码依赖 OpenAI-compatible API；当前还不满足强基线公平复现条件。

所以 BFCL 最终 STOP 后，正确的下一步将不是直接实现 V1，而是先执行一个 **新方向 Gate0 重定义审计**：把 Task Shield 和 IPIGuard 作为必须超过的直接强重叠工作，先证明新 RQ 在任务、输入、机制、Gold 和外测上至少有一项实质区别；无法证明即整个安全/授权问题簇 STOP，重新选题。

## 1. 当前严格事实

1. 方向 A / AppWorld：`STOP`。可执行环境与任务存在，但目标 train/dev 上可用的官方自然 action trajectory 不存在，不能用 Gold 倒推 Agent response。
2. 方向 B / 记忆：`STOP`。四类官方资产中，完整自然 `memory -> retrieve/use -> tool/result -> 独立 Gold` 案例为 0。
3. 方向 C / DevAI：`STOP`。365 个 requirement 中独立 requirement-to-evidence Gold 映射为 0/365。
4. 方向 D / BFCL：Gate0/1 `GO`，但实验44--46旧科学分数因 evaluator 跨候选状态污染而 `INVALID`；隔离重评未完成验收。
5. 因此当前仍为 **0 个方向达到两章 GO**。本文提出的新方向只有文献可辩护性，尚没有数据可行性证据。

## 2. 核心论文的自述不足与交集

### 2.1 AgentDojo：静态工具隔离的明确边界

- 简单 tool filtering 在“正常任务只需读、攻击需要写”时有效。
- 论文明确说明两类失效：
  1. 下一步需要哪个工具取决于前一个工具的返回，因而无法事先冻结全部工具集；
  2. 合法任务和攻击共用同一组工具，论文报告该情况占其测试约 17%。
- 论文还未覆盖不重置上下文的多任务时间序列；作者建议更强的隔离、planner 分发和符号化交互。
- 这直接支持“按当前状态和依赖关系动态授予/撤销能力”，而不支持继续做静态工具黑白名单。

正式资料：[AgentDojo，NeurIPS 2024 Datasets & Benchmarks Track](https://proceedings.neurips.cc/paper_files/paper/2024/hash/97091a5177d8dc64b1da8bf3e1f6fb54-Abstract-Datasets_and_Benchmarks_Track.html)。它可作为数据/环境资产，不冒充 CCF A 主会 Full/Regular 方法论文。

### 2.2 GuardAgent：代码守卫的可执行性依赖与未完成问题

- 方法由 LLM 生成 task plan，再转换成 guardrail code；工具箱和经验记忆用于提高可执行性。
- 作者在 Conclusion and Future Research 中明确保留：自动工具箱设计、更强的任务规划推理、用于保护多种 Agent 的多 Agent 框架。
- 这说明“守卫代码能运行”不等于“当前动作所需的最小权限被正确、及时地绑定”。

正式资料：[GuardAgent，ICML 2025](https://proceedings.mlr.press/v267/xiang25a.html)。

### 2.3 ShieldAgent：显式策略验证很强，但仍非动态最小权限

- ShieldAgent 将策略文档抽取为 action-based probabilistic rule circuits，并对动作轨迹生成验证计划、执行形式化核验。
- 它的贡献是“对显式策略的动作轨迹合规验证”，不是在执行前根据工具输出依赖给予短期 capability lease，也不研究何时撤销已暴露的能力。
- 论文报告对 hallucination-related risks 略弱，原因是这些风险常需要策略外部知识。这进一步说明只有策略文档不足以包含全部执行语义。

正式资料：[ShieldAgent，ICML 2025](https://proceedings.mlr.press/v267/chen25ae.html)。

### 2.4 Authenticated Delegation：授权问题的理论站台与待解难点

- 论文把 Agent 代理授权、问责和访问控制定义为一个完整的 Agent 治理问题，主张可验证的委托凭证与可审计范围。
- 作者明确列出自然语言 scope 翻译的四个风险：正确性难核验、新的 LLM 攻击面、上下文漂移、依赖第三方正确执行。
- 该文是 position paper，适合支撑问题定义和机制动机，不能替代我们的实证 Gate，也不应按 CCF Full/Regular 核心方法论文计数。

正式资料：[AI Agents Need Authenticated Delegation，ICML 2025 Position](https://proceedings.mlr.press/v267/south25a.html)。

### 2.5 AgentAuditor 与 SafeArena：评价标签和显式恶意意图不足

- AgentAuditor 的记忆增强 LLM evaluator 依赖 shot 标签质量，具有 CoT 方法共同的推理能力和资源开销限制，并且仅实证二元 safe/unsafe 标签。
- SafeArena 明确承认其任务中的恶意意图是显式的，因而可在外部直接检测；它还指出自动评测易碎，可能漏掉轨迹中的其他有害行为。
- 因此新方向不应做“看用户 prompt 的恶意分类”，也不应把 LLM-as-a-Judge 文字判断当 Gold；应使用可执行环境中的 utility/security 结果反事实定义动作授权标签。

正式资料：[AgentAuditor，NeurIPS 2025 Main](https://proceedings.neurips.cc/paper_files/paper/2025/hash/3dc85735f6e2fcf093e67b134fa00d21-Abstract-Conference.html)；[SafeArena，ICML 2025](https://proceedings.mlr.press/v267/tur25a.html)。

### 2.6 与可靠工具使用论文的交叉

- BFCL 指出当前模型在多轮、记忆密集和长程推理中明显下降；记忆类别中还会猜测 key、首次失败后过早放弃。
- tau-bench 发现复合请求、多个写操作、复杂领域规则与长程信息跟踪仍然困难，并特别提到冲突事实下的当前决策需要聚焦正确信息。
- AppWorld 报告 Agent 常遗忘当前状态与旧动作、重复工作，并将多 Agent 协同、安全和隐私作为后续延伸。
- 这些论文共同说明：动态授权不能只看单个 call 文本，必须显式表示当前状态、前缀证据和工具依赖。

正式资料：[BFCL，ICML 2025](https://proceedings.mlr.press/v267/patil25a.html)；[tau-bench，ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/1b126cc38b8638e07bef37e7b2bb72bf-Abstract-Conference.html)；[AppWorld，ACL 2024](https://aclanthology.org/2024.acl-long.850/)。

## 3. 交叉后的研究缺口

可辩护的缺口不是“Agent 不够安全”，而是：

> **当合法任务与攻击共用工具、下一步所需能力取决于前序执行结果时，如何将用户委托和环境证据转换为动作级、有时限、可撤销的最小权限，并在不明显伤害任务效用的前提下阻断越权执行？**

它同时命中四类已公开局限：

1. AgentDojo 的静态 tool filter 无法预见动态依赖；
2. GuardAgent/ShieldAgent 主要做策略生成与合规验证，没有直接回答 capability 何时暴露、续期和撤销；
3. Authenticated Delegation 提出了可验证授权架构，但自然语言权限翻译、上下文漂移和执行可靠性仍未解；
4. AgentAuditor/SafeArena 暴露了评价对标签、明显恶意意图或 LLM judge 的依赖。

## 4. 候选题目与两章结构

### 4.1 暂定题目

**《面向工具智能体的动作级策略授权与动态最小权限控制方法研究》**

在 Gate1 前不使用“可靠”、“自主恢复”、“因果”等尚未被数据支持的强词。

### 4.2 第一章：可执行证据约束的动作级策略授权

- 白话问题：在一个工具调用真正执行前，如何判断它是完成用户任务所必需、可安全执行，还是应被拒绝/暂停？
- 学术定义：输入用户委托、显式策略、公开 schema、当前轨迹前缀和 proposed call，输出 `allow / deny / abstain` 以及可审计的策略-资源-依赖证据。
- 独立 Gold：仅用可执行环境中的 counterfactual utility 变化和 attack-goal 达成变化生成，禁止 LLM judge 解释作为 Gold。
- 三个方法模块：
  1. **策略-资源绑定**：将用户委托与公开策略规范化为主体、动作、资源、约束和时效证据；
  2. **前缀依赖接地**：仅使用当前可见的 tool result 与 action dependency，判断 proposed call 是否已具备合法前置条件；
  3. **选择性授权**：对证据不足的调用 abstain，而不是为了安全全拒或为了效用全放。
- 章节主指标：任务结构分组 OOF macro-F1；辅指标为攻击使能动作 recall、效用必需动作 precision、abstention coverage-risk。

### 4.3 第二章：依赖感知的动态最小权限能力防火墙

- 白话问题：不是一开始就把全部工具给 Agent，也不是一次性删掉一组工具，而是能否随当前状态只给这一步必需的能力，执行后立即续期或撤销？
- 学术定义：仅消费第一章的任务级折外授权/风险分数与当前依赖状态，产生短期 capability lease，对工具能力执行暴露、限参、隔离、撤销或阻断。
- 独立结果：任务级 `J = utility_success AND NOT attack_success`，并分开报告 utility 和 attack success，不用拒绝率代替安全。
- 三个方法模块：
  1. **最小能力租约**：由当前动作的策略绑定与数据依赖生成工具/参数/资源级短期权限；
  2. **依赖驱动续期与撤销**：工具返回改变依赖后重算权限，防止一次授权在后续轨迹中无限留存；
  3. **选择性强制与安全终止**：对 deny/abstain 执行阻断或安全停止，并显式记录效用损失。
- 章节主指标：任务级 `J`；辅指标为 utility success、attack success、授权暴露面积、撤销延迟和执行成本。

### 4.4 两章关系为何不是伪递进

- 第一章有独立的动作授权 Gold 与 OOF 主指标，不依赖第二章才成立。
- 第二章仅能使用第一章的 OOF 预测，禁止使用 Gold 授权标签作正式结果。
- 必须比较 `No / Random / Shuffled / Predicted / Oracle`。`Oracle` 只回答信息是否有价值；`Predicted` 不优于全局最强公平基线时，两章桥直接 STOP。

## 5. 与最新重叠工作的实质差异

| 工作 | 它已经做了什么 | 本候选不能重复的部分 | 可辩护增量 |
|---|---|---|---|
| GuardAgent | 将 safety request 转换为 plan 和可执行 guardrail code | 再做一个 LLM 生成的守卫脚本 | 授权对象从“规则是否违反”变为“当前动作的最小、短期、可撤销能力” |
| ShieldAgent | 抽取策略规则并验证动作轨迹合规 | 只替换规则表示/提示词 | 将工具数据依赖和授权时效加入执行前控制，并用 utility/security 反事实验证 |
| AgentDojo ToolFilter | 事先冻结工具子集 | 换一套静态黑白名单 | 将论文明确的动态依赖失效边界变成逐步 lease/renew/revoke 问题 |
| AgentAuditor | 记忆增强 LLM 轨迹安全评价 | 安全文本分类或换 judge | 动作标签来自环境反事实，并必须转化为执行结果改善 |

## 7. 首个数据候选：AgentDojo，但不预判 GO

### 7.1 为什么优先它

- 它是 stateful 工具 Agent benchmark，包含官方已提交的模型轨迹、tool calls/tool outputs、utility 与 security evaluator。
- 正常任务和 injection task 并存，可直接测量效用-安全权衡。
- 论文自己明确指出静态 ToolFilter 的动态依赖失效边界，与候选增量直接对应。

### 7.2 已知陷阱

1. 旧 `runs/` 不总是显式记录 package/benchmark version，不能默认 join 到当前 suite。
2. AgentDojo 在 injection 场景下的 `security=True` 表示攻击目标成功，是坏事；必须重命名 `attack_success`，并以 `safe = NOT attack_success` 评价。
3. 阻断一个工具调用后，原轨迹后缀可能依赖被阻断的 tool output；这类样本必须标为 `OFF_POLICY_SUFFIX`，不得假装反事实可重放。
4. 官方 ToolFilter 会改变模型生成轨迹，若我们不重跑同模型，它只能作非配对外部参考，不能与固定 response 的局部干预混为一张配对表。
5. 若不调用新模型，第二章的严格研究对象只能称为 **execution-time capability firewall**，不能宣称已验证 prompt-time tool orchestration 改变了 Agent 规划。

## 8. AgentDojo Gate0/1 预注册

### Gate0：版本、轨迹和严格 join

- 锁定官方 repo commit 和稳定 package version；记录每个 run blob SHA、引入 commit、suite/package/benchmark version。
- 严格 join key：`repo_commit + package_version + benchmark_version + suite + user_task_id + injection_task_id + attack_type + pipeline_name + run_blob_sha`。
- 基础独立单位为 `(suite, canonical user_task)`；同任务的 attack/defense/model/rollout 都属于同一 group。
- 最低样本门：
  - 不少于 80 个唯一 base-task structures；
  - 覆盖 4 个 official suites；
  - 每个 base task 存在同 pipeline/model 的 clean 与至少一个 attacked episode；
  - 总计不少于 160 episodes。
- 不足即 `STOP`，不用模板改写或合成数据补数。

### Gate1：精确重放与反事实 support

- 从精确版本重建 initial environment 和 injections，只执行确实进入 runtime 的 calls；保留原 final assistant text。
- 用 fresh environment 双重放，重新计算 utility 和 attack success。
- 硬门：160/160 join 完整、stored labels 100% 复现、双 replay 100% 一致、0 harness error、每 suite 不为空、clean/attack pair 完整。任一不满足即 `STOP/INVALID`，不接受 90% 近似标签。
- counterfactual 最低 support：
  - 不少于 120 个稳定 action-level allow/block calls；
  - 来自不少于 60 个 base tasks 和 3 个 suites；
  - `utility-essential`、`attack-enabling`、`neutral` 各不少于 20；
  - 全部标签由程序化 before/after evaluator 差分产生；
  - 后缀依赖断裂的样本不计入。

### Oracle bridge 门

- 公平基线：`AllowAll`、`DenyAllMutating`、`StaticSchemaRisk`；全局只能选一个 strongest baseline，禁止逐任务取 union。
- 桥接臂：`No/AllowAll`、`Random`、`Shuffled chapter-1 scores`、`OOF Predicted`、`Oracle`。
- Oracle 和最终 Predicted 对全局 strongest baseline 必须同时满足：
  - 主指标 `J` 相对提升不少于 10%；
  - 净 rescue 不少于 8 个 base tasks；
  - 按 base task cluster 的 paired bootstrap 95% CI lower > 0；
  - utility 绝对下降不超过 5 个百分点；
  - 所有 replay/harness 门通过。

## 9. 最小实验顺序与停止规则

1. 先结束 BFCL 隔离重评；若三个同目标设计有效地全部 STOP，只执行 Sol 独立审阅限定的同 item call-order 桥。
2. call-order 也 STOP 后，方向 D 第二章永久 STOP，不再叠加第五个局部 operator。
3. 然后才执行 AgentDojo Gate0；它与 BFCL 不是“同一目标下的第四次调参”，而是由多篇论文局限导出的新研究对象。
4. AgentDojo Gate0/1 任一硬门失败，该数据路线立即 STOP；先不训分类器，不生成 synthetic negatives，不调用付费 API 补轨迹。
5. 只有 Gate1 Oracle bridge 过门，才进入第一章 OOF 预测与第二章 Predicted bridge。

## 10. 当前裁决

**能推进，但只能以 `CONDITIONAL` 推进。**

比原 A/B/C/D 设想更强的地方是：

- 缺口由多篇论文作者自述限制的交集导出，不是为适配现有代码而造题；
- 有两个彼此独立、又能用 OOF 预测严格连接的章节；
- 存在 AgentDojo 这一 stateful executable benchmark 作数据候选；
- 标签有机会由程序化 utility/security 反事实产生，而不是 LLM judge。

它仍然可能很快 STOP，最大风险不是模型分数，而是：

1. 官方 committed runs 无法与精确 benchmark version 严格 join；
2. 可稳定反事实的 call 不足 120，或三类标签不平衡；
3. 阻断后 off-policy suffix 太多，无法形成严格的执行结果桥；
4. 静态强基线已经足够好，Oracle 动态授权仍达不到 10% / 8 rescue / CI 门。

因此，下一步的正确动作不是立即写方法，而是用一次严格 AgentDojo Gate0/1 回答：**这个文献缺口在现有公开资产上是否真的可测。**
