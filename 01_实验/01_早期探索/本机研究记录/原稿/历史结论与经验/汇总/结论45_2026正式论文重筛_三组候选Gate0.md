## 2. 候选组一：Agent 系统问题定位与可执行修复

### 2.1 暂定题目与统一主线

暂定题目仅用于 Gate：

> **《面向智能体系统的软件问题定位与测试约束修复方法研究》**

统一主线：Agent 系统的问题不仅落在普通业务函数，还可能落在模型适配、提示/配置、工具 schema、执行 Harness、记忆、编排和多 Agent 协议。先用失败触发测试、issue 语义和 Agent 架构证据定位责任模块，再只在该证据范围内生成修复，并以失败翻转和非目标回归验证闭环。

这不是把普通 SWE-bench 换名为 AgentOps；主数据必须是 Agent 系统真实 issue，最终结论必须回答哪些 Agent 特有组件导致现有 SWE Agent 显著失效，以及架构证据何时改善定位与修复。

### 2.2 核心论文组

1. [Can Agent Fix Agent Issues?，NeurIPS 2025 Main](https://proceedings.neurips.cc/paper_files/paper/2025/hash/45f0ab2d264a057113492b35c5ef47f2-Abstract-Conference.html)：直接把 Agent 系统 issue resolution 定义为完整研究问题；分析 201 个真实 issue，发布 50 个可复现任务，并报告现有 SWE Agent 低解决率。
2. [Improving Code Localization with Repository Memory，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/b4c06f095368497f3ac19422efef8133-Abstract-Conference.html)：为第一章“仓库演化证据辅助代码定位”提供直接方法站台和强 baseline 来源；它不是 Agent 专属，必须在 AgentIssue 上证明增量来自 Agent 架构证据。
3. [Self-Challenging Language Model Agents，NeurIPS 2025 Main](https://proceedings.neurips.cc/paper_files/paper/2025/hash/a5a305fac88fb4ae40969cfec5eef48d-Abstract-Conference.html)：用 instruction、verification function、solution/failure tests 定义 Code-as-Task，为测试约束和可验证反馈提供方法来源。
4. [STRATUS，NeurIPS 2025 Main](https://proceedings.neurips.cc/paper_files/paper/2025/hash/47a6e9e2c3019f13ad94a0f259fe4970-Abstract-Conference.html)：提出 Transactional No-Regression，说明自动缓解必须同时成功和不引入回归；本文只借其可执行安全验证原则，不把云 SRE 数据冒充 Agent 主数据。

数据与代码资产：[AgentIssue-Bench 官方仓库](https://github.com/alfin06/AgentIssue-Bench)，MIT 许可证，50 个任务以 Docker image 发布，并含官方生成 patch 与评测脚本。

### 2.3 第一章：Agent 架构证据约束的文件与代码区域定位

- 白话问题：给定真实 Agent 项目 issue 和失败测试，能否比普通代码检索更准确地找到负责的 Agent 模块、文件和可执行修改区域？
- 学术定义：输入 issue、buggy repository、失败触发测试输出、静态调用/依赖图和可公开的 Agent 架构角色；输出 file Top-K、code-region Top-K、责任组件类别与可执行证据链。原function输出因Gold不足删除。
- 独立价值：即使不自动改代码，准确定位和“为什么是这里”的测试证据已可降低 Agent 系统维护成本。
- 冻结主指标：task-level file MRR；code-region MRR/overlap只在32个可靠hunk子集作次指标；辅助指标 Top-1/Top-5、developer-patch coverage、test-to-location evidence coverage。
- 2--3 个模块：
  1. **Agent 组件语义映射**：识别 model adapter、tool/Harness、prompt/config、memory、orchestration 等 Agent 特有组件；
  2. **仓库演化记忆检索**：按 ICLR 2026 repository memory 方法，只检索训练期/当前时点可见的历史 issue、commit 与功能摘要；
  3. **失败测试证据接地**：将 stack trace、断言和执行依赖连接到候选位置，输出可复核链而不是 LLM 文字解释。
- 主要 baseline：BM25/stack-trace 简单规则；同信息预算的 Agentless localization；Repository Memory；另选一个近年直接 localization 方法。总数不超过5。
- 泄漏禁止：developer patch diff、fixed code、未来 commit、hidden tests、issue ID/仓库名捷径不得作为在线输入。

### 2.4 第二章：定位引导的测试约束修复与无回归验证

- 白话问题：第一章给出的样本外责任位置，能否让代码 Agent 更少搜索、更少越界修改，并真正把失败测试修好而不破坏其他行为？
- 学术定义：仅消费第一章 task-level OOF Top-K 和证据链，在限定上下文与执行预算内产生 patch；以原失败测试翻转、公开/隐藏回归测试和修改范围评价。
- 独立价值：研究对象是可执行 patch 与 Agent 系统行为恢复，不是对第一章标签再分类。
- 冻结主指标：task resolution rate；辅助指标 fail-to-pass、pass-to-pass/no-regression、patch scope、执行次数和成本。
- 2--3 个模块：
  1. **证据约束补丁上下文**：只把 OOF Top-K 及其依赖扩展给 repair agent；
  2. **verification-function 驱动的候选修复**：以失败触发测试和 issue 约束生成/筛选候选；
  3. **Transactional No-Regression sandbox**：候选必须原子应用、失败翻转且非目标测试保持，再允许接受。
- 桥接对照：`No localization / Random / Shuffled OOF / OOF Predicted / Oracle developer locations`。Oracle 只作上界；正式主张必须由 OOF Predicted 过门。
- 强 baseline：官方 Agentless、AutoCodeRover、SWE-agent 的同模型同预算复现或官方冻结结果；若无法同模型重跑，只能作外部参考，不能与新 arm 混成配对统计。

## 3. 候选组二：证据保真的主动上下文与风险触发恢复

### 3.1 暂定题目与核心论文

暂定题目：

> **《面向长程智能体的证据保真上下文管理与执行恢复方法研究》**

核心论文组：

1. [Sculptor，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/f9155a06ba1b20e40c38bf8541db456f-Abstract-Conference.html)：主动 fragment/summary/fold/restore/search；已覆盖“可逆上下文工具”，不能重复。
2. [MEM1，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/file/5fc8b3bdfbb9167b5144df5d3fae4616-Paper-Conference.pdf)：记忆与推理联合压缩；失败分析包含因丢失原推理路径而覆盖正确答案。
3. [COMPASS，ACL 2026 Long](https://aclanthology.org/2026.acl-long.152/)：Context Manager + Meta-Thinker + Main Agent；局限是 QA 式受控环境和强 proprietary models。
4. [FS-Researcher，ACL 2026 Long](https://aclanthology.org/2026.acl-long.288/)：文件系统持久证据与双 Agent；局限是强模型、文件操作脆弱和不可信网页风险。
5. [GTA，ACL 2026 Long](https://aclanthology.org/2026.acl-long.856/)：提供 realistic multi-hop web tasks、executable trajectories、deterministic replay，可作程序化过程 Gold 候选，但其自动生成数据不能成为唯一外测。

### 3.2 两章合同

第一章：**可执行约束与证据保真的上下文状态构建**。

- 输入：长程 trace prefix、user constraints、tool results、source anchors；输出结构化 working state、保留/折叠/摘要/恢复动作和 provenance map。
- 三模块：事件/证据锚点；约束与动作前置条件保留；可逆摘要和 restore index。
- 主指标：程序化 constraint/evidence retention；辅助指标 provenance exactness、restore fidelity、state reconstruction consistency、token/latency。
- 直接区别：Sculptor 主要以最终 benchmark score 和 token 降低评估工具策略；本章必须对每次上下文变换的可执行约束/证据保真建立独立 Gold。

第二章：**保真风险触发的恢复与重规划**。

- 仅消费第一章 OOF 的 evidence-loss / constraint-loss risk；输出 restore、checkpoint replay、replan 或继续执行。
- 三模块：风险门；最小证据恢复；恢复后的动作验证。
- 主指标：长程 task success；辅助指标约束违反率、恢复率、无目标回归和成本。
- 桥接：`Full context / Static summary / Random restore / Shuffled OOF / OOF Predicted / Oracle restore`；Predicted 不优于最强公平 baseline 则两章关系 STOP。

### 3.3 Gate0 阻塞

1. 必须证明 GTA 或另一个可执行 benchmark 的 trajectory 可在本地 deterministic replay，并能从公开任务约束/状态而非未来 Gold 稳定标注 evidence/constraint preservation。
2. 必须有真实 Agent 外测；PI-LLM、NeedleBench 等静态/合成 long-context 数据只能用于机制探针。
3. Sculptor 已覆盖可逆操作，COMPASS/FS-Researcher 已覆盖 context manager/workspace；若增量最终只剩“摘要更准确”或“少 token”，整组 `REJECTED_OVERLAP`。
4. 现无模型 API key；Sculptor 论文的 13B RL 和 proprietary baseline 无法在当前 16GB 机器等价复现。Gate0 必须先定义小规模同模型公平比较或明确需要用户提供 API 预算。

### 3.4 实验51 Gate0实测与整组裁决

只读审计核验了Sculptor、MEM1、COMPASS、FS-Researcher、GTA，并补入更直接的CoMem、SUPO、OCR-Memory。核心结论不是“领域拥挤”这一泛泛判断，而是原两章合同已被逐项覆盖：OCR-Memory用visual anchor定位并从外部日志确定性恢复verbatim evidence，同时提供active recall；CoMem用action-consistency reward优化压缩记忆对下游动作的functional equivalence；SUPO端到端联合优化tool-use summary与Agent policy；Sculptor已经提供fragment/fold/summary/hide/restore/search。

公开资产资格也未成立：MEM1 demo可见1000行、CoMem BrowseComp文件128行，但都不具备冻结的`constraint -> tool result/source anchor -> context transform -> executable outcome`过程链。严格合格独立任务0、held-out 0、程序化process-fidelity Gold 0、官方冻结无模型replay链0、自然外测资产0；官方主路径需要vLLM/权重、API或H100/H200/A100级资源。

因此候选2为 **`REJECTED_OVERLAP`**，同时记`CONDITIONAL_ASSET_BLOCKED/STOP_ASSET`。不进入模型/API Gate1，不用“再加provenance verifier或risk trigger”绕开直接重叠。该Gate0不计方法失败次数。

## 4. 候选组三：工具可靠性估计与自适应恢复

### 4.1 暂定题目与核心论文

暂定题目：

> **《面向动态工具环境的智能体可靠性估计与自适应恢复方法研究》**

核心论文组：

1. [ToolEVO，ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d8d1d325f822e07d16866780cc23deb2-Abstract-Conference.html)：API/tool 演化下主动探索、自反思和更新。

3. [ReIn，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/3144924eaa37b635a79dd382c6d7c825-Abstract-Conference.html)：诊断错误上下文并在不改 backbone/prompt 的条件下执行恢复计划。

### 4.2 两章合同

第一章：**部分可观测工具可靠性与转移风险估计**。

- 输入仅为当前 trace prefix、公开 schema、调用结果类别和依赖图；输出下一调用成功概率、失败模式和校准不确定性。
- 三模块：transition-focused state delta；依赖条件化可靠性；非平稳变化检测/abstention。
- 主指标：task-grouped next-call failure Brier score 或 calibrated AUCPR，必须预先二选一；辅助指标提前量、ECE、跨 tool/failure type 泛化。

第二章：**可靠性分数驱动的恢复工作流选择**。

- 仅使用第一章 OOF 风险；输出 retry、alternative tool、dependency repair、checkpoint backtrack 或 safe stop。
- 三模块：依赖约束恢复候选；风险/成本联合选择；可执行状态验证。
- 主指标：task success；辅助指标恢复率、额外调用、无回归和失败类型边界。
- 桥接：`Original / Fixed retry / Random / Shuffled OOF / OOF Predicted / Oracle reliability`。

### 4.3 Gate0 阻塞

- 先全面检索 2026 “online tool reliability belief / latent failure inference”直接工作；若已有相同输入和恢复机制，本组删除。

### 4.4 实验52--53 Gate0/Gate1实测与最终停止

正式论文与官方仓库审计后，候选3暂为 **`CONDITIONAL_ASSET_BLOCKED`**，非章节GO。当前严格计数为：next-call failure Gold 0/30、executable recovery Gold 0/30、held-out 0/20、无模型离线replay 0/1、自然外测0/1。

- ResiliBench报告5040任务、30 APIs和五类参数化错误，是最强构造候选，但浅克隆只有11个Git-LFS pointer；它的已知可靠性MDP workflow也可能使“在线估计”退化为读取生成参数。
- ToolEVO覆盖API演化后的探索、反思与工具用法更新，但需要外部ToolQA/API server与模型权重。
- WMA有WebArena真实网站语义和transition样例，但仓库样例各仅10行，未给稳定executor failure type Gold；完整运行依赖Docker与OpenAI轨迹生成。
- OpenApps可单CPU运行，Python state/reward透明；静态配置有28 base tasks、243 goal variations和100 long-horizon records，但GUI environment variation不等于随机tool failure，只能先作环境/Gold控制。
