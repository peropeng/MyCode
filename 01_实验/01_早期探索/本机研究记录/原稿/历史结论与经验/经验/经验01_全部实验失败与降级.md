# 全部实验失败与降级经验

## 先说人话

这份文件回答的是“每一次为什么没有资格把结果写成论文 Go”。不能因为代码跑通、某个子指标上涨、Oracle 有效、文件命中或环境闭环就越级写成责任因果。只能把排除泄漏、确认数据资格、定位基础设施问题、或在同状态干预中真正翻转结果的证据保留下来。以后审阅任何新材料，先看它属于方法 Go、开发信号、数据/环境 Go，还是 STOP；同一个实验的“成功一项”不能自动带动递进故事的下一项。

固定复盘模板：**口语总结 → 回答了什么 → 不能说明什么 → 只能说明什么 → 为何失败/降级 → Sol 审核办法 → 后来为何仍不可行/何时适用 → 可复用价值**。

## E012–E017：受控检测、文献复现和方法冻结

### E012 多类型故障区间

- **口语总结：**多类故障预检能告诉我们探针边界，但把多类型预检写成正式区间检测还太早。
- **回答了什么：**语法/文件/验证探针的接口和故障类别可编码，C-mutant/C-native 的资格问题可自动记录。
- **不能说明什么：**不能说明多类型自然故障已覆盖，也不能说明区间边界比周期基线好。
- **只能说明什么：**只能说明预检合同和负证据，属于资产/方法准备而非 RQ1 Go。
- **为何失败/降级：**没有独立自然任务和足够状态证书，且不同分支有不同快照。
- **Sol 审核办法：**把探针事实、语义 Judge 和责任定位拆开；预先冻结漏斗门。后续仍因资产不足归档。
- **可复用价值：**故障类 A/B/C 的契约字段、clean/fault 双门、泄漏字段黑名单。

### E013 Flash 触发式在线故障检测（P2）

- **口语总结：**Flash 不是“在线监控算法”，API 触发也不能替代可执行探针。
- **回答了什么：**语义诊断在触发条件、提示 schema 和证据引用上的失败边界；Flash 试验未形成可靠在线主结果。
- **不能说明什么：**不能说明 `deepseek-v4-flash` 能发现自然故障、生成可靠修复或提高责任定位。
- **只能说明什么：**只说明 API/语义层必须被形式证据门控，且 no-API/Periodic-API 必须是公平基线。
- **为何失败/降级：**在线资产、触发覆盖和结果一致性不足；有“零编辑/不稳定输出”负证据。
- **Sol 审核办法：**Flash 仅作必要时语义诊断，要求引用事件 ID/探针；随后实验未解决资产 STOP。
- **可复用价值：**提示 schema、API 预算和证据绑定规则；模型名不是创新。

### E014 统一受控故障基准

- **口语总结：**基准把场地画平了，但没有替方法跑出冠军。
- **回答了什么：**统一仓库、manifest、故障合同和 leakage audit 可以重复使用。
- **不能说明什么：**不能说明某个 detector 优于周期基线或真实 Agent 可泛化。
- **只能说明什么：**只能说明基准与输入边界准备到什么程度。
- **为何失败/降级：**同名 base/分支快照、资产和运行缓存有差异，独立确认未完成。
- **Sol 审核办法：**固定 commit、任务独立性、source hash 和 forbidden fields；保留为开发证据。
- **可复用价值：**manifest、任务/仓库分组、泄漏审计字段。

### E015 受控在线故障检测开发集

- **口语总结：**过程图原型有研究味道，但开发集不是论文测试集。
- **回答了什么：**事件阶段、时间边、文件/函数结构边和验证依赖边的表示可实现。
- **不能说明什么：**不能说明图表示本身提高自然在线检测。
- **只能说明什么：**只能说明 M1 过程证据图和基础单元测试可用。
- **为何失败/降级：**开发集过于受控，缺少外部强基线和独立样本外结果。
- **Sol 审核办法：**引用 OOPSLA 作为过程中心锚点，但不声称在线干预复现；后续不再扩实验。
- **可复用价值：**图 schema、前缀单调性、未来信息审计。

### E016 OOPSLA 过程中心方法复现

- **口语总结：**复现审计能证明论文边界，不能把 artifact 当成我们的新贡献。
- **回答了什么：**Graphectory 的过程表示、前缀分析、在线范围和诊断/回滚语义可被逐项核对。
- **不能说明什么：**不能说明本文已完成同样的 Agent 监控收益或干预复现。
- **只能说明什么：**只能说明一个 CCF-A 过程中心方法锚点和它的适用边界。
- **为何失败/降级：**本地资产/LFS/环境不足，且研究对象与本文故障责任问题不完全同构。
- **Sol 审核办法：**将其降为主线参考与去重审计；结构图是方法来源，不是首创。
- **可复用价值：**schema 审计脚本、prefix/online scope 检查。

### E017 论文指导方法冻结

- **口语总结：**把论文来源写清楚，才知道哪些只是工程拼接。
- **回答了什么：**M1 过程证据、M2 形式探针+证据门控语义、M3 保守区间和干预分离的来源链。
- **不能说明什么：**文献追溯本身不能证明模块有效。
- **只能说明什么：**只能说明方法假设和禁止越界表述被冻结。
- **为何失败/降级：**后续 RQ1 实验没有满足独立门；不能靠文献替数据。
- **Sol 审核办法：**每个模块写“论文实际支持/本文保留/禁止声称”。
- **可复用价值：**核心论文身份核验、CCF-A 与预印本分层、模块追溯矩阵。

## E020–E025：历史 P1/P2 和语义预检

- **E020 无成功参照在线检测：**回答无参照检测的可行性较弱；不能说明在线风险没有研究价值；只能说明当时召回低于 Fail-Fast 式基线，导致 NO-GO。Sol 要求引入真实过程证据、强基线和明确在线时点，后续资产/标签问题仍未解决。
- **E021 RQ1→RQ2 动作排序：**回答风险分数与责任候选排序的初始桥接；不能把 risk peak 当责任；只能说明桥接是独立门。MRR 下降/无增益后停止。
- **E022 跨状态责任动作干预：**回答把事后标注动作搬到另一状态不可靠；不能用静态 patch/文件命中替代干预；只能说明 0 闭环不是方法 No-Go，而是状态不一致。Sol 要求同检查点重放，E011 才解决受控版本。
- **E023 责任主体预测：**回答主体软预测与局部步骤排序能否组合；不能把主体标签当因果或当前题目；只能说明强基线和 OOF 桥接要求。后续受用户禁多 Agent 责任主体主线、标签构造和数据边界影响而降级。
- **E025 可见验证命令语义回归预检：**回答命令/测试“可见”不等于语义 oracle；不能由 AST/命令通过判定责任；只能说明验证命令语义和 oracle 资格需单独审计。缺真实任务和强基线，STOP。

共同教训：P1 的“在线”不能只是离线结果切片；P2 的“Flash/动作”不能跳过状态证据。后续 Exp30–43 试图收缩到动作效果契约，但最终仍未取得 RQ1 Go。

## 总结：什么才可能重新被称为 Go

在本项目已经终止实验的前提下，不再执行验证。仅作为论文判定标准记录：

1. RQ1 需独立问题、强基线、无未来泄漏、任务/仓库独立、主指标相对提升 ≥10% 且 paired CI 下界 >0。
2. RQ2 需消费 RQ1 的 OOF/样本外产出，且相对完整轨迹/候选缩小的对照不能只靠 Oracle。
3. 责任动作需同状态重放、撤销/替换或恢复翻转；文件/步骤/主体标签只是候选或上界。
4. 任何基础设施 STOP 先写“没有结果”，不写算法 Go/No-Go。
