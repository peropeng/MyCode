# 线程 01a008b8-99dc-72f3-9bdd-aa8062e23332 经验总结

## 先说人话

这段旧对话回答了“如何把三个场景从文档想法推进到可审计的小论文实验，以及哪些看起来漂亮的 Go 必须撤回”。它不能证明旧主机上的 6,055 条轨迹、私有缓存或 Docker 结果在当前机器仍可复现，只能说明当时冻结过哪些协议和为什么后来被审计降级。最有用的经验是：单项实验过了，不等于 RQ1→RQ2 桥接过了；执行器卡住不等于科研 No-Go；而 `Who&When Pro` 已覆盖大量基础归因设计，创新去重要按“组合级研究单元”而不是单个模块名判断。

## 纠错链

### 1. 本机只有文档，不能伪造旧机证据

- 旧对话先确认当前本机缺少旧主机的完整轨迹、环境和 Docker 资产。
- 受控模拟的高分只能证明 pipeline、字段、门和统计代码连通；不能说真实 SWE Agent 已经取得同样效果。
- 旧主报告中的真实数字必须保留为历史记录，不能在新对话中自动继承为当前复现事实。

### 2. controlled simulation 只能是 Pipeline-Go

- A/B/C 三组模拟固定任务、候选池、随机种子和 Oracle/Predicted 条件，适合测试协议是否按预期区分条件。
- 模拟不能证明数据分布、自然故障、工具状态或模型输出上的方法增益。
- Oracle 先验与 Predicted 先验必须分开；Oracle 的桥接结果只说明上游信息理论上有用。

### 3. 原始 Who&When 与 Who&When Pro 的去重边界

- 本地成功解析的 184 条来自原始 Who&When 数据的两个 split，不是 Who&When Pro 的数据子集，也不是 Pro 的“公开 184 条”。这次本地审计只用于 schema、索引、Oracle bridge 预检，并反驳 recency 基线；不能把它写成 Pro 复现。
- Who&When Pro 是不同的构造协议和更大规模的论文/预印本资产，覆盖 taxonomy、warm-start 单点注错、责任 Agent/步骤/错误类型 Gold，以及 All-at-once、Step-by-step、Binary-search 三种归因协议。
- 当前没有完整下载或复现 Who&When Pro 的官方资产，不能声称完成官方复现；它直接反驳“建立错误 taxonomy”“从成功轨迹注入单点错误”“联合预测 who/when/type”作为首创贡献。
- 后续可研究的是独立证据验证、三值 verdict、拒识、真实仓库状态或 Pro 尚未回答的症状—根因混淆；不是把相同模块换名。

### 4. 三组真实/受控材料：单项过 ≠ 桥接过

- 场景 A 的在线风险检测和责任动作桥接必须分别过门；风险峰值不自动成为责任动作证据。
- 场景 B 的恢复识别可过独立门，但恢复质量到责任定位的桥接仍可能无增益。
- 场景 C 的 Oracle responsible-agent Bridge 只能证明正确上游信息能改善步骤搜索，不能证明 predicted 假设或因果。

### 5. 历史方向纠正

- 早期成功参照、有限编辑修复和反事实归责都说明了“可观察偏离/文件相关/静态标签”与责任因果之间的鸿沟。
- group6 的主体概率→步骤 MRR 是相关桥接；由于用户禁止“找一个责任 Agent”作为主线，且该标签主要来自构造注入，不作为当前题目。
- group7 的选择性恢复质量和 group8 的后验开发结果共享同一数据，不得当作两个独立 Go。

## 最终可携带的规则

1. RQ1 必须独立有价值；RQ2 消费 RQ1 的 OOF/样本外产出。
2. 每个主张都写清输入、输出、观测时点、Gold 来源和因果边界。
3. 不读未来，不用终局标签当在线特征，不把最近动作当责任动作。
4. 公开标签/执行器/检查点缺一不可；静态文件命中只能是候选线索。
5. 执行器无输出或卡死，要先标为 executor/infrastructure failure；同一阻塞重复三次才做停止审计，不能把无数据写成科研 No-Go。
6. 文档和实验资产必须分开；仅靠编号平铺会再次混杂，必须按内容类型分层。
