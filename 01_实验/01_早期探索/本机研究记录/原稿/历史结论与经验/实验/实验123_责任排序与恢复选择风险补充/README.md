# Exp123：责任排序与恢复选择风险补充

本轮已完成 34 个任务、8 个仓库、3 个种子的全部 816 个切片逻辑槽，以及单点训练标签、故障参照与重复哨兵。实际新执行 579 次。科学联合门未通过，综合严格 GO 不通过；原子状态与泄漏审计通过，逐候选原始 stdout/stderr 摘要未保存这一合同缺项单独保留。

风险约束使 M3 在全部划分选择 k=0、全部弃权；其零恢复不是模型没有恢复能力。M4 在全部划分选择 k=1，退化为 M1。M4 相对弃权策略的恢复增加伴随更高 held 风险，不能作为同等风险下责任先验独立增量的证据。 按预注册的任务级配对区间，M4 相对 M2 的不安全尝试不增门通过。

科学上的主要失败原因是：同预算 M3 恢复 23/34、M4 恢复 22/34，M3 观测风险和平均尝试数也更低；但不把这些差异全部称为显著。风险约束下 M4 只恢复 8/34，低于 M2 的 11/34，恢复差为 −8.82 pp、95% CI [−17.65, 0]。M4 对全部弃权的 M3 多承担 17.65 pp 风险，95% CI [5.88, 29.49]。因此组合的科学联合门已经未通过，日志缺项是另一个限制。

这批 34 个任务已参与历史实验，结果只构成内部机制证据。这里验证的是 Python `compile()` 与非目标状态恢复，不是原 Issue 修复；不改写 Exp112C 的既有排序结论。

## 1. 比较的实际方法

| 条件 | 冻结定义 |
| --- | --- |
| M1 | 只尝试 Exp113J 冻结责任顺序的第一项 |
| M2 | 沿完整责任顺序，首次验收成功即停止 |
| M3 | 完全不用责任名次、分数或第一名保护的恢复后验顺序；同分按匿名结构摘要及原轨迹位置排序 |
| M4 | 保护与 M2 相同的第一项，剩余候选使用 M3 的恢复后验 |

原 Exp116/120 后验的八项特征本来就没有 RQ1 分数或名次。本轮核实 `posterior_mean`、`posterior_margin` 为 0；其他输入为轨迹时间位置、可回滚性、可执行性、是否改变状态、预计成本和响应类别。因此 M3/M4 的实际方法差异只有第一名保护，不宣称进行了责任分数融合。八个锚点按原工具调用时间编号，与责任名次分开保存。

后验保持原固定 ExtraTrees 参数，训练标签仍来自**单点候选**的验证成功，评价池仍是**同目标键前向切片**。outer 留一仓库，outer-train 内再留一仓库生成 OOF 预测；以训练任务 M2@2 的不安全尝试率为参照，在 k∈{0,1,2,3} 中选恢复率最高的合法深度，平局取小 k。held 顺序和深度在磁盘不可变发布后才解封 held 字段。M2 使用的预训练责任先验来源是 Exp113J 八锚点封存排序，不是 Exp112C 最终 OOF 预测。

## 5. 执行、提交和成本

本轮不复用旧策略级执行缓存。单点训练、切片评价分别命名；不可变记录绑定 claim、代码、数据、task、base commit、故障、候选计划和参照。重放没有 seed/fold 输入或随机执行分支，因而相同绑定的物理结果跨 seed/fold 复用；另用预先指定的首任务 anchor 0 重复完整重放，非计时字段完全一致。全部 816 个逻辑槽保留物理来源映射。

失败尝试在独立 clone 中执行，清理成功在上下文退出后实测。可接受候选的真实文件内容在 clone 删除前发布为内容寻址快照，随后重新读取并执行目标 compile 和非目标 hash 检查；这只是实验专属状态提交，没有修改用户或源仓库。独立 finalizer 再从 ZIP 中读出实际字节验证全部 hash、目标和非目标状态。
