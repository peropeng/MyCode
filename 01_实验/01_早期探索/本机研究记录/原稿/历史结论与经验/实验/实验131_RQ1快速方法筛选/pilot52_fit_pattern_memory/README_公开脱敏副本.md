## 方法与监督边界

复用 P39 已合法保存的 31 个不同 FIT 示例、其中的责任步骤与同角色对照标注，以及原有 32 条评测任务到这些示例的最近邻映射。不重新检索、不改样本、不打开源 FIT 标签文件。这里使用了合法训练监督，不能把整个阶段称为没有 Gold。

先对每个 FIT 示例生成一次诊断模式，输入包括完整公开任务、原始编号轨迹及已有 origin／non-origin 标注，输出固定的 `trigger`、`origin_mechanism`、`foil_distinction` 三个非空字符串。单字段上限为 600 个 Unicode 字符，每次输出预算 768 token。6 个源示例没有同角色对照，输入保留 null；non-origin 只表示不是数据集指定的责任步骤，不意味着该步骤正确或无害。

31 个模板及映射全部封存后，才构建评测请求。沿用 P39 的系统提示、目标任务／完整轨迹、命名空间和全步骤排序要求，仅把原始训练参考替换成已保存的诊断模式；每次评测输出预算 512 token。新 B 是所得完整排序，主条件 A+B 将同一排序按原冻结 A 的角色优先级稳定重排。没有新角色模型、神经模型、编码器或参数拟合。

所有规则、生成器、授权和继承账本在第一次模板调用前冻结；评测消息由封存模板依照冻结规则派生，另行绑定哈希，不重写原协议。无效模板会使其对应的评测任务在 B 与 A+B 中保留为未命中，不回退或补抽；本轮实际没有出现无效模板或评测输出。
