# 实验130 v8：仅任务语义树与来源结构的 CPU 可行性审查

当前候选 A+B 未获得继续付费或训练的资格。本版只有 CPU 输入与结构审计，没有模型生成、API 调用、embedding 或训练。后续设计应另立版本，本版不通过压缩输出上限来维持已不成立的机制假设。

原 A 需要可追溯的非平凡重复证据族；本轮没有建立该覆盖，保守下界为0。一次调用及其返回是互补内容，不能自动视为重复证据。严格整字段 JSON object 的匹配为0；根数组直接成员的唯一 typed-ID、同工具名、较后返回配对为1564对，分布于441条记录／441组，单独保存。18个孤立返回 ID／14条记录与319个缺 ID 请求对象／253条记录保持未知。全部7366个候选节点保留。

数组配对包含 diagnosed 46/235条、injected 395/496条；agentic没有这种配对。这证明可检查的公开调用结构覆盖，不证明执行成功、语义正确、因果关系或A去重效用。静态来源审计15项合成测试通过；原始v6/v7本地账本与代码未改。

另一个 CPU 接口只传完整原始task与输出cap，不传角色、步骤、trace或标签。输出使用typed JSON node与字符串操作名；and/in不是Python关键字执行，Buck-Tick是字符串实体。完整函数定义、单位、范围、否定、变量作用域和多目标均可表达。完整原始task及UTF-8 SHA256由本地绑定，仅声明字段级来源，不声明原子span。结构有效也不证明语义准确或目标完整。

两个与数据集任务无关的完整合成输出分别需要322和786个官方token，16项结构/边界检查通过。同12条开发任务仅重用为待审输入，没有真实语义生成，不能视为新独立样本。所有731条task逐字符往返一致。任何未来C/A/B/AB仍须共同拥有完整原始trace及既有静态/嵌套语法账本；task AST本身不是A/B贡献。

没有推荐付费cap：512虽然规划预算可行，却无法容纳完整786-token例；1024可以容纳两个例，却在全量规划中触发预算保护。更根本的阻塞是A机制输入不成立、B目标到trace对象的绑定尚未评估；费用或JSON结构检查不能替代机制资格。

B仍只能提出局部可解析表达式与检查谓词的对象对齐设想；仅相同数字不能建立跨调用来源。task-only AST也不能自动补足agentic过程中的检查范围、工具能力或执行语义。这里的NO-GO只针对本版依赖强结构重复族及静态绑定的候选方案，不意味着所有可学习的弱关系设计都必须有确定性证明。
