## 排序与回滚实现

部署使用既有 Exp112/96/106/88 科学函数：seed 20260816、按 task_group 五折生成 OOF A/B2 分数、七维 stacker、200 epochs、lr 0.05、l2 0.001、pos_weight 1、B2 权重 0.5。仅一次部署训练，没有调参或评测结果选择。731 条开发记录、716 个组、7366 步；确认集未参与训练、评分或选择。历史 loader 会先物化完整表，再过滤确认集，报告不把这一点写成从未底层读取确认字段。

重合检查额外仅读取 conv_id/task 两列，按允许开发 task_group 过滤；身份与规范化任务描述无匹配。重新构造的 2672 条角色特征与原 loader 逐项相等。NumPy float64 加速经固定非评测合成矩阵及前 4 条训练记录的真实 215 维 B2 差分验证，最大权重/分数差 1.7764e-15，排序一致。

每条 assistant 决策消息均进入排序，包括没有工具的回复；单 Agent 映射为 role_0，正文移除函数调用片段，全部调用保留为 action JSON 列表。只用原匿名结构特征；新任务输入无责任 Gold。每步成功的业务代码编辑构成原子根；源复现脚本和轨迹内测试保留在真实状态重放及映射中，不允许恢复方法改写它们。

依赖由文本来源与创建存在条件产生：整个 new_str 保守标为编辑产物，后续 old_str 消耗相应字符时建立边，撤销后继闭包后从公共检查点严格重放。old_str 必须唯一，不能用整文件前像强行修复冲突。用于构造公共检查点的首个实际前像和完整重放经过全部文件字节一致校验。候选仅接收可见目标反馈，固定保护测试只在选定最终状态后验收一次。

## 可以与不可以据此得出的结论

可以确认：固定模型部署、完整步骤适配、编辑来源依赖、真实重放、可见反馈与保护验收这条本地管线已接通；三个已封存开发状态均能恢复。

不能据此证明排序增益：三项完整排序中被执行业务根的位置为 10、8、7，成功的是首个合法业务候选，并非所有责任 Top1 都正确。候选池分别只有 4、2、1 个，六次预算覆盖全部候选。不能据此证明依赖闭包增益：三个实际撤销集合均只有一个编辑，且没有错误后的其他编辑。没有 LATS 实际运行，不能声明相对基线更优或给出任务级胜负。样本量很小且复用旧资产，仅属开发可行性。

LATS 离线适配保留 UCT、扩展、真实微型文件状态、可见反馈、反思、回传与父状态继承；六项契约测试通过。测试用脚本化合成响应，不是模型基线结果。接口没有 API 客户端；未来真实 API 接入与响应 usage 记账仍需在用户恢复授权后完成，不能把离线运行写成完整基线已复现。
