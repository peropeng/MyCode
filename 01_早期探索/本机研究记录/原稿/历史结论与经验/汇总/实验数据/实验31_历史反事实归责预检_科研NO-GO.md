#### 对正式实验的决定

可以进入“固定修复器 + 官方验证器”的下一轮环境协议，但不能立即把 TraceElephant 原始日志当作可任意选点的 RQ2 数据。正式实验开始前必须二选一：

1. 为每条轨迹补充可恢复的仓库快照、每步文件状态和动作输出；或
2. 明确把公开 SWE-bench 的可重放轨迹作为 RQ2 主数据，把 TraceElephant 仅用于静态责任定位外部验证。

在完成上述数据契约之前，继续安装 Docker/Colima不会解决“日志缺少 checkpoint”的根因；当前宿主机已经证明 Docker 不是最短阻断。

### 单例闭环结果

#### 实际结果

`machine_result.json` 保存了三份状态的完整 stdout/stderr。关键返回码为：

| 状态 | 官方测试返回码 | 解释 |
| --- | ---: | --- |
| 基线 + 官方 test patch | 1 | 出现 `sqlite3.OperationalError: near "WHEN": syntax error`，失败可复现 |
| Trace 责任步骤 12 的错误编辑 | 1 | 仍出现同一 SQL 语法错误，Trace 错误状态可重放 |
| 撤销责任步骤 12 的代码编辑 | 1 | 可审计地恢复到基线语义；同一测试仍失败，说明撤销本身不是修复 |
| 公开 gold patch 上界 | 0 | 同一测试通过，`Ran 1 test ... OK` |

五种候选选点中，责任步骤可以从相同基线应用并得到返回码 1；末端症状步和随机步若是后续创建的 `reproduce_error.py`，由于日志没有前置文件 checkpoint，直接从基线应用会失败；包含 `undo_edit` 的步骤也明确被拒绝。这是“日志不等于任意中间状态”的直接证据。

#### 判定

单例环境闭环：**GO_ENV_SINGLE_CASE**。

“撤销责任步骤”不是被包装成成功：它确实完成了可审计逆操作，但验证器仍返回 1；只有公开 gold 上界返回 0。这正是后续研究不能用“定位到责任步”替代“干预后得到改善”的原因。

这证明在当前机器上，不需要 Docker 或 API，也可以通过公开 SWE-bench 元数据恢复等价仓库状态、复现官方失败测试并验证一个公开修复上界。它不能证明 RQ2 的动作选择方法有效，也不能把 gold patch 的通过写成科研提升。

#### 最重要的限制

TraceElephant 自身没有发布该仓库状态和 patch；本单例的仓库与测试来自 SWE-bench Verified，Trace 只提供错误动作日志和责任标签。正式实验必须在论文中把这一点写清楚，并将“补齐后的等价闭环”与 Trace 原始数据集分开报告。

### 数据结构核验结果

结论：TraceElephant 的公开压缩包本身不能直接完成逐步重放。它确实给出了 44 条 SWE-Agent 失败日志、责任 Agent、责任步骤和测试状态，但没有 `.traj`、`replay_config`、仓库基线、patch 或中间 checkpoint。官方 `trace_locate` 还要求 OpenAI 兼容 API。

这不是 TraceElephant 论文声称“提供可执行系统代码”的否定；准确说法是：仓库提供生成轨迹的 Agent 系统代码，数据包提供静态失败轨迹，两者没有在发布包中绑定为可恢复的逐任务 checkpoint。

因此，正式 RQ2 不能仅凭这 44 条日志声称已具备反事实干预条件。本轮继续使用公开 SWE-bench Verified 元数据和可下载的仓库基线做等价宿主机预检，所有补齐内容在单例和五例报告中单独标识。

### 反事实归责预检总论

#### 当前结论

**环境层面：GO_ENV_5/5。科研层面：不计科研 GO。**

在当前 M5 16 GB macOS 上，不装 Docker、不使用 LLM API，已经用公开 SWE-bench Verified 元数据补齐了五条 TraceElephant SWE-Agent 任务的等价仓库状态。五条任务两次运行都得到：基线失败、Trace 标注责任动作状态失败、公开 gold 上界通过，返回码分别为 `[1,1,0]`；另外五条责任动作的逆操作都可审计执行，但撤销后仍返回 1。因此“恢复代码—运行官方验证器—观察干预差异”的最小环境链路真实可行，但责任动作撤销不是修复结果。

但 TraceElephant `data.zip` 本身只有 44 条 SWE 日志，没有 `.traj`、`replay_config`、仓库基线、patch 或中间 checkpoint。三种选点检查显示：标注责任步 5/5 可应用，末端症状步只有 1/5 可从基线直接应用，固定随机步只有 2/5 可应用。缺失文件和 `undo_edit` 快照不是 Docker 能解决的问题。

#### 对开题实验的影响

可以保留 TraceElephant 做静态责任 Agent/步骤定位和外部验证；RQ2 的正式反事实干预必须补充可恢复轨迹，或把公开 SWE-bench 可执行轨迹作为主数据。当前不能声称 TraceElephant 原始日志已经支持任意动作的 leave-one-out，也不能把 gold patch 通过写成方法收益。

#### 下一步唯一安全入口

先冻结“数据契约”：每条正式任务必须同时提供基线 commit、每一步文件状态或可逆 patch、动作输入/输出、官方验证器和稳定运行命令。数据契约通过后，再进行固定修复器的三种选点比较；如果再次连续两次科研实验无进展，按主方案调用 Sol/high 独立审查，不通过继续调参掩盖数据缺口。
