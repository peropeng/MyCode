# 恢复链路与原任务验收接入审计

日期：2026-09-22。授权与范围来自[交接13](../../交接/交接13_20260922责任排序与恢复选择可行性实验计划.md)。本目录只核查现有排序到恢复的真实接口，并执行最多六个原任务验收接入检查；不更改 Exp112C、Exp121、Exp122，也不修改 PPT。

## 排序到底来自哪里

Exp122 的 `_load_rankings()` 直接读取 Exp113J 的 `asset_alignment_gate_fresh_clone_isolation.json`。其规范 LF SHA-256 为 `996b5685a72b19c22a617b762c028bb95e12b7e86989075e17c8dd70afe57494`，与源码固定值一致。

生成链是：Exp113 部署训练流程 → Exp113C 的 helper 返回元组顺序修正 → 后续执行器修正及 Exp113J 封存 → Exp122 直接读取顺序 → Exp123 继续使用同一个冻结先验。部署模型使用与 Exp112C 相同的**已修正 Exp112 helper**，在 731 条、716 个任务组的开发数据上，以 seed `20260816` 做五折 OOF 分数供 stack 训练，再用全开发集拟合部署模型。八锚点的输入是匿名角色、空 content/thought 和 action shape。

因此，这条链与 Exp112C 共享方法实现，但**没有直接读取 Exp112C 的最终 outer-held OOF 预测**。它也没有保留 Exp112C 的全自然语言 turn 输入：每个恢复任务只生成八个匿名动作形状 turn。

历史记录声称 helper 对应 commit `4fe2d903496375750013172b59bea5076af8b8f7`。当前迁移仓库没有该对象；在主机权限下向原远端显式 fetch 也返回 `not our ref`。历史正式输出保存的 tie 函数文本与摘要完全自洽，且与当前函数一致；本轮另记录全部相关当前源码的原始及 LF SHA。**这不能替代已丢失的历史整文件 Git 对象或 fitted model 权重核验。** 当前冻结顺序的原件 SHA 可以核对，历史权重未重新生成。[机器审计](chain_audit.json)

## 步骤到可执行动作的覆盖

逐条使用原始 OpenHands SFT Parquet 及历史解析器，将 `sft_index → 原消息索引 → 函数调用索引 → 八锚点位置 → 同目标键前向切片` 连起来。272 个锚点全部映射成功，覆盖八候选池的 100%；所选 34 条原轨迹共有 789 次函数调用，因此对全部调用的覆盖为 **34.47%**。

`chain_audit.json` 的 `mappings` 保留原消息编号、调用编号、可见 editor 命令、路径、相邻响应摘要、责任预测名次、切片与实际省略调用。责任名次与轨迹时间位置分开保存。这是观测调用的身份映射，不是自然失败步骤 Gold；构造故障位置也不被改称自然语言推理的真实原因。同目标键切片是状态关系代理，不是跨文件因果闭包。

使用重新恢复、SHA 与历史一致的 AFTraj 开发任务映射，对 731 条记录与 34 个 SWE-Gym 问题做 ID、去大小写/标点/空白后的题文相等，以及双方至少 80 字符的题文包含检查，未发现命中。这只排除了这些规则可识别的重叠，不证明不存在所有语义改写；旧 34 任务经过多轮开发的内部证据性质不变。

## 旧恢复验收能支持什么

Exp120/122 的目标探针检查目标 Python 文件能否 `compile()`；非目标状态、diff 和冲突检查支持受控状态恢复与隔离尝试的验收。它们没有执行原 Issue 的 FAIL_TO_PASS/PASS_TO_PASS，因此不能据此写“原 Issue 已修复”。Exp123 新增的提交后重读检查也只针对实验状态快照，其结论仍受这一验收范围限制。

## 复核入口与下一步界限

- `audit_chain.py`：只读重建映射、核源码与数据摘要，不训练或评价方法。默认输出不存在时才能发布。
- `run_native_gate.py`：按冻结名单运行独立状态，attempt 目录必须不存在；`--tasks` 仅用于名单内受阻案例的环境修复。
- `collect_nodeids.py`：保存真实 collection，不修改测试；有零个或多个前缀匹配就停止。
- `finalize_native_gate.py`：逐一确认全部公开目标/保留节点的前后结果，并验证日志摘要与本地源码导入身份。

临时 clone、Parquet 和依赖环境位于 `工作区/0922-recovery-audit/`，不混入历史执行目录。后续若要证明恢复算法修复原任务，须另冻独立外部任务、候选生成及原任务验收协议，再实际评价恢复计划；本轮接入门不替代这一步。
