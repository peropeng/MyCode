# 实验149：任务与步骤联合编码

本实验执行 `approved_decision.json`，测试在冻结编码器内部为每个步骤加入任务文本，是否提供额外的排序信息。原数据仍为实验138的731条轨迹、716个任务组与固定120题，使用原始步骤坐标、三个种子和五个外折。

每个编码输入固定为 `Task:`、原任务文本、空行、`Step:` 与原节点JSON。JSON沿用124的 `text_of`：仅拼装非空 `content/action/thought`，保留原字段字节、排序及默认JSON分隔符。三个条件分别使用正确任务、空的新增任务字段、错配任务。空任务条件中的Step可能已经包含任务，不能解释为完全没有任务信息。

错配任务只来自当前 seed/outer 的原内层三折训练组。每组以最小 sample_id 的记录作为代表；排除同组和与目标组任何任务文本在空白归一化后相同的 donor。选择独立任务token长度最接近的合法组，以固定hash打破同分。相同训练池共用映射，该映射贯穿selection、四折refit与held，不能借validation或held组作为训练donor。公开文本不同不保证语义无关。

编码器保持原已绑定的本地Qwen权重、tokenizer、CUDA float16、左侧填充、last-token池化及前128维输出。全部完整输入先检查8192 token上限。12个训练池形成103,124个节点上下文，按完整文本和配置去重为49,461个唯一输入，最长2,131 token；没有删题或静默截断。缓存存储原始float32向量，头部使用时才逐节点归一化。

六臂为 `AB_JOINT`（主臂）、`AB_NO_TASK`、`AB_MISMATCH`、`SF_JOINT`、`SF_NO_TASK`、`SF_MISMATCH`。每臂复用对应条件的同一编码缓存，在冻结原AB或matched StepFinder logit上增加残差。残差头输入为 `[old_content,new_condition,new_condition-old_content]`，经过384→32、GELU、32→1，共12,353参数；末层权重与bias初始化为零。每个seed/outer的六臂共用完整初始化与采样规则。

实验146提供30个内层三折基座缓存和30个原138四折外层缓存。149不重训、重建或前向这些基座。选择仍按内层任务组等权Top1、MRR、最早epoch进行，epoch 0有效；随后从相同初始化在四折上重训所选epoch。90次选择和90个refit阶段完成后，六臂三种子及ensemble的17,544条输出全部封存，再统一外折评分。

固定120题保留八项主比较，机制家族在全716组上比较AB和SF各自的正确任务条件与两个控制，共四项Holm校正。保存全量排名、三个seed、域分层与恢复/退化，控制臂获胜也不替换主臂。原AB84、B86保持比较锚点；原146/147/148结果和不同预算的hybrid只作历史背景。

这是已多次使用的历史数据上的OOF开发比较。要求正确任务优于空任务与错配任务，才能支持所测的任务对应收益；仅优于错配任务可能是错配文本干扰。编码器表示不能等同事实核验、因果归因或新的独立测试。原136/137来源的688条AB/B资产及5,504个既有输出按hash保护，不能据此宣称新AF模型跨来源泛化成功。

执行顺序为 `input_contract.py`、`encode_stage.py run`、`preflight.py`、`runner.py run`。最后一项连续完成训练、封存、评分与收尾。只读复用资产以绝对路径引用，数据、映射、编码配置和所有训练代码均已冻结；状态见 `execution_state.json`，完成后结果见 `main_decision_packet.json` 与 `final_execution_audit.json`。

本轮本地encoder前向明确获授权，并单独计量：实际6,183批、49,461个文本、6,439,789个非填充token、12,406,941个填充后位置，前向约494秒。费用为0元，API、下载、新Gold均为0，连续账本保持原样。原148与上一诊断的零encoder记录保留其历史真实性。
