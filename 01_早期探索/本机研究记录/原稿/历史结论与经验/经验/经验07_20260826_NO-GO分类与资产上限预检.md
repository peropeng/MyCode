# 经验07：NO-GO 分类与资产上限预检

## 1. 先算可行空间，再决定是否实验

恢复类任务的主指标是离散计数时，必须先计算 `Oracle` 可达到的最大恢复数和相对门槛所需的最小恢复数。若最强基线是 `11` 个、Oracle 最多 `12` 个，则最大相对提升只有 `1/11=9.0909%`；`≥15%` 至少需要 `ceil(11×1.15)=13` 个，原资产不可能承载该门。此类预检应在冻结协议前完成，避免把不可达的门误当成方法失败。

## 2. 五类结果不能混称

- `TRUE_METHOD_NO_GO`：对象、协议、强基线、预算和统计单位都合格，方法仍稳定无增益或显著更差。
- `HARNESS_INVALID`：协议、evaluator、覆盖、Gold 可见性、运行完整性或写入合同有问题；修正前不能判断方法。
- `ASSET_STOP`：缺少合法 Gold、轨迹、checkpoint、源码、切分或可执行环境；资产不足不是算法失败。
- `STORY_MISMATCH`：结果本身有效，但不能回答当前 RQ 或自然 Agent 故事；可以保留作边界或基线，不升级为当前 GO。
- `COMBINATION_NO_GAIN`：组合相对组件没有增益；须在组件和比较器均合格时才成立，不能覆盖更基础的 Harness/资产问题。

2026-08-22 审计确认的真正方法 NO-GO 只有 E10、E44、E45、E46、E48、E65；完整审计原件放在 [`开题/实验审计`](../开题/实验审计/README.md)。

## 3. 正提升即使不到门也有价值

只要提升不是误差、泄漏或无效协议造成，就应保留其数值、CI 和适用边界。它可能与范围扩展、依赖身份、风险控制或更强基线互补；“未过章节门”不等于“没有科研价值”。Exp118C 的真实正信号就是后续设计的输入，而不是被删除的 NO-GO。

## 4. 归因要按对照层次写

Exp121 的 extent control 已恢复 `12/34`，same-target dependency 在相同范围上只净增 `2` 个任务；因此最终 `14/34` 的全部收益不能归功于依赖语义。报告应把“范围扩展贡献”和“依赖身份贡献”分开，把组合方法的可行性与单因素因果归因分开。

## 5. 失效输出和工作区治理

`HARNESS_INVALID` 的 claim、terminal、formal output 和 SHA 必须原封不动保存；纠正实验应使用新目录和新结果，不能覆盖父文件。实验目录因 runner 硬编码依赖保持原位，权威代码入口由 [`实验/README.md`](../实验/README.md) 统一说明；临时执行副本遵循 [`工作区/README.md`](../工作区/README.md)，归档、交接、结论、经验、开题不在每个实验中复制。

重复 Exp112a 支线只有协议/诊断草稿，没有正式 outer-held 指标，不构成第二次实验或 GO 证据。该经验与最终资料入口见 [`交接10`](../交接/交接10_20260826主线工作区与归档入口.md)。
