# 1. 两个研究问题

## 1.1 RQ1：秩深度感知的责任步骤级联定位

### 白话表述

一条多智能体轨迹已经失败时，怎样把最值得排查的责任步骤放到最前面，同时不破坏后续候选的整体顺序？

### 学术定义

给定仅含部署时可见角色、步骤位置、结构形态和冻结预测分数的失败执行轨迹，学习或构造一个 Gold-free 的步骤排序函数；该函数输出完整责任候选排序，并以任务组等权 MRR、R@1、R@3、强基线比较和配对 Bootstrap 评价。方法不得读取 `mistake_agent`、`mistake_step`、任务标识、未来事件或外部 Gold。

### 独立价值

RQ1 即使没有 RQ2，也能够直接回答“先查哪一步”，并形成完整的排序方法、强基线、消融、负对照和统计结论。

## 1.2 RQ2：基于样本外效用预测的选择性归因与回退

### 白话表述

结构化定位不是每条轨迹都可靠。怎样在不知道正确答案时，判断本条轨迹应该使用 RQ1 的级联排序，还是回退到时间近因排序？

### 学术定义

给定 RQ1 在严格折外条件下产生的候选排序，以及九个部署时可见、Gold-free 的结构与不确定性特征，预测 `RR(RQ1)-RR(recency)` 的连续效用；输出每条轨迹的路由决定与最终责任排序。评价包括最终 MRR、相对最强组件增益、路由选择率、效用加权准确率、Oracle regret、删除与 shuffle 对照。

### 独立价值

RQ2 解决的是**算法选择与可靠部署**，而不是重新训练一个同名排序器。它有自己的连续效用目标、路由输出、组件强基线、退化失败条件和跨边界迁移问题。

# 2. 两章为何目的不同但递进

```text
失败执行轨迹
    │
    ├─ RQ1：生成结构—时序责任排序
    │        输出：Top-1 候选 + 完整尾部秩
    │
    └─ RQ2：读取 RQ1 的严格 OOF 排序与 Gold-free 特征
             预测：RQ1 相对 recency 的连续效用
             输出：使用 RQ1 / 回退 recency + 最终排序
```

递进关系不是“第一章给第二章一个事后 Gold 分数”。Exp108 在每个 outer fold 内，只用其他 task groups 的 inner-held OOF 预测构造效用标签，再把路由器应用于 outer-held；RQ2 因而真实消费 RQ1 的样本外产出。

两章也不是同一任务换指标：

| 项目 | RQ1 | RQ2 |
|---|---|---|
| 目的 | 生成高质量责任步骤排序 | 判断何时信任 RQ1、何时回退 |
| 输出 | 完整步骤秩 | 路由决定、预测效用、最终秩 |
| 主比较 | pairwise、recency、原始结构臂 | RQ1、Exp101、线性路由、常规公平基线 |
| 主要失败模式 | Top-1 提升破坏尾部秩 | 路由退化为永远选择一个 arm |
| 关键消融 | 去掉 Top-1 提升、打乱提升位置 | 删除路由器、打乱路由决定、线性 gate |

# 3. 方法设计

## 3.1 第一章：Top-1 提升级联

RQ1 保留三个必要模块：

1. **结构化 pairwise 步骤分数**：利用角色与步骤结构产生每步数值分数；
2. **固定软 Top-1 选择**：使用 Exp105 冻结的 `alpha=0.5` 软分数，只选择一个候选提升到首位；
3. **pairwise 尾部保序**：移除提升候选后，其余步骤完全按 `pairwise_B` 数值分数排序，数值并列使用平均秩。

该设计来自 Exp105 的机制诊断：软融合把 R@1 从约 7% 提高到约 15.8%，但损害 R@3。Exp106 不继续调 alpha，而是进行秩深度模块替换，让软信号只负责首位、pairwise 信号负责尾部。

## 3.2 第二章：连续效用森林路由

RQ2 保留三个必要模块：

1. **严格 OOF 连续效用标签**：`u = RR(Exp106)-RR(recency)`；
2. **Gold-free 路由特征**：轨迹长度、角色数、角色概率最大值与 margin、归一化熵、末角色/末步骤一致性和数值分数间隔等九项；
3. **固定连续效用回归与零阈值路由**：浅层 ExtraTrees 回归 `u`，预测 `u_hat>0` 使用 Exp106，否则回退 recency。

Exp107 已证明固定线性 logistic + 0.5 阈值会在 15/15 outer folds 中 100% 选择 Exp106，不能形成第二章。Exp108 的连续效用回归是一次实质模块替换，不是调 Exp107 阈值。

# 5. 主要实验结果

## 5.1 RQ1：Exp106 独立可行性 GO

数据为 Exp96 的 731 条记录、716 个 task groups，3 seeds × 5 outer folds，主指标为 task-group 等权 MRR。

| seed | Exp106 MRR | pairwise_B | 绝对差 | 相对差 | 95% CI |
|---|---:|---:|---:|---:|---|
| 20260816 | 0.377519 | 0.344260 | +0.033259 | +9.66% | [0.020390, 0.046766] |
| 20260817 | 0.377253 | 0.344457 | +0.032796 | +9.52% | [0.019788, 0.046795] |
| 20260818 | 0.377398 | 0.342382 | +0.035016 | +10.23% | [0.021413, 0.049333] |

Pooled 绝对增益为 `+0.033691`，95% CI `[0.020358, 0.047149]`。R@1 保持约 15.8%，R@3 修复到 46.47%，超过 `pairwise_B`。删除、shuffle、Gold 隔离和 nested OOF 审计通过，判定为 `TOP1_CASCADE_FEASIBILITY_GO`。

## 5.2 RQ2 与信息桥：Exp108 两章指标 GO

| seed | Exp108 MRR | Exp106 MRR | 对 Exp106 绝对差 | 对 pairwise_B 相对差 |
|---|---:|---:|---:|---:|
| 20260816 | 0.412092 | 0.377519 | +0.034573 | +19.70% |
| 20260817 | 0.406812 | 0.377253 | +0.029559 | +18.10% |
| 20260818 | 0.413805 | 0.377398 | +0.036408 | +20.86% |

相对 Exp106 的 pooled 增益为 `+0.033513`，95% CI `[0.020493, 0.047276]`；三个 seed 各自 CI 下界也均大于 0。相对最强常规公平基线的平均提升为 `+19.56%`。

路由器选择 Exp106 的比例为 62.93%—70.86%，效用加权准确率为 74.09%—77.18%，捕获 Oracle 相对 recency 可用增益的 56.85%—62.04%。删除路由器严格退回 Exp106，shuffle 在三个 seed 均低于完整方法。

冻结判定为：

```text
UTILITY_FOREST_INTEGRATION_GO
TWO_CHAPTER_METRIC_GO
```

## 5.3 外部边界：Exp109 与 Exp110

Exp109 只用 Exp96 OOF utility 训练森林，再应用到历史冻结的 Exp97/Exp98；所有边界预测与路由决定完成后才挂接 Gold。

| 边界 | 最强公平基线 | Exp108 相对提升 | 公平比较 CI | 相对最强组件 |
|---|---|---:|---|---:|
| Exp97，168 groups | pairwise_B | +18.38% | 每 seed 下界 >0；pooled [0.02289, 0.11063] | +0.029206 MRR |
| Exp98，161 groups | recency | +17.41% | 每 seed 下界 >0；pooled [0.02496, 0.09105] | +0.02303—0.02489 MRR |

两个边界单独相对组件的 CI 因样本量较小略跨 0，所以 Exp109 如实判为 `POSITIVE_NOT_YET_GO`，没有事后降低单边界门槛。

Exp110 对每个 task group 先跨三 seed 平均，再在两个边界内部分层 bootstrap，最后等边界权重合成：

```text
跨边界组件增量 = +0.026738 MRR
95% CI = [0.003248, 0.050716]
```

组数加权敏感性为 `+0.026791`，95% CI `[0.003382, 0.050803]`。因此外部总体组件增量排除 0，判定为：

```text
TWO_CHAPTER_OPENING_EXTERNAL_SYNTHESIS_GO
```

该分析明确标注 `adaptive_posthoc=true`、`pristine_unseen=false`、`final_paper_go=false`。

# 7. 研究贡献、实验协议与实现细节

## 7.1 可主张的研究贡献

1. 将责任排序拆成“软信号只负责 Top-1、结构化 pairwise 负责尾部”的秩深度级联，解决连续融合的 R@1/R@3 冲突；
2. 把责任排序部署建模为连续效用预测，而不是固定置信阈值或永远使用单一排序器；
3. 建立 RQ1 OOF 排序到 RQ2 路由的严格信息桥，并以组件删除、shuffle 和跨边界压力证据验证其额外信息。

## 7.2 属于实验协议而非创新的内容

- task-group split、3 seeds、5 outer folds 和 inner OOF；
- 5000/10000 次 paired bootstrap；
- Gold 延迟挂接、hash seal、一次性基线选择；
- 10% 门槛、删除和 shuffle 对照。

## 7.3 属于实现细节而非创新的内容

- ExtraTrees 的 256 棵树、深度 4、叶节点最小样本 20；
- Python、scikit-learn 版本、JSON 文件格式；
- 固定随机种子和目录编号。

# 8. 与最近工作的重叠和边界

## 8.1 与 StepFinder

相同：都做失败轨迹步骤排序，使用时序与 Agent-aware 信息。  
不同：本研究不复刻完整深度时序网络，而是研究 Top-1 与尾部秩的职责分离，以及失败轨迹间策略效用异质性。  
必须补做：将 StepFinder 官方实现或严格最小复现作为正式强基线。

## 8.2 与 Process-Centric Analysis

相同：都把 Agent 轨迹视为结构化过程。  
不同：Graphectory 主要分析过程模式和效率；本研究输出责任步骤排序与路由决策。  
边界：当前结构特征不是完整 Graphectory 图，不能把它写成图程序分析的完整复现。

## 8.3 与 Who&When Pro

相同：都研究 decisive step / failure attribution。  
不同：当前方法重点是轻量级秩深度级联和样本级算法选择；Who&When Pro 提供更大规模、多模态、warm-start 可控因果标签。  
必须补做：在其正式可用数据上做 pristine unseen 验证，并制作“问题—数据—机制—指标—结论”逐项去重矩阵。

## 8.4 与 LLM routing/cascading

相同：都按样本选择策略。  
不同：本研究路由的不是大/小语言模型，也没有证明计算成本下降；它预测两种责任排序器的 reciprocal-rank 效用差。  
因此论文中应使用“效用感知选择性归因/回退”，不能写“节省 60% 成本”等未验证结论。

# 9. 剩余风险与论文阶段硬门

1. **RQ1 内部平均相对增益为 9.80%**，非常接近但未达到最终论文的 10% 门；开题可以 GO，论文主结果必须用全新外测或更强方法重新达到 10%+CI，不能四舍五入。
2. **Exp97/Exp98 曾被历史实验使用**，Exp110 是看到同向结果后的自适应合成；它足够支持开题风险判断，但不能替代 pristine unseen confirmation。
3. **当前标签主要支持排序相关性，不自动等于因果责任**。最终论文需在可控 warm-start 注入、撤销、替换或同状态重放子集上验证责任结论。
4. **第二章目前以最终 MRR 为主要效用**。正式论文需增加 risk–coverage、路由 regret、跨错误类型与跨框架分层，避免第二章退化为一个小型 ensemble trick。
5. **近三年强基线仍需补全**：StepFinder、一个 LLM failure-attribution baseline、一个 routing/cascading baseline，并保持同信息与同预算。
6. **当前外部边界规模较小**。正式实验应使用至少一个新 benchmark、框架或模型，预注册后一次性运行。

论文阶段不得继续在 Exp96/97/98 上调森林深度、叶节点或阈值。下一次方法结果必须来自预注册的 pristine unseen 数据。

# 10. 开题后的正式实验路线

1. 固定当前 Exp106 + Exp108 代码和全部超参数；
2. 获取并封存 Who&When Pro 或 StepFinder 官方可用数据，按 task / source benchmark 分组；
3. 实现 StepFinder、最近 LLM attribution 与 routing/cascading 强基线；
4. 预注册 RQ1 MRR/R@1/R@3 与 RQ2 MRR、路由 regret、risk–coverage、成本和延迟；
5. 在可控错误子集做撤销/替换/重放责任验证；
6. 一次性运行 pristine unseen 主实验，报告所有失败类型、任务组和框架分层；
7. 若 RQ1 仍低于 10% 或 pristine unseen CI 下界不大于 0，则把最终论文结论降级，但不改写本次开题证据。

# 11. 两分钟导师说明

> 多智能体系统失败以后，现有方法通常直接用一个统一模型给所有步骤排序，但不同轨迹的结构和时序线索并不总是同样可靠。第一章研究如何把责任步骤排得更准：软融合只负责选择一个最值得排查的 Top-1，结构化 pairwise 分数保留其余步骤顺序，从而同时提高首位命中率和前三名覆盖。第二章研究什么时候应该信任第一章：只用其他任务的折外结果学习第一章相对时间近因的连续效用，再按每条轨迹选择结构化定位或回退。严格 nested OOF 中，第一章相对最强基线稳定提升约 9.8%，第二章完整方法提升 19.6%，且显著超过第一章组件；两个冻结外部边界分别提升 18.4% 和 17.4%，跨边界组件增量的置信区间也排除 0。因此当前已具备两章开题 GO 的实验基础。我们不会把它写成最终论文已完成：后续还要在全新 Who&When Pro/StepFinder 数据上做强基线和因果责任验证。
