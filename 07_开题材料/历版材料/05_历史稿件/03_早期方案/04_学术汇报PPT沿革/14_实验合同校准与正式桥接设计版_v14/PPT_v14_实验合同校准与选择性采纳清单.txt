PPT v14 实验合同校准与选择性采纳清单

一、修订原则

1. 题目、研究方向、RQ1→RQ2 的总体链路和六章结构保持不变。本轮不是改题，也不把现有方法写成已定型的最终系统。
2. 外部审查意见只作为审查材料。优先级依次为：正式实验协议与代码口径、已确认的开题表达要求、论文原文事实、外部审查建议。
3. 开题报告以未来研究设计为主体。已完成数据只作为“内部先导证据”或“受控先导结果”简要出现，不把先导实验写成完整实验已经完成，也不写“前期实验不足”“尚未做完”等自我否定表述。
4. 不采纳“全稿压缩到45—48页”的建议。当前页数不设硬上限；优先补全研究现状、方法依据、实验合同和上下文过渡。只有内容重复时才合并。
5. 模块名称表示当前候选实现，而不是不可替换的最终实现。正文使用“拟采用”“当前候选实现”“将比较”“将通过消融检验”等前瞻性表述。

二、外部审查意见的选择性采纳

（一）采纳

1. 明确区分研究现象、现有工作边界、研究问题、候选方法、可证伪假设、正式实验判据和先导证据。
2. 将RQ1、RQ2对应的核心判断改写为H1、H2a、H2b，并在实验设计中逐一映射到对比与消融。
3. 校正数据谱系、特征维度、局部排序先验、Harm统计层级、恢复对照名称以及先导结果的证据边界。
4. 研究现状不能把StepFinder等方法概括为只输出Top-1。应承认其可生成步骤级分数或排名，再指出现有研究主要按离线归因指标评价，尚未在同一候选池、同一恢复预算下验证完整任务级排序的下游效用。
5. 将STRATUS相关内容写成“借鉴无回归验收原则的任务特定实例化”，不得把本研究的仓库级TNR公式写成STRATUS原式。
6. 数据表改为PowerPoint原生三线表；确实不适合三线表的内容改为三点完整文字，不再用竖线图形拼表格。

（二）不采纳

1. 不压缩为45—48页，不把核心方法依据和实验合同大量移至备份页。
2. 不改变题目、方向、RQ1→RQ2串行框架，也不因外部审查缺少实验细节而重写为另一套研究。
3. 不使用“Gold步骤”等英文占位表达；统一为“人工标注责任步骤”或与具体数据协议一致的专业中文。
4. 不把实验112的内部有效信号包装为正式结论，也不在开题中展开其工程审计失败；只说明其是确定方法方向的只读先导证据。
5. 不把实验121的14/34解释为完整RQ1排序的下游验证；完整排序桥接必须对应实验122式正式设计。

三、当前版本确有的内容不足及必须修改项

1. 研究现状的接口缺口表述失真

Who&When将责任主体与决定性步骤归因形式化；Scope Delineation通过先范围后定位降低长轨迹推理负担；StepFinder利用时序语义建模和跨步骤交互形成步骤级评分，并同时评价归因精度与排序质量。因而本文不能声称现有方法都只给出单个Top-1。

应改为：已有研究已能输出责任主体、步骤分数、候选范围或步骤排名，但诊断输出主要在离线归因指标上评价；恢复研究通常使用内部锚点、固定锚点或独立生成的恢复范围。现有证据尚未回答：在相同任务、候选池和预算下，完整任务级责任排序能否稳定改善恢复计划选择及事务式执行结果。

第一章研究现状采用“作者与年份—问题—方法—推进—仍未解决的接口”写法。引用紧跟具体论断，不能只列论文名称，也不能在一句话末端堆叠多篇引用。

2. RQ1方法中的局部排序先验定义不清

当前23维初始表示中的 frozen_e88_local_score 不是人工标签，也不是最终融合分数。应统一定义为：

“冻结局部排序先验 ℓ_i：由外层训练数据独立拟合的局部成对排序器产生，测试时仅作为只读输入；该量不访问当前测试样本的责任标注，并与最终融合得分相区分。”

为避免循环论证，实验设计增加“移除ℓ_i”消融，检验跨步骤图证据是否提供独立增益。不得使用含糊的“局部责任分数”而不解释来源和泄漏控制。

3. 23维到215维的构成存在数学口径错误

严格按实验112协议改为：

初始表示 h_i^(0) ∈ R^23 = 17维结构与可见行为描述 + 1维冻结局部排序先验 + 1维相对位置 + 3维阶段独热编码 + 1维归一化角色序号。

四个关系通道分别为：时序相邻、同角色、同完整形状签名、同非空动作形状。

图传播后的215维表示 = 23维初始表示 + 第一轮四通道邻域均值92维 + 第二轮四通道邻域均值92维 + 四通道归一化相对差距均值4维 + 四通道邻域存在标记4维。

删除“92维轮间差分”或“8维轮间变化”描述。最后8维不是92维差分，而是4维相对差距统计和4维存在标记。

4. 研究假设没有与实验合同完全对齐

在研究问题或总体框架页明确：

H1：局部可见行为证据与跨步骤关系证据具有互补性；在任务组严格外层切分下，融合模型的MRR、R@1、R@3应优于单一证据基线。

H2a：在候选池和执行预算一致时，完整RQ1责任排序对恢复计划次序具有可识别的下游效用；其结果应优于保留Top-1但替换尾部次序的对照，以及破坏完整次序的随机化对照。

H2b：恢复收益不仅取决于计划范围大小，还取决于依赖身份与事务式安全机制；在范围匹配条件下，依赖一致计划及双边验收应提高RSR并降低Harm暴露或回滚代价。

5. RQ2模块写得像既定最终系统

将“多粒度计划选择”和“可撤销双边验收”标为当前候选实现。方法章节必须先说明其可靠性依据，再进入本研究实例化：

— 局部/全局回退说明恢复计划需要覆盖不同范围；
— 检测—回退闭环说明每次尝试均需重新评估；
— 补偿执行与事务保证说明状态改变不能直接提交；
— 无回归原则说明验收同时检查目标修复和非目标状态保持。

这些设计依据在正文中给出相邻引用，但不写“本文使用了某论文的模块”。本研究只主张将完整责任排序连接到多粒度计划选择，并用任务特定的事务式验收控制提交。

6. 5.2完整实验的主视觉和条件矩阵仍不够精确

主视觉必须是唯一的串行端到端数据流：

失败轨迹 → RQ1完整责任排序π → 按π构造并排序恢复计划 → 隔离执行 → 双边验收 → 提交或撤销 → RQ2结果。

诊断MRR/R@1/R@3只作为RQ1模块的评价支路；恢复RSR/Harm/尝试次数/回滚次数/成本只作为RQ2模块的评价支路。禁止再画成两条并行方法链最后汇总。

完整排序桥接正式条件必须按实验122思路展开，而不是笼统写“固定、随机、Oracle”：

— RQ1 Full Ranking：完整RQ1排序，主方法；
— RQ1 Top-1 + Canonical Tail：保持Top-1，尾部采用规范次序，用于检验完整尾部价值；
— RQ1 Top-1 + RQ2 Posterior Tail：实验121的前置选择器，用于分离RQ2后验排序贡献；
— Shuffled Full Ranking：打乱完整排序且不保护Top-1，作为完整次序零假设；
— No-RQ1 Fixed / Uniform：不使用RQ1证据的固定/均匀对照；
— Oracle：性能上界。

同一任务、同一原生候选池、同一依赖与范围缓存、每任务预算2次、3个随机种子。当前34任务/8仓库是受控先导总体；正式实验可在资源允许时扩展样本，但协议与指标保持冻结。

7. 先导结果与正式完整实验混写

实验121的 native_ranked_dependency_slice 由“RQ1 Top-1 + 外层训练数据上的RQ2候选后验尾部”构成，不是完整RQ1排序。必须删除任何“完整RQ1排序得到14/34”或“完整排序已验证下游效用”的表达。

先导结果页按三层证据写：

（1）RQ1内部方向信号：局部成对基线MRR约0.3437，加入跨步骤证据后的只读复核约0.4961；仅用于支持继续开展正式任务组嵌套评测。

（2）RQ2前置恢复信号：同一34任务/8仓库、预算2次、3个种子下，RQ1 Top-1 + RQ2后验尾部的依赖切片为14/34；最强公平单例基线 native_prefix2 为7/34，范围匹配非依赖控制为12/34，固定依赖切片为6/34，打乱原生依赖身份为1/34，Oracle为16/34。

（3）证据边界：14/34主要同时包含恢复范围扩大和候选身份选择的贡献；范围匹配控制已达到12/34，依赖身份的净增益需由正式消融确认。该先导结果证明恢复空间可执行，但不替代完整RQ1排序桥接实验。

禁止把7/34写成“Fixed Order”；其名称应为“native_prefix2（原生前缀双单例基线）”。

8. Harm与TNR的统计对象不清

候选级验收：TNR用于判断计划执行后非目标测试与仓库约束是否保持；本研究公式是面向代码恢复任务的具体实例化，不是STRATUS原式。

执行级Harm：对每个任务×随机种子，若任一实际尝试的计划未通过TNR，或相对参考状态增加冲突，则记为一次Harm暴露。报告中的75/102→63/102属于任务×种子执行级计数。

RSR按任务统计恢复成功；尝试次数、回滚次数和执行成本分别报告。不得把Harm写成“已提交方案的有害率”，也不得将不同统计总体直接联合检验。

9. 数据谱系不完整

将AFTraj数据关系写清：本地可用1,074条轨迹记录 = 官方测试163条 + 非官方911条；非官方911条 = 开发记录731条 + 锁定确认记录180条；731条开发记录按任务分组后对应716个诊断任务组。所有训练、融合、阈值与校准只能在开发部分的外层训练折内完成；官方测试和锁定确认集保持只读。

RQ2受控先导总体为34个任务、8个仓库。必须明确它与RQ1的716个诊断任务组不是同一统计总体；两类指标分开报告，不做跨指标联合统计。

10. 已完成工作表述过度

不得写“已经完成RQ1完整排序到RQ2的正式端到端验证”。应写：

“已完成RQ1候选排序器、恢复候选池、隔离执行与事务式验收的组件原型，并形成受控先导链；下一阶段将按预注册的完整排序桥接协议开展正式比较。”

进度安排以模块开发流程表述：数据与评测协议冻结 → RQ1排序模块改进与消融 → 完整排序桥接适配器 → 多粒度计划选择模块比较 → 隔离执行与双边验收模块改进 → 端到端实验、统计与论文撰写。不得暗示模块已经最终定型。

四、版式与可读性验收

1. 实验表使用PowerPoint原生表格并采用严格三线表：仅表顶线、表头下横线、表底线，不使用竖线；其他表尽量三线表化，不适合时改成三点完整文字。
2. 红色表示重点，不依赖加粗表示重点。每句话写完整；遇到分号或句号时优先换行，避免一整段挤在单行。
3. 图编号写“图7”而不是“图 7”；图名必须紧邻图，不得被正文插入。
4. 所有英文实验条件第一次出现时在同一行给出中文解释，不另起孤立翻译行。
5. 公式、图框与正文无重叠、无溢出、无多余虚线。字体可以适当缩小，但不能删减关键定义。
6. 所有论文引用必须链接到对应正式论文页或可核验原文，而不是只链接到参考文献页；引用放在相应论断附近。

五、最终验收禁区

出现下列任一情况即不通过：

1. 5.2把RQ1与RQ2画成两条平行方法链后汇总。
2. 把实验121的14/34说成“完整RQ1排序”的结果。
3. 把7/34标成Fixed Order，或遗漏12/34范围匹配控制与6/34固定依赖控制。
4. 把215维最后8维写成轮间差分，或写出不存在的92维差分。
5. 将frozen_e88_local_score写成未说明来源的“局部责任分数”，或使人误解为读取测试标签。
6. 将任务特定TNR公式冒充为STRATUS原始定义。
7. 把75/102→63/102写成已提交计划的Harm率，而不说明任务×种子执行级口径。
8. 把先导实验写成完整实验已经完成，或宣称正式端到端结论已经得到。
9. 研究现状继续声称现有方法只输出Top-1。
10. 使用竖线图形拼接实验表，或存在明显文字溢出、图文重叠。
