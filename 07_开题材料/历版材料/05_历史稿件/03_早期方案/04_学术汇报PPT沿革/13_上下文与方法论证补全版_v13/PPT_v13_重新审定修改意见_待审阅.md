## 一、修改边界

1. **唯一底稿为 v13。** v14 对 5.1 的重写不继承，也不依据 v14 调整章节结构。

3. **不扩写工程状态。** PPT 只陈述拟开展的正式实验、统一对照、评价指标和预期效果；不出现“资产未到位”“尚未执行”“没做完”“前期不足”等内容。

## 三、第7—10页：论文名称优先，作者信息降级

### 统一写法

每项统一采用：

> 《论文正式名称》[引用]：作者等人（年份）提出/构建……；其贡献是……；但……，因此本文进一步……。

论文名称置于句首并作为主视觉；作者和年份放在冒号后。正文不再只写 FLKR、TraceElephant、ReAgent 等简称。需要强调时，将“主要设计”和“尚未解决的问题”标红，不将作者姓名标红。

### 第7页建议文案

- 《A Survey for LLM Agent Trajectory Analysis: From Failure Attribution to Enhancement》[17]：Wang 等人（2026）将智能体轨迹分析概括为失败归因、步骤定位、因果分析与轨迹增强，说明研究对象已由终局判错扩展到执行过程分析。
- 《Which Agent Causes Task Failures and When?》[2]：Zhang 等人（2025）将失败归因划分为责任主体识别与决定性错误步骤定位，并构建 Who&When 评价任务；但输出仍以单点定位为主，未形成可供恢复连续选择使用的完整候选次序。
- 《Scope Delineation Before Localization: A Two-Stage Framework for Enhancing Failure Attribution in Multi-Agent Systems》[3]：Sun 等人（2026）先依据角色职责和协作关系确定故障范围，再在范围内定位责任步骤；但候选范围尚未被定义为恢复计划的统一输入。

### 第8页建议文案

- 《Failure Localization in Multi-Agent Code Generation via Knowledge-Guided and Transferable Reasoning》[4]：Geng 等人（2026）通过行为编码、知识—策略对齐和一致性评分提高异构角色行为的可比性；其贡献主要集中于局部行为语义，跨步骤传播关系仍需显式建模。
- 《Seeing the Whole Elephant: A Benchmark for Failure Attribution in LLM-based Multi-Agent Systems》[5]：Chen 等人（2026）联合记录输入、上下文、中间状态、工具调用与执行环境，建立更完整的失败归因证据边界；但完整观测仍需结构化建模以抑制长轨迹噪声。
- 《StepFinder: A Temporal Semantic Framework for Failure Attribution in Multi-Agent Systems》[6]：Zhu 等人（2026）结合步骤语义和时序建模刻画状态演化与跨步依赖；其评价仍以责任步骤定位为主，尚未直接检验完整排序对后续恢复的效用。
- 页面收束句：上述工作依次推进了任务定义、范围约束、局部表示、完整观测与时序关系建模；本文据此联合局部行为证据与跨步骤关联，输出覆盖全部候选步骤的任务级责任排序。

### 第9页建议文案

- 《ReAgent: Reversible Multi-Agent Reasoning for Knowledge-Enhanced Multi-Hop QA》[9]：Zhao 等人（2025）保留可返回状态，并依据失败影响范围选择局部或全局回退，使恢复范围成为显式决策变量；但多个责任候选的尝试次序尚未由完整诊断排序确定。
- 《BacktrackAgent: Enhancing GUI Agent with Error Detection and Backtracking Mechanism》[10]：Wu 等人（2025）以异常检测、回退判断、反思修订和重新执行构成闭环，使诊断反馈持续参与恢复；但尚未建立诊断排序质量与任务级恢复效用之间的统一评价接口。

### 第10页建议文案

- 《SagaLLM: Context Management, Validation, and Transaction Guarantees for Multi-Agent LLM Planning》[11]：Chang 和 Geng（2025）将检查点、持久状态、补偿操作和独立验证纳入长流程事务，使恢复由控制流回退扩展到外部状态补偿；但未讨论步骤责任排序如何决定补偿候选的执行次序。
- 《STRATUS: A Multi-agent System for Autonomous Reliability Engineering of Modern Clouds》[16]：Chen 等人（2025）以状态机组织检测、诊断和缓解，并将目标故障消除与非目标行为保持共同作为提交条件；该设计能够验收恢复候选，但不负责从多个诊断候选中确定计划优先级。
- 《Where LLM Agents Fail and How They Can Learn From Failures》[18]：Zhu 等人（2025）通过 AgentDebug 对根因进行结构化分类，并将诊断反馈用于后续修正；其输出以反馈信息为主，尚未形成覆盖全部步骤、可在统一预算下驱动恢复的候选次序。
- 页面收束句：现有研究分别解决了责任定位、回退控制、状态补偿和无回归验收；本文将完整责任排序定义为诊断与恢复之间的统一接口，并在同一候选池和执行预算下检验其下游效用。

## 八、5.5：拆清稳健性、成本、复现与预期效果

### 第一页：5.5 稳健性、效率与可复现性

导语建议：

> 正式实验除报告主指标外，还将从数据分层、资源消耗和实验可复现性三个方面分析方法的适用范围与实施成本。

正文按下面的人工换行直接排版：

**01 稳健性分析**

按数据来源、软件仓库、任务类型、轨迹长度、候选步骤数和故障类型报告分层结果；

通过关系置乱、执行预算变化和验证器替换分析方法对结构扰动与实验设置的敏感性。

**02 效率与成本**

报告训练与推理耗时、模型/API调用次数、Token消耗、候选尝试次数、回滚次数和状态差分规模；

比较完整方法与各基线在相同恢复预算下的单位成功成本。

**03 可复现性**

记录数据版本、代码提交、运行环境、随机种子、实验配置和任务级原始输出；

保存统计脚本、任务划分、排除规则和结果汇总过程。

### 第二页：5.5 正式实验的预期效果

导语建议：

> 正式实验以预注册对照检验三个递进结论：责任排序是否更准确、排序信息是否改善恢复选择、依赖范围与事务验收是否提高恢复效用并控制错误干预。

**01 责任排序质量**

在相同任务划分与候选步骤集合上，完整方法预期相对局部排序、直接定位和时序排序基线提高 MRR、R@1 与 R@3；
