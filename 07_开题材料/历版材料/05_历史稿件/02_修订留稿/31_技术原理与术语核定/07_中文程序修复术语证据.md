# 中文程序修复术语核查

核查日期：2026-10-26。范围：中文软件工程、自动程序修复论文的实际用词及其与当前第三模块的对应关系；不改动现有正文或图，不评价实验结果。

**建议第三模块采用“基于测试的补丁验证”。** “补丁验证”有直接中文论文证据；“基于测试的”说明本文采用的验证手段。这个完整模块标题是依据既有术语对本文操作的描述，不宣称来自某篇论文的完整算法名称。“状态更新、累计保持已通过测试、验证失败后回退”写入流程解释。

对“补丁接纳”的结论必须限定：本轮针对精确短语进行公开互联网检索，并查读下列中文原文，**尚未核实到“测试保持约束下的补丁接纳”这一完整名称，亦未核实到将“补丁接纳”作为该类自动验证模块规范名称的高质量中文证据**。这不等于证明中文学界绝不使用“接纳”。2018年综述实际出现了“接受补丁”，也用“接纳”描述开发人员合入补丁，必须区分上下文。

## 六个候选术语的结论

| 候选词 | 本轮证据与用法边界 | 对当前模块的建议 |
|---|---|---|
| 补丁接纳 | 尚未核实为该类模块的既有名称；“接受补丁”有原文，“接纳”也有人工合入语境 | 不保留原长标题；不能对外写成“中文论文从不使用接纳” |
| 补丁验证 | 两篇2024/2025论文直接出现，2021综述也有验证模块 | 作为核心术语，标题采用“基于测试的补丁验证” |
| 补丁筛选 | 已核读原文有筛选满足条件的补丁、过滤及排序操作；不把非连续表述充作连续术语命中 | 每轮一个候选时使用“验证”更准确；若写筛选，须明确只是按条件保留/拒绝 |
| 补丁选择 | 2018综述p.592直接出现，2019综述也有评估及选择阶段 | 有多个候选需要比较或选择时更合适；当前不能暗示有排序、最优性或候选池搜索 |
| 回归测试 | 精确检索定位到陈翔等《回归测试中的测试用例优先排序技术述评》，《软件学报》2013，24(8)：1695–1712；本轮未成功取得该文完整正文，故不把检索摘录升级为已读正文证据 | 可用来解释重新执行既有测试检查修改影响的目的，但本报告不据此为本文声称测试选择/优先排序算法 |
| 迭代修复 | 2025综述已核实迭代生成和验证反馈的过程；本轮未据已读高质量中文程序修复原文确认这一连续词组作为特定算法名 | 可作普通过程说明；建议正文写“根据测试反馈继续修复”，并具体交代循环规则 |

## 可直接用于本文的机制解释

第三模块对当前轮生成的候选补丁执行测试验证。验证范围包括初始已通过测试集合B，以及先前各轮修复后已确认通过并累计保留的测试集合H_t。满足既定保留条件时，将候选作为下一轮代码状态，并按实际通过结果更新累计集合；未满足条件时，恢复至本轮修改前状态，利用本轮反馈继续修复。这样的规则旨在避免后续修改破坏已验证的结果。

该解释仅涉及有限测试集合上的执行结果和工程状态维护。B与H_t的来源、当轮新增目标的通过要求以及停止条件应在正文逐项定义；不能仅用“测试保持”替代这些规则。最终交付是否恢复成功仍由规定的独立验收判断，模块内验证通过不等同于独立验收通过。

不应从上述规则推出约束优化、强化学习、事务原子性、全输入行为保持或形式化正确性；若未来确实采用其中某项技术，应另给对应算法、假设和实现证据。
