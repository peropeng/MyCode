# RQ1 文献到方法设计追溯矩阵

## 1. 口径

本文档用于防止将工程组件拼接成研究方法后再倒找引用。文献作用分为三级：

1. **主方向锚点**：整篇论文的研究对象、主要任务或主要结论与本研究一致；
2. **方法模块来源**：整篇论文研究一种相关方法范式，但对象或场景不同；
3. **实现选择**：模型、数据结构、工具和阈值的具体实现，不能单独宣称为学术贡献。

不存在一篇已核验的 CCF-A 论文同时完整覆盖“软件工程 Agent + 过程表示 + 在线故障检测 + 可执行探针 + 语义诊断 + 候选动作区间 + 纠偏”。论文必须以“直接软件 Agent 锚点 + 整篇故障检测锚点 + 整篇混合验证锚点”构成证据链，不得宣称某一篇论文已经完成了本题全部问题。

## 3. 因文献追溯而冻结的 RQ1 方法

### M1：软件 Agent 过程证据图

不允许只保留扁平日志字段。最低图表示必须包含：

- `locate / patch / validate / finish` 阶段；
- 事件的时间边；
- 读写同一文件/函数的结构边；
- 编辑到语法、导入或受影响测试的验证依赖边；
- 只由当前及过去事件递增构建，不读未来或终局 `resolved`。

### M2：形式验证与证据门控语义诊断

- 语法、导入、文件状态和受影响测试形成 Formal Verifier；
- 显式验证失败可直接形成故障事实，不需要 API 重新“猜”一次；
- 只在任务语义、跨步依赖或建议不确定时调用 `deepseek-v4-flash`；
- API 输出必须引用过程图事件 ID 和探针证据，否则记为无根据诊断；
- 必须比较 Formal-only、Periodic-API 和 Evidence-gated Hybrid，不允许只报告 Hybrid。

### M3：从首次故障证据到保守候选区间

- 从首次稳定故障探针节点沿验证依赖边和结构边向后切片；
- 输出“最后健康证据—首次稳定故障证据”内的保守连续区间；
- RQ1 只评价区间是否覆盖私有金标动作，不输出 Top-1 责任动作；
- 区间有效性是研究假设，必须对比 Fixed/Random/Shuffled/Oracle，不能从文献直接宣称成立。

### M4：影子检测与干预分离

- P1 先在影子模式验证捕获、误报、延迟、区间和成本；
- 只有 P1 通过后，P2 才运行高层建议或回滚；
- P2 必须报告新增解决、成功回归、误干预和总成本，不以离线分类准确率替代。

## 4. 当前实验的恢复条件

RQ1 DEV 实现只有在以下条件写入方案和泄漏审计后才能恢复：

1. M1 是可递增过程图，不是扁平词法特征；
2. Formal Verifier 与 Semantic Judge 的责任分离；
3. API 仅为证据门控的语义层，Flash 模型名不写成创新点；
4. 候选区间作为待验证研究假设，不作为已知结论；
5. RQ1 不执行任何 RQ2 重放、Top-1 或干预定位。
