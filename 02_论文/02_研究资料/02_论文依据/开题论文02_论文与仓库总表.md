## 1. 核验口径

### 1.1 武汉大学专业硕士引用格式

已核验模板仓库 [iamywang/whu-thesis-latex-template](https://github.com/iamywang/whu-thesis-latex-template)，本次读取提交为 `4609860b433b4240ba2a46d5608cb2fa5a68649e`。模板说明和 `thesis.tex` 表明：

- 专业学位/学术学位的区别体现在封面等字段，不另设一套参考文献格式；
- 参考文献使用 BibTeX；
- 加载 `\usepackage{gbt7714}`；
- 使用 `\bibliographystyle{gbt7714-numerical}`；
- 使用 `\bibliography{bibs/ref1}`；
- 编译顺序为 `XeLaTeX → BibTeX → XeLaTeX → XeLaTeX`，或 `latexmk -xelatex`；
- 输出格式为 GB/T 7714—2015 顺序编码制。

可直接复制的条目已经集中在同目录的 `references_whu_gbt7714.bib`。正式写作时可以将该文件复制为模板的 `bibs/ref1.bib`，或在 `\bibliography{}` 中引用其不带扩展名的路径。

本机已用 `bibtexparser 1.4.3` 验证 34 条记录可解析、key 唯一且含 title/author/year；本机当前未安装 XeLaTeX/BibTeX，因此没有把“完整模板编译通过”作为已验证事实。

### 1.2 CCF 等级与 paper type

已下载并读取 CCF 于 2026-03-31 发布、4 月 9 日勘误的第七版目录。官方说明明确：目录等级只适用于会议正式 `Full paper` 或 `Regular paper`；Short、Demo、Technical Brief、Summary、Findings 和 Workshop 不自动继承会议等级。

本研究直接涉及的等级为：

| Venue | 第七版 CCF | 本研究可计入的类型 |
|---|---:|---|
| ICML | A | 正式主会论文 |
| NeurIPS | A | Main Conference 正式论文 |
| ACL | A | Volume 1 Long Paper |
| SIGKDD/KDD | A | 正式 Research/Regular 论文 |
| OOPSLA | A | 正式 Research Article/Full paper |
| ICSE | A | 正式 Technical Track/Full paper |

“CCF A”是 venue 与正式论文类型的组合判断，不是对单篇论文质量的保证。

## 2. 三场景正式论文与前沿方法

### P01 — SWE-Gym

- **论文**：[Training Software Engineering Agents and Verifiers with SWE-Gym](https://proceedings.mlr.press/v267/pan25g.html)
- **时间/类型**：ICML 2025 正式主会论文，PMLR 267，47717–47737；CCF A。
- **场景**：A/B/C 共用主数据和执行环境。
- **仓库**：[SWE-Gym/SWE-Gym](https://github.com/SWE-Gym/SWE-Gym)，核验 HEAD `b681068ca20628c6987b7416cc4cf03f06b77ba5`。
- **摘要**：构建 2,438 个真实 Python 软件工程任务，每个任务包含代码库、可执行环境、单元测试和自然语言问题；使用环境训练 Agent 与 verifier，并公开任务、模型和轨迹。
- **主要结论**：训练数据可显著提升开放权重 SWE Agent，轨迹 verifier 还能支持推理期选择。
- **本研究边界**：终局 `resolved` 可作任务结果 Gold，但原始数据不自动提供动作级根因 Gold。
- **BibTeX key**：`pan2025swegym`。

### P02 — SWE-agent

- **论文**：[SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering](https://proceedings.neurips.cc/paper_files/paper/2024/hash/5a7c947568c1b1328ccc5230172e1e7c-Abstract-Conference.html)
- **时间/类型**：NeurIPS 2024 Main Conference，正式论文；CCF A。

- **BibTeX key**：`yang2024sweagent`。

### P03 — Fail-Fast, Restart-Smart

- **论文**：[Fail-Fast, Restart-Smart: Early Failure Prediction and Restart for SWE Agentic Tasks](https://arxiv.org/abs/2608.03222)
- **时间/类型**：2026-08-04 arXiv 预印本；不计 CCF A。
- **场景**：A 的最直接早期失败预测前沿与强基线。
- **仓库**：截至核验日未确认作者官方专属仓库；只能实现 `FailFast-lite`，不得声称官方复现。
- **摘要**：使用可观察执行前缀、终局标签和稠密 fail-to-pass 进展监督训练轻量监控器，并研究终止失败运行后如何复用已有编辑进行重启。
- **主要结论**：部分失败可在运行结束前被识别，并在固定误报约束下节省 Token；失败轨迹中的中间修改仍可能有复用价值。
- **本研究边界**：普通“前缀预测失败”已被直接覆盖；A 必须证明风险输出对动作级 RCA 有增量。
- **BibTeX key**：`wang2026failfast`。

### P05 — Who&When

- **论文**：[Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems](https://proceedings.mlr.press/v267/zhang25cq.html)
- **时间/类型**：ICML 2025 正式主会论文，PMLR 267，76583–76599；CCF A。
- **场景**：A/C 的责任 Agent 与步骤归因任务定义和外测。
- **仓库**：[mingyin1/Agents_Failure_Attribution](https://github.com/mingyin1/Agents_Failure_Attribution)，HEAD `b2bae5c5b06d681d04ea5e9b63b7a30525c04925`。
- **摘要**：构建包含 127 个多 Agent 系统失败日志的 Who&When 数据，并标注责任 Agent 与决定性错误步骤。

- **BibTeX key**：`zhang2025whowhen`。

### P17 — Who&When Pro

- **论文**：[Who&When Pro: Can LLMs Really Attribute Failures in AI Agents?](https://arxiv.org/html/2607.09996)
- **时间/类型**：2026-07-10 arXiv；作者主页列为 ICML 2026 Workshop on Failure Modes of Agentic AI Oral（Top 6/170）。Workshop 不继承 ICML 的 CCF A 等级，按非 CCF A 前沿工作引用。

- **仓库/数据**：[whowhenpro/whowhen_pro](https://github.com/whowhenpro/whowhen_pro)，网页核验 main HEAD `db3946cae6895c8056b9b482c283fc3949a6654f`；数据 [Leoxx/whowhen_pro](https://huggingface.co/datasets/Leoxx/whowhen_pro)，CC BY 4.0。
- **摘要**：从成功轨迹精确重放前缀，在单一步骤注入 taxonomy-conditioned 错误并 warm-start 后续执行；只有确实转为失败且通过过滤的轨迹进入 benchmark，从而得到责任 Agent、决定性步骤和故障模式的构造性 Gold。数据含 12,326 条失败轨迹、26 个 benchmark、15 个 Agent 框架、18 类错误和 3 种模态。
- **主要结论**：完整轨迹 All-at-once 总体优于 Step-by-step 与 Binary-search；长轨迹显著降低步骤定位；模型常把规划、验证和协作根因误判为后期“推理”症状。最佳文本步骤准确率 73.9%，但最佳错误类型 macro-F1 仅 22.2%。100 条分层人工复核中，步骤/Agent/类型接受率为 94%/90%/90%，Fleiss κ=0.73。
- **与场景 C 的重叠**：taxonomy、warm-start 单点注入、精确 who/when/type Gold、联合预测和三种基础协议均已被覆盖，不能再作为本研究创新。
- **本研究进一步问题**：以 Pro 的数据、18 类 taxonomy 和 All-at-once 为基线，检验“两阶段故障假设提出 → 独立证据检索 → ENTAILED/CONTRADICTED/INSUFFICIENT 验证与拒识 → 责任步骤排序”是否减少症状—根因混淆，尤其在长轨迹、规划/验证/协作错误上。Oracle responsible-agent Bridge 只作机制探针，不作创新贡献。
