# RQ1实验设置与模块审查

## 审查结论

当前完整排序方法已有可复用的模型结构、训练代码及三份检查点，可以据此固定实现。尚未完成的是共同评价、严格模块消融和独立评价清单核定。Binary Search在AFTraj固定120题上的原Flash记录已核对为51/120，此前“未测试”为整理遗漏。原调用直接复用，不改变或重跑完整排序模型。

审查依据为开题修订定稿（封存原件：`../../03_开题/01_当前材料_v1.0/开题报告_评议修订稿_v1.0.md`）第3.2、5.1—5.3节及现有源码。定稿要求研究关联证据、全轨迹上下文和任务类别的作用，并未将旧版15次训练计划或具体网络参数写成不可变研究条件。这里固定的是当前实现与比较边界，后续若因明确缺陷改变实现，需另记原因、配置和影响，不能悄悄覆盖已有结果。

## 训练的对象是什么

“coding训练”指用代码任务的故障轨迹及根因步骤标签，训练一个对历史步骤打分的排序器。输入是步骤内容、角色记录和结构特征，监督目标是标注根因步骤的位置，输出是每步分数及检查顺序。它不训练代码生成模型，也不训练恢复生成器。

文本编码器使用现有冻结编码，学习的是其后的排序网络。数学轨迹与代码轨迹采用同一排序目标，区别在任务内容，不能把数学任务的答案正确率当成排序指标。

| 材料 | 规模 | 用途 |
| --- | --- | --- |
| 代码任务训练/验证 | 256/64条轨迹 | 仅代码任务训练条件，即coding-only |
| 数学任务训练/验证 | 236/58条轨迹 | 混合训练中加入的另一任务类别 |
| 混合训练/验证 | 492/122条轨迹 | 现有完整模型的训练和选轮条件 |
| 代码任务开发集合 | 363条轨迹 | 历史方法开发与匹配划分比较，不能当作训练数量或新独立测试 |
| 代码任务评价候选 | 127条轨迹 | 待核定历史使用及任务重叠后再决定能否用于独立评价 |
| AFTraj开发材料 | 731条轨迹、716个任务组 | 另一种记录形式的开发和旧外折研究 |
| AFTraj评价候选 | 163条轨迹 | 待核定曝光及任务组，不能直接宣称独立评价已就绪 |

训练、验证、评价按原问题分组。轨迹数与问题数分别登记，不能只按记录编号去重。

## 当前完整模型固定什么

153的context_models.py（封存原件：`../历史结论与经验/实验/实验153_候选条件全轨迹上下文/context_models.py`）及它继承的基础模型（封存原件：`../../02_工作区/01_工程/src/thesis_recovery/frozen/ranking/sources/original_models.py`）定义了以下流程。

| 环节 | 当前实现 | 为什么保留 |
| --- | --- | --- |
| 步骤表示 | 内容128维、角色32维、结构23维，共183维。内容和角色分别归一化，结构统计仅由训练成员计算 | 使本轮比较沿用已有模型的输入，避免换表示后将收益归于模块 |
| 状态/动作配对残差 | EventResidual利用前后配对内容及有效标志更新步骤表示 | 它已属于完整方法，应在关系和注意力消融中保持，否则一次取消多个机制 |
| 关系消息 | 投影为96维后执行2层门控多关系消息传递 | 联合相邻步骤、同一角色、记录结构相同、动作结构相同四类日志联系 |
| 全轨迹读出 | 每个候选产生query，key/value来自同一轨迹的步骤，线性输出为残差形式 | 为不同候选读取不同的全轨迹证据，不在批内跨轨迹注意 |
| 步骤评分 | 拼接关系表示、初始表示、上下文及二者差值，经评分头输出单一分数 | 所有候选在同一轨迹内形成完整顺序，步骤分数同分时按原步骤序号确定顺序 |

四类关系的构造继续遵循当前输入约定。同一角色连接前后最近步骤，动作字段非空才参与动作结构分组。角色编号仅为轨迹内归属编码，不能据此推断协作架构或真实职责。

## 哪些作用分析必须做

| 条件 | 改变内容 | 保持内容 | 能回答什么 |
| --- | --- | --- | --- |
| 完整模型 | 无 | 当前固定输入、配对残差、关系消息、候选条件全轨迹读出 | 作为全部比较的参照 |
| 去关系消息 | 取消四关系邻居聚合，使用不读取邻居的逐点变换保留层级 | 配对残差、全轨迹读出、评分、数据与训练规则 | 日志连边是否提供超出步骤表示和全轨迹交互的补充 |
| 去候选条件全轨迹注意力 | 使用已有AB_REF的轨迹均值背景替代Q/K/V/O候选读出 | 配对残差、关系消息、评分输入的含义与维度 | 候选专属的全轨迹读取是否优于共享均值背景 |
| 仅代码任务训练 | 仅使用代码训练成员，重新计算训练结构统计 | 完整模型结构、编码器、代码任务评价成员 | 在当前可用数据条件下，加入数学轨迹后的方案是否更好 |

去注意力条件仍使用轨迹均值，不能称为“完全去掉全轨迹上下文”。去关系消息仍保留状态/动作配对，因此它检验的是显式四关系消息，不等同取消一切跨步骤信息。报告时采用精确干预名称。

逐点替代与关系层的参数量不同，注意力与均值背景的容量也不同。主分析报告这种差别及训练条件，不将观察到的全部差异直接解释为关系语义本身的因果效应。只有主结果需要进一步区分容量时，再增设容量控制，不先恢复旧154全套控制臂。

历史154的内容清零、关系重排、四关系复制相邻关系、点层容量替换，和上述两项干预均不完全相同。已有训练结果继续保留，不抵扣新作用分析。旧157/159跨划分组合也不等于固定同一划分的重复初始化。

## 仅代码任务训练为什么需要，能说明多少

RQ1需要判断关联证据在代码与数学任务上的表现，不能只给混合总成绩。分任务评价是基本要求，应先报告代码和数学的各自计数。

仅代码任务训练进一步回答：若最终面向代码故障排序，保留数学训练数据是否值得。它是有明确用途的类别分析，优先级低于补齐三基线、完成核心模块比较及核定独立评价，不是启动完整模型推断的前置条件。

现有混合训练492条，代码训练256条。直接比较同时改变了类别、样本量和每轮更新次数，因此只能说明“加入现有数学数据后的整体训练方案”如何变化，不能单独证明数学内容具有迁移收益。若要提出后者，需追加同量训练成员、匹配优化更新预算的对照，并提前固定采样和验证规则。不能见结果后再决定保留哪个子集。

代码任务比较应使用相同的代码验证64条、同一选轮指标及相同代码评价清单。现有混合模型按122条混合验证选轮，直接与代码64条选轮的新模型比较还包含选轮目标差异。因此有两条可行路径：沿用原122条选轮并明确只报告整个训练方案差异，或为这项类别分析将两个条件都统一到代码64条选轮。后一路径需要查已有逐轮检查点是否足够复用，不能直接将现有混合最终检查点当作已完成的匹配对照。

## 训练与评价条件

已有153源码的训练条件为：轨迹内根因位置交叉熵，按轨迹平均，AdamW学习率0.001、权重衰减0.0001，批量16条轨迹，最多40轮，连续8轮不改善停止。验证先比较Top-1，再比较MRR，完全相同时保留更早轮次。结构标准化只拟合训练成员。StepFinder使用对应论文预设和其原生损失，不强行改成本方法损失。

新配置沿用这些已有条件作为实现基准，避免根据开发成绩反复调参。模块比较固定数据、编码、验证规则和共同参数初始化，新增模块的初始化另记。重复次数、种子及每个条件的模型身份必须在运行前记录。原始训练代码中的历史路径、期限和108模型/198阶段调度只作档案，不能直接启动为新实验。

当前三份完整模型保留。三份StepFinder模型也保留为复用候选，其中一份独立训练回执缺失。模型身份、验证成员及已找回训练证据见核查回执（封存原件：`../../02_工作区/01_工程/verification/experiment_reuse_assessment.json`）。模型能推断与符合新研究比较条件是两项判断，尚不提前将六份候选计入正式完成数。

共同评价包括Who&When All-at-Once、Who&When Binary Search、StepFinder和本方法，统一公开轨迹、步骤边界、根因位置映射及任务清单。学习式方法报告Top-1、MRR、Hit@3/5，生成式方法按其输出能力报告Top-1、调用数及token，不为单位置输出伪造完整排序。

Binary Search固定120题已在129完成，120份均有效，共377次Flash请求，51题正确。129原输入及零基映射可直接核对，153与158保留的源码及历史通过回执确认固定清单沿用。当前模型完整逐题数组缺失，不重新计算配对显著性，具体限制见核对说明（封存原件：`固定120题基线核对.md`）。原步骤日志采用Step i与字段JSON，不能将新简版role:content适配器视为逐字相同协议；已完成原调用不重发。其他未完成记录只有输入、后端、提示词、参数与映射一致时才续跑，变化另开记录。

效率分别统计首次加载和已加载场景的P50/P95，明确文本编码、特征构造及模型评分是否计入，固定硬件、线程、轨迹长度分布和批量。无效输出、执行错误和预算耗尽分别报告，未完成记录不得填0。比较分母和缺失处理规则在运行前核定。现有开发比较、迁移回放和接口测试均不替代新独立评价。

## 本轮代码处理的边界

工程新增的rq1_study.py（封存原件：`../../02_工作区/01_工程/src/thesis_recovery/rq1_study.py`）将当前设置从旧153的路径、截止时间和全套调度中独立出来。完整模型精确使用冻结AB_GLOBAL，去关系条件将两层RelationLayer替换为两层NodeLayer，去候选注意力使用冻结AB_REF。共同参数按同一种子的完整模型复制，参数量差别保留记录，不宣称同容量。仅代码条件筛选256/64成员并重新拟合结构统计。

StepFinder采用已选定的ALG_PAPER50预设，学习率0.001、权重衰减0.00001、最多50轮、耐心10轮、时序损失权重0.9，不混用153内部SF_REF的40轮配置。完整模型和消融沿用最多40轮、耐心8轮的既有规则。

准备入口只读取公共成员信息并绑定文件，不解析标签值。训练入口是单独动作，支持按已完成epoch续接。新入口不是历史训练逐字节复跑，也不自动执行独立评价。本轮代码与配置准备不代表训练、付费基线预测或Gold评价已经完成。
