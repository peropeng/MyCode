## 为何不选择只需本地测试的缩减算法凑数

ddmin（TSE 2002）、ProbDD（ESEC/FSE 2021）、CDD（ICSE 2025）及 Wddmin（WDD，ICSE 2025）均有无需模型的本地算法实现，但主要任务是缩小满足某一性质的集合。它们可以被适配为“缩小已知能恢复的撤销集合”，前提是已经取得这样一个初始集合。

当前主实验要求方法从失败状态自行找到恢复结果。若先向缩减器提供已经能恢复的答案，再比较首次恢复成功率，就改变了问题；若让所有方法共用一个先找到答案的过程，该过程的作用和预算也必须计入。不能简单把缩减代码里的 FAIL 改为 PASS，便称为四种完整智能体恢复系统。因此本轮不把它们加入这张完整恢复主表。

参考：[ddmin 作者论文](https://www.st.cs.uni-saarland.de/papers/tse2002/)、[ProbDD 正式记录](https://2021.esec-fse.org/details/fse-2021-papers/94/Probabilistic-Delta-Debugging)、[CDD 正式记录](https://doi.org/10.1109/ICSE55347.2025.00117)、[WDD 作者论文](https://cs.uwaterloo.ca/~cnsun/public/publication/icse25_wdd/)。CDD 的预印本发表于 2024 年，正式发表为 ICSE 2025，不标作 FSE 2024。

## 数据仅保留三项来源

1. **AF-Traj**：用于训练责任排序器和分析诊断表现，当前允许使用的开发部分为 731 条记录、716 个任务组。
2. **OpenHands-SFT-Trajectories**：提供软件任务的实际执行日志和编辑参数。[官方数据](https://huggingface.co/datasets/SWE-Gym/OpenHands-SFT-Trajectories)
3. **SWE-Gym**：提供对应任务、仓库基线和原生测试。[官方数据](https://huggingface.co/datasets/SWE-Gym/SWE-Gym)

后两项按任务标识配对，整理为**同一套恢复任务**。它们不是两个独立外部测试集。由中间编辑状态得到的恢复任务是本研究的派生数据，须固定纳入规则、失败前缀、编辑记录和测试。

Who&When、TraceElephant 和 SyncBench 保留为相关研究参考，不再同时列为计划采用的数据集。所有完整方法使用相同的恢复任务清单。排序训练任务、预算确定所用的开发任务与最终测试任务分开，反复查看过的三个 moto 状态不能改称未见测试集。

## “同一数据、同一参数”应怎样落实

公平比较要统一可共同控制的条件，不是使不同算法的所有参数相同。

- **共同任务**：相同任务 ID、失败文件字节、检查点、截断日志、编辑记录与任务说明。
- **共同执行环境**：相同依赖、硬件、文件操作权限、固定测试和单次超时。不向某一方法提供正确责任位置或最终修复补丁。
- **共同评价**：所有方法使用相同的可见恢复测试，隐藏保护测试只作最终验收。未执行、预算用尽和执行失败都如实记录，不在比较后更换测试。
- **共同资源约束**：统一候选状态评估预算与总时限，记录整个方法的实际成本，不能只计算本文的回滚操作。
- **生成式基线的共同配置**：相同基础模型权重、量化、上下文上限、温度、采样设置和随机种子。只允许本机推理，不启用云端回退或在线搜索来补充某项方法的输入。
- **算法特有参数**：树搜索分支数、检索策略、排序器学习率等含义不同，按原论文或独立开发任务确定，并在最终测试前固定。不把树搜索次数与训练轮数强行设成一个数。

提示词保留各方法的原有决策方式，仅统一任务说明、操作权限和适配必需的格式。工具名字或封装可以随方法保留，但底层能力和可见信息应相同，不能为了“相同工具”删掉某方法的关键功能。

旧开发配置的六次候选提交、十二次模型生成和十五分钟上限，尚未证明适合这五种完整方法，不能直接当成正式统一参数。预算与具体本地模型需在测试集之外确定，避免让无法正常执行的基线充当弱比较对象。

## 当前能否直接做公平比较

**当前不能直接给出五方法的公平效果比较。**已具备部分共同数据与本文本地恢复实现，也有上述公开基线源码；但四个完整基线的本地模型接入、共同失败状态适配、版本与预算冻结尚未完成。当前只有三个开发状态，而且都是单次编辑撤销，没有错误之后的其他编辑，不能检验多编辑依赖处理的优势。

在允许本机离线推理的前提下，上述统一比较在方法设计上可以组织，不依赖在线 API 额度。但“可组织”不同于“现在已经完成”，本轮不启动这项实验。

当前证据应写为：本文排序 MRR 0.4961，低于同数据适配的 StepFinder 0.8458；三个状态的恢复记录尚无完整基线比较。**这些证据尚未支持本文具有方法优势。**不得将“文件重放与测试能执行”列作有效性结论。后续效果需来自固定任务上相对基线的可重复改善，并报告差值与不确定性；没有改善也应保留结果，而不是改称“突出”。

## 两种结构关系的实际含义

当前实现的“结构”是 JSON 记录的粗粒度编码：保留数据类型、元素数量类别和有限的嵌套信息，丢弃键名与具体取值。例如 `{"tool":"read","path":"a.py"}` 和 `{"tool":"write","path":"b.py"}` 都是包含两个字符串值的对象，编码相同，操作却不同。外面再加一层列表后，编码改变。

“整条记录结构相同”同时比较正文、动作、思考三项编码，以及动作是否为对象列表和是否包含多项调用。“非空动作结构相同”只比较非空 action 字段，正文与思考可以不同。后一条不能简称为“同动作”，因为没有判断语义动作是否相同。

实现还有明确限制：普通文本和空字段的结构标记都可能是“未解析”，是否为空另列数值特征；数量按 0、1、2、至少 3 项分组，每层最多展开前八个子项，最大深度四层。故结构关系是一种待检验的日志格式假设，不是已经证明的功能或因果联系。
