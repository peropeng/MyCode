# 开题设想05：两章最终主线与实验审计边界

## 1. 研究主线

本研究的两章形成可检验的输出递进关系：第一章在失败轨迹中对责任步骤进行全排序；第二章把该排序作为恢复候选的先验，在持久化状态和有限重放条件下选择事务式回滚/重放范围。两章共享可观测执行证据，但不重复计算指标，也不把 RQ1 的排序提升倒灌为 RQ2 的恢复提升。

RQ1 的最终证据是 Exp112C：B2 约 `+33.3350%`、A+B 约 `+44.3302%`，pooled CI 下界分别约 `0.09493`、`0.13237`。RQ2 的最终证据是 Exp121：`14/34` 对 `7/34`，相对 `+100%`，CI 下界 `0.088235294`。RQ2 的 extent control 为 `12/34`，same-target dependency 仅净增 `2`，所以开题应写组合方法价值，不写“依赖语义单独造成全部提升”。

## 2. 审计是开题边界的一部分

完整审计原件位于 [`开题/实验审计`](../实验审计/README.md)。该审计快照覆盖实验 01–68，作用是说明为什么历史负结果不能被粗略归并为算法失败，也说明当前工作如何从资产、协议和故事边界收敛到可行主线。后续 Exp112C–Exp121 的当前裁决以 [`结论46`](../../结论/结论46_20260826两章最终主线裁决.md) 和交接09为准。

审计把证据分为 `TRUE_METHOD_NO_GO`、`HARNESS_INVALID`、`ASSET_STOP`、`STORY_MISMATCH`、`COMBINATION_NO_GAIN` 等类别。只有 E10/E44/E45/E46/E48/E65 进入可信方法 NO-GO；协议无效、资产不承载或故事不匹配的材料仍保留为研究边界和设计经验，不能在论文中写成“多种算法失败”。

## 3. 数据可行性与门槛设计

恢复任务的可恢复空间是离散的，开题实验在冻结门槛前先计算 baseline、Oracle、候选池和分母。Exp119C 显示旧 8-candidate 资产的 `11/34` baseline 与 `12/34` Oracle 只能支持 `9.0909%` 的最大相对提升；`≥15%` 需要至少 13 个恢复任务，因而该门在原资产上数学不可达。该结果证明的是评价包络上限，不是整个方法方向的 NO-GO。

同理，实验输出若因 coverage、evaluator、Gold 可见性或写入协议失效，必须标为 `HARNESS_INVALID` 并新建纠正命名空间；原始输出不可覆盖。所有未达到 GO 但具有真实、非误差正提升的结果仍作为互补机制或边界证据保留。

## 4. 活动面与复现边界

开题只引用 [`实验/README.md`](../../实验/README.md) 指向的正式依赖链。冻结实验目录仍原位，因为 runner 对父实验路径有硬编码依赖；独立 Git worktree 统一位于 [`工作区/README.md`](../../工作区/README.md) 规定的顶层路径，是执行隔离而不是最终资料层级。重复 Exp112a 支线只有设计冻结/诊断草稿，没有正式结果，不构成第二次实验、复现或 GO 证据。

本边界支持的表述是：在当前受控、可执行资产上，责任步骤全排序和诊断引导的依赖感知事务式恢复均具有章节可行性；不把结果扩张成自然失败上的通用因果、自愈或自动代码修复结论。完整主线入口见 [`交接10`](../../交接/交接10_20260826主线工作区与归档入口.md)。
