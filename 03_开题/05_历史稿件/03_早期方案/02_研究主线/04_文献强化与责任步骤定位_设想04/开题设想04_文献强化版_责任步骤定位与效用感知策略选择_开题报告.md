# 摘要

大型语言模型驱动的多智能体系统能够通过角色分工、工具调用和多轮协作完成复杂任务，但自然语言推理的非确定性、跨 Agent 依赖和错误传播使失败调试变得困难。现有高水平研究已经把“识别失败责任 Agent 与决定性错误步骤”正式定义为自动失败归因问题，并连续提出作用域划分、全轨迹可观测、时序语义定位和知识引导定位等方法。这说明：从失败轨迹中定位责任步骤不是本文为了适配数据而自造的问题，而是一个近三年迅速形成的通用 Agent/MAS 研究方向。

然而，失败并不适合由一种固定机制统一处理。近三年的 Agent 可靠性研究已经分别在多智能体协作、云 SRE、GUI Agent、多跳推理和协作软件工程中，把“根据风险、异常或冲突状态进行条件化诊断、隔离、回退或恢复”作为全文主问题。与此相邻的高水平路由与选择性预测研究又证明，可以根据样本可见信息估计候选方法的相对质量或可靠性，再选择专家、级联路径或安全回退。本文将这两条研究流交叉：第二章研究异质失败轨迹下的自适应诊断与可靠回退，当前可行性实现聚焦于在不知道责任金标时，何时使用结构化责任定位、何时回退到稳健近因排序。

据此，本课题设置两个递进但输出不同的研究问题：第一章研究责任步骤的完整排序；第二章研究异质失败轨迹下的自适应诊断与可靠回退，样本级归因策略选择是其当前可验证实例。当前严格嵌套折外实验中，第一章相对最强结构基线获得稳定的非误差增益；第二章的当前实例显著超过第一章组件和固定回退组件，并在两个冻结历史边界上得到同向结果，跨边界合成置信区间排除零。因此，在采用这一最小问题重述并明确文献层级后，当前证据支持“两章开题 GO”；最终论文仍需补充预注册的全新未见外测、最新强基线、risk–coverage 和可执行责任验证。

**关键词：** 多智能体系统；AgentOps；失败归因；责任步骤定位；自适应诊断；选择性预测；可靠回退

## 1.2 RQ1 的最强对应论文

[Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems](https://proceedings.mlr.press/v267/zhang25cq.html)，ICML 2025，CCF A。

这篇论文不是借用一个归因模块，而是整篇正式提出和定义 LLM 多智能体系统的自动失败归因任务：输入失败日志，输出责任 Agent 和决定性错误步骤；论文构建 Who&When 数据集并系统比较多种归因方法。其结论是责任 Agent 的最佳准确率为 53.5%，而责任步骤只有 14.2%，部分方法甚至低于随机，说明步骤级归因困难且远未解决。它与 RQ1 的研究对象、输入形态、输出目标和主要评价对象直接一致，是最强问题锚点。

## 1.3 RQ2 的最强对应论文与口径修正

[Taming “Zombie” Agents: A Markov State-Aware Framework for Resilient Multi-Agent Evolution](https://aclanthology.org/2026.acl-long.373/)，ACL 2026 Long，CCF A；以及 [STRATUS: A Multi-agent System for Autonomous Reliability Engineering of Modern Clouds](https://proceedings.neurips.cc/paper_files/paper/2025/hash/47a6e9e2c3019f13ad94a0f259fe4970-Abstract-Conference.html)，NeurIPS 2025 Main，CCF A。

前者整篇研究多 Agent 中暂时失效或产生幻觉的节点不应一律硬删除，而应根据风险在 Active、Standby、Terminated 状态间自适应转换；后者整篇研究 Agentic SRE 中的失败检测、诊断、缓解和安全状态机，并在两个可靠性基准上把故障缓解成功率提高至少 1.5 倍。它们的方法、场景和本文不同，但全文共同证明了 RQ2 的更大问题：**异质 Agent 失败状态需要条件化诊断、隔离、回退或恢复，固定处理策略并不可靠。**

需要特别纠正：截至本次审计，没有发现 5 篇、甚至 1 篇近三年 CCF B+ 正式论文，把“对每条失败轨迹选择哪一个归因器，并以归因 MRR 为目标”作为全文主问题。因此不能用 BEST-Route、Smoothie 等通用 LLM 路由论文冒充 Agent 领域强对应论文。本文采用最小重述：RQ2 是“异质失败轨迹下的自适应诊断与可靠回退”，Exp108 的归因器效用路由是该问题的当前具体化；通用 routing/cascading 论文只作方法支持。

# 3. 研究背景与问题提出

## 3.1 Agent/MAS 失败为什么难以调试

传统程序故障通常能够映射到代码位置、异常栈或测试失败，但 LLM 多智能体系统的失败具有四个特点：

1. **错误在自然语言交互中传播。** 上游 Agent 的不完整计划可能在多个后续步骤后才表现为失败；
2. **责任主体与症状主体不同。** 最后输出错误的 Agent 不一定是最早产生决定性错误的 Agent；
3. **轨迹长且噪声多。** 大量正确步骤、冗余消息与工具返回会稀释真正的责任证据；
4. **同一策略并非处处可靠。** 完整/部分可观测性、轨迹长度、角色数量、错误位置和任务类型都会改变定位难度。

Who&When 的责任步骤准确率远低于责任 Agent 准确率；TraceElephant 进一步发现，补全输入和上下文后，归因准确率相对部分可观测版本最多提高 76.5%。这些结论共同表明，责任步骤定位既是通用问题，也存在显著的样本与观测条件异质性。

## 3.2 从“统一处理”到“条件化诊断与回退”

现有失败归因工作主要回答“怎样设计一个更好的归因器”，但部署时还存在另一个更大的 Agent 可靠性问题：不同失败状态是否应采用不同诊断、隔离、回退或恢复策略。AgentRevive 根据风险在三个 Agent 状态间软转换；STRATUS 以检测—诊断—缓解状态机处理云故障；BacktrackAgent 和 ReAgent 在错误或冲突出现后触发 backtracking/rollback；SyncMind 发现现有 Agent 在不同 out-of-sync 状态下缺乏资源意识和适应能力。这些整篇论文说明，固定失败处理机制并不充分。

通用路由、级联与选择性预测研究进一步提供了一个可操作的抽象：候选方法的相对表现随样本变化，系统可从可见信号估计当前质量、难度或可靠性，再逐样本选择专家或回退。本文不把该研究流机械移植为“大/小模型成本路由”，而是将其作为 RQ2 的方法论，把 Agent 失败处理问题具体化为：**先选择能给出更可靠责任排名的诊断策略，再为后续回退或恢复提供可信候选。**

## 3.3 研究空白

三条研究流尚未充分交叉：

- 失败归因论文大多对所有轨迹应用固定归因方法或固定观测配置；
- Agent 可靠性论文会进行状态转换、隔离、backtracking 或 recovery，但通常不比较失败归因策略的样本级相对效用；
- 通用路由论文大多选择 LLM、专家或计算路径，而非选择 Agent 失败诊断策略；
- 当前没有发现一篇 2024—2026 CCF B+ 正式论文，把“逐失败轨迹预测归因器相对效用并安全回退”作为完整标准任务。

因此，不能声称“选择性归因路由”已经是一个拥有 5 篇直接先例的成熟子领域。本文采用的开题逻辑是：责任步骤归因和自适应失败处理分别都有整篇高水平论文支撑；样本级质量估计与回退有成熟方法论；Exp108/Exp110 已证明三者交叉的最小实例可行。研究空白本身构成创新位置，但最终论文必须把归因可靠性、route regret、risk–coverage 与可执行回退价值补齐，避免只剩离线两臂 ensemble。

## 4.2 RQ1 研究现状归纳

现有工作形成四条路线：

1. **任务定义与基准化：** Who&When、TraceElephant；
2. **长轨迹搜索空间收缩：** Scope Delineation；
3. **时序表示与轻量定位：** StepFinder；
4. **领域知识、反事实标注与可执行反馈：** FLKR、AgenTracer。

共同结论不是“问题已经解决”，而是：责任步骤比责任 Agent 更难；完整证据、时序结构与搜索空间设计显著影响结果；当前仍有较大提升空间。这直接证明 RQ1 的必要性。

## 4.3 RQ1 与现有工作的差异

本文不主张首次提出失败归因，也不主张首次使用时序信息。第一章研究的具体空白是：

- 现有连续分数融合容易出现 Top-1 提升与尾部秩覆盖相冲突；
- 本文把“首位候选选择”和“尾部完整排序”分配给不同证据臂；
- 输出不是一句解释，而是可用于后续排查、回退和评估的完整步骤排名。

# 5. RQ2 研究现状：异质失败状态下的自适应诊断与可靠回退

## 5.1 先区分字面子任务与更大研究问题

当前 Exp108 的字面子任务是：逐失败轨迹预测 RQ1 相对 recency 的效用，并在两个归因器间选择。严格检索没有发现一篇近三年 CCF B+ 正式论文把这一字面任务作为全文主问题，严格数量为 **0**。因此本报告不再用通用 LLM routing 论文凑成“归因器路由已有 5 篇先例”。

开题采用的 RQ2 更大问题是：**面对异质 Agent 失败状态，如何依据部署时可见风险、异常或冲突证据，条件化选择诊断、隔离、回退或恢复策略，以降低固定处理机制的失效。** Exp108 的 OOF 效用路由是这个问题在失败归因阶段的当前具体化。按这一问题层级，已有至少 6 篇近三年 CCF B+ 正式论文整篇研究同一问题家族。

# 7. 研究目标与研究问题

## 7.1 总体目标

面向已有失败结果和完整执行轨迹的 LLM 多智能体系统，研究一种既能给出高质量责任步骤完整排序，又能根据样本级可见证据判断何时信任该排序、何时回退的可靠失败归因方法。

## 7.2 RQ1：秩深度感知的责任步骤级联定位

### 白话问题

一条多智能体轨迹已经失败时，怎样把最值得排查的责任步骤放到最前面，同时不破坏其余候选的整体顺序？

### 学术问题

> 给定仅含部署时可见角色、步骤位置、轨迹结构和冻结预测分数的失败执行轨迹，秩深度感知的级联排序能否在不读取责任 Gold 的条件下，相对时序近因、结构化 pairwise 和统一连续融合等强基线，稳定提高任务组等权 MRR、R@1 与 R@3？

### 输入与输出

- 输入：失败轨迹的 Agent、步骤、结构和冻结分数；
- 输出：全部步骤的责任候选完整排名；
- 不读取：`mistake_agent`、`mistake_step`、测试任务标识、未来信息或外部 Gold。

### 核心假设 H1

Top-1 候选选择和尾部排序需要不同证据臂；让软信号只负责首位、让 pairwise 信号保持尾部顺序，可以避免统一融合造成的 R@1/R@3 冲突。

## 7.3 RQ2：异质失败轨迹下的自适应诊断与可靠回退

### 白话问题

不同失败状态不应统一处理。系统怎样利用部署时可见证据判断应采用哪种诊断策略、何时回退，并避免不可靠诊断继续误导后续处置？当前实验先回答其中最小且可验证的一步：使用 RQ1 还是回退到时间近因排序。

### 学术问题

> 面对状态、结构和证据异质的 Agent 失败轨迹，能否依据部署时可见信息条件化选择诊断或回退策略，以降低固定失败处理机制的失效？在当前失败归因具体化中，给定 RQ1 的严格折外排序和 Gold-free 特征，能否预测 RQ1 相对稳健回退策略的连续效用，使最终责任排名显著优于任一固定策略，同时控制 Oracle regret 和错误路由风险？

### 输入与输出

- 广义输入：失败状态、结构、异常、冲突和不确定性等部署时可见证据；
- 当前具体化输入：RQ1 的严格 OOF 排名和九个 Gold-free 特征；
- 学习目标：`u = RR(RQ1)-RR(recency)`；
- 当前输出：预测效用、使用 RQ1/回退的决策以及最终责任排序；
- 论文阶段扩展输出：risk–coverage、拒识/复核建议，以及在可执行子集上的回退或恢复收益；
- 评价：最终 MRR、组件增益、效用加权准确率、Oracle regret、risk–coverage、删除和 shuffle 对照。

### 核心假设 H2

失败轨迹的结构和不确定性能够预测不同诊断策略的相对效用；当前归因实例的样本级选择应显著超过永远使用 RQ1 或永远使用 recency，并在未见边界上保持正向增益。若最终无法把该选择扩展为可靠性/回退价值，第二章必须降级为方法模块而不能冒充完整失败处置系统。

# 8. 两章关系与论文故事

## 8.1 主故事：从“定位”到“可信部署”

```text
失败执行轨迹
    │
    ├─ 第一章：生成责任步骤完整排序
    │      解决“先查哪一步”
    │      输出 Top-1 + 保序尾部排名
    │
    └─ 第二章：在异质失败状态下选择诊断或可靠回退
           当前实例解决“本次是否应信任第一章”
           输出策略选择 + 最终排名 + 风险/回退信息
```

## 8.2 两章不是同一问题换指标

| 维度 | 第一章 RQ1 | 第二章 RQ2 |
|---|---|---|
| 研究目的 | 生成高质量责任排序 | 在异质失败状态下选择诊断、复核或回退；当前聚焦前两臂 |
| 主要输出 | 完整步骤排名 | 相对效用、策略决定、最终排名与风险/回退信息 |
| 强基线 | recency、pairwise、连续融合、StepFinder/LLM attribution | RQ1、recency、固定 arm、线性 gate、routing/cascading |
| 失败条件 | 提高 Top-1 却破坏尾部覆盖 | 退化为永远选同一 arm 或无法超过最强组件 |
| 独立价值 | 帮助开发者确定排查顺序 | 避免不可靠归因器在不适合样本上造成错误定位 |

## 8.3 可证伪的 RQ1→RQ2 桥

第二章训练效用标签时，必须使用 inner-held OOF 的 RQ1 预测；应用于 outer-held 时不得接触该任务的责任 Gold。若删除 RQ1 输出后第二章不变，或打乱 RQ1 输出后仍不受影响，则两章桥接失败。Exp108 的删除与 shuffle 对照已经通过该最低要求。

# 9. 研究方法

## 9.1 第一章方法：Top-1 提升级联

第一章包含三个模块：

1. **结构化 pairwise 步骤评分。** 利用角色、步骤和局部结构得到完整步骤分数；
2. **固定软 Top-1 选择。** 使用冻结软分数只选择一个候选提升到首位；
3. **pairwise 尾部保序。** 移除首位候选后，其余步骤严格保持 pairwise 数值顺序。

该方法针对 Exp105 暴露的机制冲突：统一软融合提高 R@1，却损害 R@3；级联不是继续调权重，而是进行模块职责分离。

## 9.2 第二章当前具体化：连续效用森林与零阈值回退

第二章的更大问题是异质失败状态下的自适应诊断与可靠回退；当前可行性实验先把可证伪范围限制为两种归因策略。该具体化包含三个模块：

1. **严格 OOF 效用构造。** 在训练折中用 inner-held 预测计算 `RR(RQ1)-RR(recency)`；
2. **Gold-free 特征。** 使用轨迹长度、角色数、角色概率最大值与 margin、归一化熵、末角色/末步骤一致性、分数间隔等九项部署可见特征；
3. **连续效用预测。** 使用冻结浅层 ExtraTrees 回归效用，`u_hat>0` 时使用 RQ1，否则回退 recency。

Exp107 的线性二分类 gate 在 15/15 个 outer folds 中 100% 选择 RQ1，已判定为退化。Exp108 是从二分类 gate 到连续效用回归的模块替换，不是事后调阈值。

# 11. 必要性、创新性与可行性论证

## 11.1 RQ1 必要性

RQ1 获得 5 篇领域内强对应 CCF A 正式论文支持；Who&When 的低步骤准确率、TraceElephant 的观测差异、StepFinder/Scope/FLKR 的持续方法升级共同说明问题通用、困难且未解决。Exp106 又证明当前模块设计具有稳定的非误差提高。因此 RQ1 的“问题存在性”和“本项目可行性”均为 GO。

## 11.2 RQ2 必要性

重述后的 RQ2 获得 6 篇 Agent 领域 CCF B+ 正式论文支持：这些论文整篇研究风险条件下的 Agent 状态选择、检测—诊断—缓解、faulty-agent 防御、backtracking、rollback 或 out-of-sync recovery，一致表明异质失败状态需要条件化处理。Who&When、TraceElephant 等又证明归因方法和观测配置存在显著异质性；Exp108/110 证明其中“归因策略选择”这一最小实例可被部署可见特征部分预测。因此 RQ2 的更大 Agent 目的成立，但必须保留边界：目前没有 5 篇字面同题的 attribution-router 论文，现有离线 MRR 路由也尚未等价于完整恢复系统。

## 11.3 预期创新点

1. **秩深度职责分离。** 将 Top-1 选择与尾部完整排序交给不同证据臂，处理统一融合的首位—覆盖冲突；
2. **失败归因中的相对效用建模。** 不预测抽象置信度，而是直接预测两种归因策略的 reciprocal-rank 效用差；
3. **严格样本外策略桥接。** 以 RQ1 的 OOF 产出训练 RQ2，并通过删除、shuffle、固定 arm 和跨边界验证约束信息泄漏；
4. **从固定归因器到可靠回退。** 把通用算法选择问题落到 AgentOps 失败诊断中，输出可审计的策略选择和最终责任排序。

## 11.4 不属于创新的内容

- task-group split、bootstrap、Gold 延迟挂接；
- ExtraTrees 的具体树数、深度和叶节点大小；
- JSON 格式、Python 版本、固定随机种子；
- 通用 routing/cascading 概念本身。

## 12.2 RQ2 主实验

### 强基线

- 永远使用 RQ1；
- 永远使用 recency；
- Oracle 路由上界；
- 线性 logistic gate；
- 置信阈值/选择性拒识；
- routing/cascading 的质量估计基线；
- 随机和 shuffled routing；
- 在可执行子集上比较不回退、固定回退、随机回退与 Oracle 回退。

### 指标

- 最终 MRR 与相对最强固定组件的配对增益；
- 路由选择率、效用加权准确率；
- Oracle regret；
- risk–coverage；
- 跨框架、任务类型和错误位置的迁移；
- 额外计算成本和推理延迟，仅作为次指标；
- 可执行子集的恢复成功率、无回归率和错误回退代价。

### 消融

- 删除 RQ1 OOF 输出；
- 打乱 RQ1 排名或路由决定；
- 二分类标签替代连续效用；
- 删除不确定性特征；
- 固定阈值与零阈值比较。

## 12.3 最终论文硬门

1. 在预注册的 pristine unseen 数据上，RQ1 相对最强公平强基线的差异 CI 下界大于零；
2. RQ2 相对最强固定组件的差异 CI 下界大于零，且路由不退化；
3. RQ1 的真实 OOF 输出对 RQ2 有删除与 shuffle 可证伪增益；
4. 至少一个可控错误子集完成撤销、替换或同状态重放，并证明第二章的回退/处置选择带来结果收益；否则第二章只能主张“诊断策略选择”，不能主张“失败恢复”；
5. 报告所有失败分层，不以平均值掩盖某类轨迹的退化；
6. 不再在 Exp96/97/98 上调超参数或改变门槛。

# 16. 最终开题结论

## 16.1 文献 Gate

- RQ1：严格领域强对应 CCF A 正式论文 **6 篇**；**GO**。
- RQ2 广义问题家族：Agent 自适应失败诊断、处置、回退或恢复的 CCF B+ 正式论文 **6 篇**；采用最小重述后 **GO**。
- RQ2 字面子任务：逐失败样本选择 attribution ranker、以 attribution MRR 为目标的全文完全同题论文 **0 篇**；不作“成熟标准任务”主张。
- 合计：两个 RQ 的问题层级核心论文 **12 篇**，另有 6 篇通用 routing/cascading 方法论文；满足“10+、每个 RQ 5+”，但必须保留 RQ2 的层级说明。

## 16.2 实验 Gate

- RQ1 的 pooled 非误差增益 CI 为 `[0.020358, 0.047149]`；**可行性 GO**。
- RQ2 相对 RQ1 组件的 pooled 增益 CI 为 `[0.020493, 0.047276]`；**章节 GO**。
- Exp110 跨边界组件增量 CI 为 `[0.003248, 0.050716]`；**开题外部合成 GO**。

## 16.3 是否需要因本轮文献审计继续做新实验

本轮审计证明：原字面 RQ2 不能靠通用 LLM routing 论文获得 5 篇强对应，必须进行本报告采用的最小问题重述。重述后，RQ2 的 Agent 问题家族已有 6 篇 CCF B+ 正式论文，Exp108/110 又提供了该问题在失败归因阶段的非误差可行性证据，**因此本轮不触发新的补救实验**。下一步进入开题后的正式路线：冻结当前方法，补全强基线，在全新未见数据上一次性验证，并增加 risk–coverage 与可执行回退/恢复价值。若导师不接受广义 RQ2，或最终实验只能维持离线两臂 MRR ensemble，则必须把第二章改为“归因驱动的选择性恢复”并新增干预实验。

## 16.4 最终表述

> 本课题的第一章研究多智能体失败轨迹中的责任步骤完整排序，已有 ICML、AAAI、ACL、KDD、ICLR 的 6 篇整篇同题论文证明问题通用且困难；第二章研究异质失败轨迹下的自适应诊断与可靠回退，已有 ACL、NeurIPS、ICML、EMNLP 的 6 篇整篇 Agent 失败处理论文证明该问题家族通用，当前以“RQ1 结构化定位或 recency 回退”的严格 OOF 效用预测作为可行性具体化。通用 LLM routing 只提供方法依据，不冒充 Agent 问题证据。两个研究问题的输出、基线、失败条件和评价指标独立，第二章严格消费第一章的样本外输出。结合当前内部、冻结边界和跨边界统计证据，结论为：**采用 RQ2 最小重述后，两章开题 GO；最终论文尚需 pristine unseen、强基线、risk–coverage 和干预/回退验证。**
