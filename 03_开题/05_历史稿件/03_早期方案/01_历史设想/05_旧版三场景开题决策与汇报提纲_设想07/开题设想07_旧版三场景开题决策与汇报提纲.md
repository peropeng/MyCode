## 2. 主选题目

> **基于可验证故障假设与证据约束的 Agent 失败归因研究——面向长轨迹症状—根因混淆与选择性拒识**

英文工作题目：

> Verifiable Failure Hypotheses and Evidence-Constrained Attribution for AI Agents: Symptom–Cause Confusion and Selective Abstention in Long Trajectories

## 3. 为什么不是重复 Who&When Pro

Who&When Pro 已经完成 taxonomy、warm-start 单点注入、精确 who/when/type Gold，以及 All-at-once、Step-by-step、Binary-search。上述内容全部作为基础和 baseline，不作为本课题创新。

本课题进一步研究：

```text
Pro：完整轨迹 → 单次联合预测 Agent / Step / Error Mode

本课题：完整轨迹
       → 候选故障假设
       → 独立证据集合
       → ENTAILED / CONTRADICTED / INSUFFICIENT
       → 证据充分才形成软先验
       → 责任步骤排序；否则 abstain
```

直接对应 Pro 尚未解决的两个事实：故障类型常按后期症状而非早期根因判断；轨迹变长时步骤定位明显下降。

## 4. 已有可行性证据

### 4.1 原始 Who&When 真实数据

- 184/184 条可解析，`mistake_step` 100% 可映射；
- 责任 Agent 标签与 Gold 步骤 actor 一致率 0.967；
- No-Prior/Recency：combined MRR 0.216、Recall@3 0.179；
- Oracle responsible-agent hypothesis：MRR 0.517、Recall@3 0.712；
- Random hypothesis：MRR 0.286，95% 区间 [0.253, 0.341]；
- Oracle–No MRR paired-bootstrap 95% 区间 [0.259, 0.342]；
- 预注册 Bridge Gate：PASS。

这组结果只证明“正确上游假设能显著缩小步骤搜索”，不证明 predicted 方法已经有效，也不构成创新本身。

### 4.2 Pro 提供的下一阶段基础

- 12,326 条失败轨迹、18 个 error mode、26 个 benchmark、15 个 Agent 框架、3 种模态；
- warm-start 注入给出构造性 decisive-step/agent/mode Gold；
- 官方代码、数据和评价 harness 已公开；
- 原始 Who&When 用作自然失败外测，Pro 用作高保真受控主测，两者不混算。

## 5. 开题研究问题

1. Verified Hypothesis 是否相对 Pro All-at-once 改善 Step、Error 与 Joint？
2. 增益或失败是否集中在 planning、verification、coordination 和长轨迹？
3. 三值验证和证据集合约束能否减少“后期 reasoning 症状替代早期根因”的混淆？
4. 选择性拒识能否用可接受 coverage 换取更低联合错误风险？
5. 结论从 Pro 注入失败迁移到原始 Who&When 自然失败时如何变化？

## 6. 实验矩阵

| 组别 | 作用 |
|---|---|
| Pro All-at-once | 官方强基线 |
| Pro Step-by-step / Binary-search | 协议基线 |
| Direct Joint + calibrated confidence | 控制置信度因素 |
| Hypothesis Only | 检验结构分解本身 |
| Evidence Only | 检验证据检索本身 |
| Verified Hypothesis | 核心两阶段方法 |
| Verified + Abstain | 安全主版本 |
| Oracle Mode / Oracle Agent | 上界与机制 Bridge，不作为方法贡献 |

主指标：Agent accuracy、Step exact/Step@K、Error macro-F1、Joint accuracy、MRR/Recall@K、verdict+evidence 联合正确率、ECE、risk–coverage。统计采用任务级 paired bootstrap，并按模态、长度和错误族分层。

## 7. 负结果保底

以下任一结果都能形成完整论文，而不是项目失败：

- 两阶段方法无平均增益：给出分解为何不能优于联合推理；
- 只在部分 error family 有效：形成适用边界与路由策略；
- evidence 判断可靠但不改善 step：证明“解释正确 ≠ 定位有效”；
- abstention 有效：以选择性归因为主贡献；
- Pro 有效、自然失败无效：形成注入 benchmark 的外部效度分析；
- 标签/actor 不一致：形成数据可信度与可拒识条件分析。

因此保底交付是“可验证机制的收益、失效边界和拒识准则”，不是必须击败所有模型。

## 10. 答辩高频问题

**Q：这不就是 Who&When Pro 吗？**
A：Pro 负责高保真数据、taxonomy 和直接联合归因；本课题使用 Pro 作为基础，研究独立证据验证与选择性拒识能否改善其暴露的症状—根因混淆。

**Q：Oracle Agent 帮助定位不是显然的吗？**
A：是，所以 Oracle Bridge 仅验证信息桥梁与数据一致性，不作为创新；最终评价对象是从可见轨迹生成并验证的 predicted hypothesis。

**Q：没有 Docker，怎么证明因果？**
A：主线采用 Pro warm-start 注入的构造性 decisive-step Gold；软件动作撤销是可选增强，不是步骤归因论文的必要条件。自然失败数据单独标注为非因果外测。

**Q：如果方法没有提升怎么办？**
A：预注册的主要产出同时包括平均增益、错误族边界、长轨迹失效、证据充分度和 risk–coverage；负结果不改变数据与实验的完整性。
