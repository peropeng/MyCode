# 0. 独立结论

## 0.1 最终判定

> **当前方案原样开题：NO-GO。**  
> **保留现有实验、进行最小幅度重构后：修改后 GO。**

这里否定的不是前期实验价值，而是“基础两阶段实验已经 GO，所以当前题目和两章设计已经达到论文开题要求”这一推论。

现有结果能够证明：

- 在 AFTraj 同源的新鲜确认集上，可观察轨迹确实包含责任主体信号；
- 责任主体概率作为软先验，确实能够改善同一标注体系下的责任步骤排序；
- 两章之间存在一个可以真实传递预测输出的接口。

但现有结果尚不能证明：

- 第一章已经形成独立、完整、超出 Who&When/VerifyMAS 等工作的研究问题；
- 当前方法击败了近三年的强归因方法，而不是只击败“发言最多”等弱规则；
- AFTraj 的单一 `mistake_agent` 足以代表真实多智能体责任；
- 责任步骤排序等于动作级根因定位；
- “故障传播”能够提供超过责任 Agent 概率的额外价值。

最后一项已经被现有 Pilot 明确否定：修复实现错误和预处理混淆后，预测传播信息相对 Agent-only 的 MRR 增益约为 0.04%，Recall@1 增益约为 1.61%；Oracle 传播信息也没有稳定优于 Oracle Agent。该结果低于预注册的 10% 门，不得通过修改指标、降低阈值或改名重新包装。

因此，推荐保留“责任主体预测 → 责任动作排序”这条已验证桥梁，但将第一章从普通责任 Agent 分类重构为一个可独立成立的研究问题：

> **在完整可观测轨迹和责任歧义存在的条件下，如何形成有原始证据支持、能区分错误源与末端症状、并允许拒绝唯一归因的责任主体判断？**

第二章继续使用第一章对未见任务产生的真实责任分布和证据范围，研究动作级排序与可执行责任验证。

## 0.2 建议题目

### 最推荐题目

> **《面向大语言模型多智能体系统的证据约束故障归因与责任动作定位方法研究》**

这个题目比现有《运行故障分析与责任动作定位》更具体，原因如下：

1. **“故障归因”**明确第一章不是普通运行日志分析，而是回答失败后责任主体及其证据；
2. **“证据约束”**对应真实方法内容：判断必须绑定消息、动作、工具输入输出和状态证据，不能只给一段合理化文字；
3. **“责任动作定位”**保留第二章，但在完成大规模执行干预前不提前使用“因果根因”；
4. 题目不包含 OOF、bootstrap、具体模型、数据集或传播图等实验协议和实现细节。

### 可选标题

1. 《面向大语言模型多智能体系统的可信故障归因与责任动作定位方法研究》
2. 《面向全轨迹可观测多智能体系统的故障责任分析与动作级定位方法研究》
3. 《面向大语言模型多智能体系统的多视角责任归因与故障动作定位方法研究》

第一项最稳。第二项强调全轨迹，但容易把输入条件写得过细；第三项需要明确继承 MP-Bench 的“多视角归因”术语，不宜在没有完成多候选标注前使用。

# 1. 当前方案最可能被导师否定的五个问题

## 问题一：RQ1 的研究价值仍然过小，而且与已有正式任务高度重叠

当前 RQ1 的核心输出仍是：

> 给定一条失败多 Agent 轨迹，判断哪个 Agent 最值得先查。

但 [Who&When（ICML 2025）](https://proceedings.mlr.press/v267/zhang25cq.html) 已正式定义“责任 Agent + 决定性步骤”的自动故障归因任务，并给出三类自动方法。之后的 [VerifyMAS](https://arxiv.org/abs/2605.17467)、[AgentLocate](https://arxiv.org/abs/2607.07989)、[ErrorProbe](https://arxiv.org/abs/2604.17658) 又分别加入故障假设验证、多视角判定、症状回溯和工具证据验证。

因此，单纯用 AFTraj 再做一次责任 Agent Top-1 分类，即使相对发言最多规则提升 20.75%，也更像数据集内的有效探针，而不是一章独立研究工作。

**必须修改为：**第一章不仅输出一个 Agent，还要回答“什么原始证据支持该归因、它是错误源还是症状报告者、何时不应强制给出唯一责任人”。

---

## 问题二：现有 GO 依赖弱基线，尚未完成论文级强对照

当前 E1 最强冻结基线是 `most-active`，即发言最多 Agent；E2 最强基线是仅使用局部动作证据的排序器。这两个对照适合可行性测试，但不能代表近三年研究前沿。

开题答辩中导师很可能直接追问：

- 为什么没有与 Who&When 官方方法比较？
- VerifyMAS 已经先验证故障类型再定位 Agent，你的方法增加了什么？
- StepFinder、FALAT 已经把步骤定位做到时序或依赖搜索，你的加权排序器为什么仍有研究价值？
- AgentDebugX 已经形成 Diagnose—Recover—Rerun 闭环，你的两阶段划分是否只是把一个联合任务拆成两章？

若正式方法只比发言最多和局部文本好，无法支撑“论文级方法有效”的结论。

---

## 问题三：第一章的消融不支持当前方法故事

现有确认集结果中：

- 删除消息数量和位置特征，Top-1 从 0.7111 上升到 0.7444；
- 删除角色和领域先验，Top-1 上升到 0.7167；
- 只有删除故障/验证内容后，Top-1 下降到 0.7000。

这说明当前正结果主要由故障和验证文本信号贡献，结构和角色先验没有得到独立支持，部分甚至有害。

因此不能继续写成：

> “融合全过程结构、角色行为和故障内容，形成稳定的责任识别方法。”

更准确的结论是：

> “当前数据上，故障/验证内容可帮助预测标注角色，但模型是否真正识别责任证据、是否利用角色模板或错误关键词，尚未证明。”

新的第一章必须把“原始证据是否支持归因”作为显式输出和评价对象，而不是继续在原有 27 维特征上加更多统计项。

---

## 问题四：传播升级已经 NO-GO，题目和故事不能继续暗含传播增量

原实验设计把故障引入、传播和症状建模作为正式第一章，并要求其改善第二章。真实 Pilot 结果是：

- 首次实现因 Predicted 与 Shuffled 共用传播向量而无效；
- 修复后 v1 的最好相对增益约 5.72%，低于 10%；
- 清理 `is_injected/is_replayed` 等混淆后的 v2，MRR 只提高约 0.04%，Recall@1 只提高约 1.61%；
- Oracle 传播也未稳定优于 Oracle Agent。

同时，[FALAT](https://arxiv.org/abs/2606.00765) 已明确区分错误引入、继承/传播步骤，并做依赖引导搜索和修正充分性判断；[TrajDebug](https://arxiv.org/abs/2608.06346) 已研究错误触发、恢复状态和终局影响。

因此：

- “传播图”不能再作为题目中心；
- “源—传播—症状”不能单独写成创新；
- 传播分析只能作为错误分析特征，除非新增人工传播标注和可执行实验后重新跨过原 10% Gate。

---

## 问题五：责任步骤标签尚未等价于动作级根因，RQ2 的“根因”主张过早

AFTraj、Who&When 和多数离线 benchmark 提供的是标注者或 Judge 认定的决定性步骤。它能够评价“是否命中数据集标注”，但不自动证明：

> 改掉这一步以后，最终结果会发生预期变化。

[Causal Agent Replay](https://arxiv.org/abs/2606.08275) 已指出，表面执行有害动作的步骤不一定是决定步骤，并通过 `do` 干预、同策略向前重放、结果分布和置信区间评价责任；[ErrorProbe](https://arxiv.org/abs/2604.17658) 和 [AgentDebugX](https://arxiv.org/abs/2607.18754) 也已经把诊断与执行验证或恢复联系起来。

若第二章只完成一个加权步骤排序器，其工作量和贡献都可能被认为偏薄。正式论文至少需要一个规模受控、选择规则透明的可执行子集，比较：

- 预测 Top-K 动作；
- 同 Agent 随机动作；
- 相邻动作；
- 末端症状动作。

只有高排名动作的替换、撤销或重放显著改变结果，题目才可以进一步升级为动作级根因定位。

# 2. 对现有实验结论的重新定级

## 2.1 E1：责任主体识别

现有结果：

| 条件 | Top-1 |
|---|---:|
| 发言最多 Agent | 0.5889 |
| 当前方法 | 0.7111 |
| 相对提升 | 20.75% |
| 配对 95% 区间 | [0.0611, 0.1889] |

### 独立评价

这是一个**可信的可行性正结果**，但不是论文最终主张，原因是：

1. 新鲜确认集避免了明显的开发集复用；
2. 任务级置信区间下界为正；
3. 但训练和确认都来自 AFTraj，同源数据可能共享角色结构、Judge 标注习惯和显式错误表达；
4. 最强对照仍是规则方法；
5. 模块消融没有支持完整方法结构。

**定级：工程/数据可行性 GO；论文方法有效性未决。**

---

## 2.2 E2：责任主体先验引导动作定位

现有结果：

| 条件 | MRR |
|---|---:|
| Local / No bridge | 0.3909 |
| Predicted Agent Prior | 0.5002 |
| Oracle Agent | 0.6940 |
| Predicted 相对 Local | 27.96% |
| 配对 95% 区间 | [0.0810, 0.1389] |

### 独立评价

这是当前最有价值的结果，因为它证明了“粗粒度责任概率 → 细粒度步骤排序”并非纯故事。但还缺两个关键对照：

1. **Random Prior**：随机生成同形状责任分布；
2. **Shuffled Prior**：把真实 RQ1 预测在任务之间打乱。

没有这两个条件，仍无法完全排除“多加了一个角色偏置项”或数据集角色分布造成提升的解释。

此外，正式主表还必须比较 StepFinder、Who&When 官方方法和至少一个依赖/验证类前沿方法。

**定级：层级桥接可行性 GO；论文级动作定位方法未决。**

## 2.3 传播增量

现有结果未达到预注册 10% 门，且 Oracle 传播上界不稳定。

**定级：NO-GO。**

这一结论必须进入开题材料的“已否定假设”，而不是隐藏在附录。

# 4. 最小幅度重构后的研究问题

## 4.1 RQ1：证据约束、歧义感知的责任主体归因

### 一句白话

> 多 Agent 任务失败后，系统能否不仅说“最可疑的是谁”，还指出哪些原始动作、工具结果和状态证据支持这一判断；遇到多个都可能负责或证据不足时，不强行编出唯一答案？

### 一句学术表述

> 给定不读取责任金标的完整多智能体失败轨迹，研究如何联合估计候选 Agent 的责任分布、检索与候选责任一致的原始证据、区分错误源证据与末端症状证据，并在责任歧义或证据不足时输出候选集合或拒绝唯一归因。

### RQ1 的独立研究价值

RQ1 不再依赖“帮助 RQ2”证明存在意义。它独立回答三个软件可靠性问题：

1. **归因正确性**：责任主体是否判断正确；
2. **证据可审计性**：判断是否由可观察原始事件支持；
3. **归因可信性**：在模糊轨迹和多责任情况下，何时不应输出唯一结论。

RQ1 的输出为：

- Agent 责任概率分布；
- Top-K 责任候选集合；
- 每个候选对应的支持证据事件；
- 证据类型：错误源、下游继承/贡献、末端症状；
- 是否拒绝唯一归因及拒绝原因。

“下游继承/贡献”只作为证据属性，不恢复完整传播链，也不承诺其独立改善 RQ2，从而尊重传播 Pilot 的 NO-GO 结果。

---

## 4.2 RQ2：责任主体与证据先验引导的动作定位及执行验证

### 一句白话

> 第一章给出了“哪些 Agent 可疑、证据在哪里”，第二章能否据此把真正值得修改的具体动作排到前面，并通过替换或重放证明它不只是最后暴露出来的症状？

### 一句学术表述

> 将 RQ1 对未见任务产生的责任分布和候选证据范围作为软先验，与动作局部语义、工具参数、观察结果和状态变化联合进行责任动作排序，并通过受控动作替换、撤销或前缀重放估计高排名动作对最终结果的影响。

### RQ2 的独立研究价值

RQ2 独立解决：

- 如何从长轨迹中排序具体动作；
- 如何避免把检查、报错和终止步骤排为根因；
- 离线标注命中与执行结果责任之间有什么差异。

RQ2 的输出为：

- 动作 Top-K 排名；
- Agent—动作联合定位；
- 每个动作的原始证据；
- 干预后的成功率、失败类型变化及非回归结果。

---

# 5. 两章为什么各自有成果且真实递进

## 5.1 各自独立

| 维度 | RQ1 | RQ2 |
|---|---|---|
| 核心问题 | 谁应承担责任、证据是否充分 | 哪个具体动作应优先检查或修改 |
| 输出粒度 | Agent 分布、证据集合、拒识 | 动作排名、联合 Agent-Step、干预结果 |
| 主指标 | Agent/集合归因、证据 F1、风险—覆盖曲线 | MRR、Recall@K、症状误判率、干预效应 |
| 独立应用 | 事故分派、审计、归因可信度 | 调试、定位、修复验证 |
| 不依赖另一章也能回答的结论 | 完整证据和拒识是否提高归因可靠性 | 动作排序与重放是否比局部/时序基线更有效 |

RQ1 即使暂不接 RQ2，也能形成一篇“证据支持与责任歧义下的多 Agent 故障归因”小论文；RQ2 即使使用 Oracle/No prior，也能形成动作排序和干预验证的完整实验。

## 5.2 真实递进

正式链条为：

```text
失败多 Agent 完整轨迹
        ↓
RQ1：每个 Agent 的责任分布 + 支持证据 + 归因可信度
        ↓ 仅使用未见任务预测
RQ2：动作候选软加权 + 证据条件排序
        ↓
Top-K 动作替换 / 撤销 / 重放
        ↓
标注命中与结果责任的对照结论
```

RQ2 不得读取测试任务的责任 Agent 金标、责任步骤、错误模式或传播金标。训练集上的桥接特征必须来自任务级折外预测；最终测试使用完全样本外预测。

---

# 6. RQ1 的核心贡献、方法设计和强基线

## 6.1 RQ1 可以主张的核心贡献

### 贡献一：把责任 Agent 分类提升为“责任—证据联合归因”

现有 E1 只评价 Agent Top-1。新任务要求同时满足：

- 候选 Agent 正确；
- 返回的证据事件确实支持该候选；
- 不能把“检查到错误”误当成“引入错误”。

该贡献不是创造新理论，而是将 TraceElephant 的完整可观测性、Agent-as-a-Judge 的过程取证和 Who&When 的责任任务组合成一个更严格的归因对象。

### 贡献二：显式处理单一责任标签不可靠的情况

参考 MP-Bench，允许：

- 多个合理责任候选；
- 源责任与贡献责任并存；
- 证据不足时拒绝唯一归因。

这使第一章研究目标从“提高一个 Top-1 分数”提升为“提高归因可靠性和可审计性”。

### 贡献三：给出跨可观测条件、跨数据来源和角色模板的归因边界

比较：

- partial trace 与 full trace；
- AFTraj、Who&When、TraceElephant；
- 自然失败与注入失败；
- 角色名保留、匿名、随机置换；
- 显式错误词保留与屏蔽。

这类主体分析回答“什么证据真正有效”，不是堆更多基线。

---

## 6.2 RQ1 的三个方法模块

### M1：候选 Agent 中心的全过程证据对齐

**来源：**

- TraceElephant：完整输入、输出、工具日志和上下文；
- Agent-as-a-Judge：按任务要求主动收集过程证据；
- Who&When：责任 Agent 任务。

**机制：**

对每个候选 Agent，统一提取：

- 其接收到的关键信息；
- 其输出的决策或动作；
- 工具名称、参数与返回；
- 对消息、文件或环境状态的读写；
- 后续验证结果；
- 与任务要求或参考约束的一致/冲突证据。

不让模型直接对整条文本生成一段解释，而是先形成候选—事件证据对。

**预期作用：**

减少仅因角色活跃、最后发言或显式错误词而归责。

**消融：**

- `no_full_evidence`：只保留 Agent 输出；
- 完整模型：加入输入、工具、观察和状态证据。

---

### M2：错误源—末端症状证据一致性评分

**来源：**

- 软件可靠性的 fault—error—failure 区分；
- FALAT 对错误引入与继承步骤的区分；
- TrajDebug 对触发、恢复和终局影响的分析。

**机制：**

不恢复完整传播图，只判断一个候选证据更接近：

1. 引入与任务要求冲突的动作或状态；
2. 使用或扩大已有错误的贡献动作；
3. 检测、汇报或暴露已有错误的症状动作。

每个 Agent 的责任分数由源证据、贡献证据和症状证据共同决定；症状证据不能直接当作负分，而是与“是否改变状态、是否被下游使用”一起判断。

**预期作用：**

降低检查者、测试者和最终总结者被错误判为责任源的比例。

**消融：**

- `no_source_symptom`：所有错误相关证据同权；
- 完整模型：区分证据作用。

---

### M3：歧义感知的候选集合与选择性拒识

**来源：**

- MP-Bench 的多视角归因问题；
- 选择性分类（Selective Classification / reject option）：[Geifman & El-Yaniv](https://arxiv.org/abs/1705.08500)。

**机制：**

当出现以下情况时，不强制输出唯一 Agent：

- Top-1 与 Top-2 责任概率接近；
- 两个候选都存在独立支持证据；
- 支持证据与反证冲突；
- 完整轨迹缺失关键输入或工具观察。

输出责任候选集合或 `insufficient evidence`。

**预期作用：**

降低高置信错误归因，给出风险—覆盖关系。

**消融：**

- `no_abstain`：强制全覆盖唯一归因；
- 完整模型：允许集合/拒识。

注意：拒识不是独立创新，只是实现“归因可信性”研究目的的成熟机制。

---

## 6.3 RQ1 的主基线

正式主表控制在五组：

1. **当前 Agent-only 轻量模型**：现有 0.7111 方法，作为必须超过或解释的内部基线；
2. **Who&When 官方方法族**：All-at-once / Step-by-step / Binary-search 作为一组；
3. **Full-trace LLM Judge / Agent-as-a-Judge**：同样可观测字段和近似调用预算；
4. **VerifyMAS 协议基线**：若官方代码仍未发布，按论文描述实现零样本“假设验证→Agent”版本，明确标注为协议复现；
5. **ErrorProbe 或 AgentLocate**：仅在代码和数据可运行时进入主表，否则放补充实验并说明缺失资产。

规则基线（多数、发言最多、最后发言）仍报告，但不再作为论文最强对照。

---

# 7. RQ2 的核心贡献、方法设计和强基线

## 7.1 RQ2 可以主张的核心贡献

### 贡献一：严格隔离责任主体预测对动作排序的真实作用

已有实验已经给出正信号，但正式论文必须加入：

- No Prior；
- Random Prior；
- Shuffled Prior；
- 当前 Agent-only Predicted Prior；
- 新 RQ1 Predicted Prior；
- Oracle Agent；
- Oracle Evidence Scope。

这套对照是实验协议，不是创新。可作为贡献的是由该协议得到的进一步结论：

> 责任主体分布在什么数据、角色结构和轨迹长度下能够或不能够改善动作定位。

### 贡献二：责任证据条件下的动作学习排序

不是简单给属于高概率 Agent 的所有步骤加同一个常数，而是结合：

- RQ1 候选 Agent 概率；
- RQ1 返回的证据范围；
- 动作自身语义和工具参数；
- 动作造成的可观察状态变化；
- 后续验证是否直接依赖该状态。

采用 pairwise learning-to-rank 或等价轻量排序器。排序器名称不是贡献，贡献是证据粒度和受控桥接。

### 贡献三：离线归因与执行责任的分层验证

先评价数据集决定性步骤，再对可执行子集做重复重放，区分：

- 标注相关步骤；
- 可能修复的动作；
- 对结果具有稳定影响的动作。

这使论文能得到“离线归因标签与执行责任的一致性和差异”这一进一步结论。

---

## 7.2 RQ2 的三个方法模块

### M1：RQ1 样本外责任与证据软先验

输入：

- Agent 责任概率；
- 候选证据事件；
- 归因可信度；
- 是否为多候选/拒识。

使用软权重，不硬裁掉低概率 Agent。若 RQ1 拒识，自动退化为全轨迹定位。

### M2：动作局部证据与状态后果的成对排序

**理论来源：**学习排序；参考 [Pairwise Learning to Rank](https://arxiv.org/abs/1909.02768)。

动作特征仅使用可观察内容：

- 动作文本或决策；
- 工具名称、参数和返回；
- 状态读写；
- 测试、检查和重试；
- 是否位于 RQ1 证据范围；
- 是否更像源动作还是症状动作。

不使用责任步骤、`mistake_reason`、注入模板或未来 Gold。

### M3：重复重放与结果影响验证

参考 Who&When Pro 的成功前缀精确重放、SWE-Gym 的可执行环境和 CAR 的分布式干预思想。

对于 Top-K 候选：

- 替换错误工具参数；
- 撤销或替换代码编辑；
- 替换错误消息；
- 恢复到动作前状态并重复运行后缀；
- 每个干预重复若干次，报告结果分布和置信区间。

阴性对照：

- 同 Agent 随机动作；
- 候选相邻动作；
- 最终检查/报错症状动作；
- `do_resample` 式空干预。

---

## 7.3 RQ2 的主基线

主表最多五组：

1. **Local / No bridge**：只用动作局部证据；
2. **当前 Predicted Agent-only Prior**：现有 MRR 0.5002 方法，是新方法最重要的内部强基线；
3. **Who&When 官方步骤定位方法族**；
4. **StepFinder**：时序语义步骤定位；
5. **FALAT 或 ErrorProbe**：优先选择公开资产更完整的一项，另一项作为补充协议对照。

TrajDebug 主要用于生命周期与终局影响的重叠审查；CAR 主要用于干预协议对照，不必与离线 MRR 混为同一主表。

---

# 8. 进一步可行性实验：按 Gate 执行

# 8.1 Gate 0：复核基础 GO 是否仍成立

这是开题前第一优先级，不能跳过。

## G0-1：补齐 Random 与 Shuffled Prior

在当前冻结确认集上，保持候选池、局部排序器和权重搜索完全不变，仅替换责任先验：

1. No Prior；
2. Random Prior；
3. Shuffled Prior；
4. Predicted Agent Prior；
5. Oracle Agent Prior。

### 通过标准

`Predicted` 相对 No、Random、Shuffled 的 MRR 均至少提高 10%，并且任务级配对 bootstrap 95% 区间下界大于 0。

### 否定标准

若 Predicted 与 Random/Shuffled 接近，则现有两章桥接不能继续记为 GO，即使它仍高于 Local。

---

## G0-2：角色与文本捷径审计

固定当前模型，分别执行：

- 角色名匿名化；
- 角色显示顺序随机置换；
- 屏蔽 `error/failure/incorrect/mistake` 等显式词；
- 仅保留错误发生前的可观察证据；
- 留一领域或留一 Agent 框架外测。

### 通过标准

- 匿名化后仍显著高于发言最多和多数规则；
- 随机置换不能系统改变预测；
- 屏蔽错误词后不退化到接近随机；
- 至少一个外部数据或框架上保留正增益。

### 处理

若主要性能来自角色名或显式错误词，现有 E1 降级为 AFTraj 数据探针，不再作为正式方法基线。

---

## G0-3：强基线最小比较

先在 100—200 条开发任务上跑：

- Who&When 官方协议；
- Full-trace direct Judge；
- 当前轻量 Agent-only；
- VerifyMAS 协议重实现。

目的不是此时得出最终 SOTA，而是估计当前 0.7111 相对强方法是否仍有空间。

### 通过标准

当前方法或后续 RQ1 最小模型必须在预注册主指标上相对最强可运行基线提高至少 10%，且 CI 下界大于 0；若只比规则好，不能以现有 RQ1 开题。

---

# 8.2 Gate 1：RQ1 标注对象是否可稳定定义

## 数据规模

开题前构造 **240 条双人独立标注轨迹**：

- AFTraj：120 条；
- Who&When：60 条；
- TraceElephant：60 条。

覆盖：

- coding、math、general agent；
- 短、中、长轨迹；
- 2—3 Agent 和更多 Agent；
- 自然失败与注入失败；
- 完整与部分可观测条件。

## 标注字段

每条轨迹标注：

1. 合理责任 Agent 候选集合；
2. 首选责任 Agent（允许为空）；
3. 每个候选的支持证据事件 ID；
4. 反证事件 ID；
5. 证据作用：错误源、贡献/继承、症状；
6. 是否证据不足；
7. 是否存在多种合理归因。

不要求标注完整传播图。

## 标注一致性

- 单标签/证据类型：Cohen’s kappa 或 Krippendorff’s alpha；
- 候选集合：Jaccard / set-F1；
- 证据事件：span/event F1。

### 开题通过标准

- 责任类型 `κ/α ≥ 0.65`；
- 候选集合平均 set-F1 ≥ 0.70；
- 支持证据 event-F1 ≥ 0.55；
- 至少 15% 的轨迹被标注为多候选或证据不足，否则拒识问题可能缺乏实际规模。

### 停止标准

- `κ/α < 0.50` 且修改协议后仍无法提高；
- 证据事件无法稳定映射；
- 多候选比例极低且主要由标注噪声产生。

若停止，应回退到单一责任 Agent 任务，但这时 RQ1 的论文价值仍不足，需要另找独立问题。

---

# 8.3 Gate 2：RQ1 最小方法是否具有独立价值

## 数据切分

- 按规范化任务 ID 分组；
- 同任务的 rollout、改写、注入版本必须在同一折；
- 训练可使用 AFTraj 大规模标签和 Silver evidence；
- 正式主指标只在人工 Gold 上计算；
- 外部测试保持 Who&When 和 TraceElephant 独立。

## 主任务

### 任务 A：责任主体归因

指标：

- Top-1；
- macro-F1；
- MRR；
- 候选集合 recall / set-F1。

### 任务 B：责任—证据联合正确

只有同时满足以下条件才记为联合正确：

- 责任候选命中 Gold 集合；
- Top-K 证据至少命中一个人工支持事件；
- 没有只用末端症状作为唯一证据。

指标：

- Agent + Evidence Joint Accuracy；
- evidence precision / recall / F1；
- 症状误归因率。

### 任务 C：选择性归因

指标：

- risk—coverage 曲线；
- selective accuracy / selective macro-F1；
- AURC；
- 80%、90% coverage 下的错误率。

### 任务 D：可观测性与迁移

- partial vs full trace；
- AFTraj 内测 vs Who&When/TraceElephant 外测；
- 角色匿名；
- 自然 vs 注入失败。

## RQ1 完整论文 Gate

1. 在 **Agent+Evidence Joint Accuracy** 上相对最强可运行近年基线提高至少 10%，任务级配对 95% CI 下界 > 0；
2. Agent Top-1 或 macro-F1 不得因证据约束下降超过 2 个百分点；
3. 症状 Agent 误判率至少下降 10 个百分点，或相对下降至少 15%；
4. 选择性版本在相同 coverage 下显著降低错误风险；
5. 至少一个外部数据集上保留正向效果，不能只在 AFTraj 成立。

若只提高证据 F1、Agent 归因反而下降明显，则方法只能作为解释性附加模块，不能承担第一章主贡献。

---

# 8.4 Gate 3：RQ1 输出能否真实帮助 RQ2

## 两层桥接比较

### 最小桥接主张

比较：

```text
No / Random / Shuffled
    vs 最终 RQ1 Predicted Prior
    vs Oracle Agent
```

通过标准：Predicted 相对 No、Random、Shuffled 的 MRR 或 Recall@3 均提高至少 10%，CI 下界 > 0。

### 证据增量主张

若论文要进一步声称“证据约束比普通 Agent 概率更能帮助动作定位”，还必须比较：

```text
当前 Predicted Agent-only Prior
    vs 新 Predicted Agent + Evidence Prior
```

通过标准同样为至少 10% 相对提升且 CI 下界 > 0，或者症状步骤 Top-1 误判率下降至少 10 个百分点且 CI 支持。

若未通过：

- 不得声称证据范围改善了 RQ2；
- 仍可保留“证据提高 RQ1 可信性，Agent 责任分布作为 RQ2 桥梁”的较弱故事；
- 若最终 RQ1 预测也不优于 No/Random/Shuffled，则整个两章结构 NO-GO。

---

# 8.5 Gate 4：动作干预接口与结果责任

## 开题前 Pilot

选择 20 个独立任务：

- 至少 10 个软件 Agent 任务；
- 至少 5 个自然语言/工具多 Agent 任务；
- 责任动作可映射；
- 环境可重放；
- 选择规则在看到方法结果前冻结。

每个任务测试：

1. 预测 Top-1；
2. 预测 Top-3 中最可执行候选；
3. 同 Agent 随机动作；
4. 相邻动作；
5. 末端症状动作；
6. 空干预/同策略重采样。

## 可重放性 Gate

- 至少 15/20 任务能够稳定恢复到候选动作前状态；
- 原始轨迹或测试结果能够重复；
- 环境错误、模型随机性和方法失败分开统计。

## 正式论文规模

扩大到 50—100 个独立任务；每项关键干预重复运行，报告：

- 失败→成功翻转率；
- 失败类型改变；
- 非回归测试；
- 结果分布差异；
- 置信区间；
- 每任务成本。

## 通过标准

预测 Top-K 动作的干预效果相对随机/症状动作至少提高 10%，并且任务级 CI 下界 > 0；若样本量允许，建议要求绝对翻转率差至少 10 个百分点。

若离线排名提高但干预与随机无差异，论文结论必须停在“责任标注定位”，题目不能升级为根因定位。

# 14. 最终决策树

## 可以“修改后 GO”的必要条件

以下全部满足：

1. 现有 Predicted Agent Prior 相对 No/Random/Shuffled 仍跨过 10% + CI 门；
2. 角色匿名和错误词屏蔽后，RQ1 仍有可学习信号；
3. 责任—证据标注具有可接受一致性；
4. RQ1 新方法相对近年强基线在责任—证据联合指标上跨过 10% + CI 门；
5. 最终 RQ1 样本外输出相对 No/Random/Shuffled 改善 RQ2；
6. 至少 15/20 干预 Pilot 能稳定运行。

## 只能做“弱修改后 GO”的情况

- RQ1 证据和拒识有效，但没有进一步改善旧 Agent-only 的动作排序；
- 旧 Agent-only 桥接仍稳定跨过 10%；
- RQ2 的动作排序和执行验证独立形成足够内容。

此时允许的故事是：

> 第一章提高责任归因的可信性；第二章使用责任分布定位动作，但不声称证据层额外提高定位。

## NO-GO 条件

任一出现即停止：

- Predicted 与 Random/Shuffled 无差异；
- 强 Who&When/VerifyMAS/StepFinder 等基线全面优于方法，且没有新的证据或边界结论；
- 责任—证据人工一致性长期低于 0.50；
- RQ1 主要依赖角色名、显式错误词或注入模板；
- 最终 RQ1 输出不能改善 RQ2；
- 干预结果与随机/症状动作无差异，却仍想写“根因定位”；
- 为挽救结果降低原 10% 门或更换主指标。

# 15. 可用于开题材料的贡献表述

## 允许表述

1. 前期独立确认结果显示，责任主体预测可以在 AFTraj 标注体系下改善决定性步骤排序；
2. 传播信息相对 Agent-only 的额外桥接已被真实 Pilot 否定，因此不再作为核心承诺；
3. 拟研究有原始执行证据支持、能够处理多责任和证据不足的责任主体归因；
4. 拟将未见任务上的责任分布和证据范围用于动作排序，并通过执行干预验证；
5. 正式结论将区分数据集标注、证据支持和结果责任。

## 禁止表述

1. 已经提出新的故障传播理论；
2. 当前已经超过 Who&When、VerifyMAS、FALAT、StepFinder 等强方法；
3. OOF、bootstrap、Random/Oracle 是创新；
4. 当前责任步骤已经被证明是因果根因；
5. 传播 Pilot 的 0.04% 或 1.61% 增益说明传播有效；
6. 只要完成三个模块组合就构成创新；
7. AFTraj 同源确认等于跨框架泛化；
8. Judge 生成的文字证据等于人工或执行 Gold。

# 16. 两分钟导师说明

> 我的研究面向大语言模型多智能体系统失败后责任判断不可靠的问题。现有工作已经能要求模型输出责任 Agent 和决定性步骤，但真实轨迹中可能存在多个合理责任候选，完整输入、工具日志和状态证据也经常缺失；最后检查到错误的 Agent 还可能只是暴露症状。因此，第一项工作不再只做“猜哪个 Agent”，而是从完整轨迹中为每个候选 Agent 检索可审计证据，区分错误源和末端症状，在多个候选都合理或证据不足时允许输出候选集合或拒绝唯一归因。它独立评价责任 Agent、证据命中和风险—覆盖关系。
>
> 第二项工作使用第一项对未见任务产生的责任分布和证据范围，对具体动作进行排序。核心对照包括 No、Random、Shuffled、当前 Agent-only、最终预测和 Oracle，并与 Who&When、StepFinder、FALAT 等方法比较。最后在 SWE-Gym 或其他可重放环境中，对前 K 个动作做参数替换、编辑撤销或前缀重放，并与随机、相邻和末端症状动作比较，判断离线决定性步骤是否真的具有结果责任。
>
> 前期 AFTraj 新鲜确认实验已经证明责任 Agent 概率能够改善步骤排序，但它只证明接口可行。我们还真实检验了更复杂的传播链，修复实现错误后没有达到预注册 10% 门，所以传播不再写进核心承诺。开题前首先补齐 Random/Shuffled、强基线、角色与错误词捷径审计，再完成责任—证据人工标注和 20-task 重放 Pilot。所有主结论继续使用 10% 相对提升和任务级置信区间，不因负结果修改门槛。

# 17. 最终评语

现有研究最值得保留的不是“已经有一套传播方法”，而是两个事实：

1. **责任主体预测在独立确认集上确实可学；**
2. **该预测作为软先验，确实可能改善责任步骤排序。**

但硕士论文不能停在“先猜谁，再给它的步骤加分”。原样方案的 RQ1 太小、基线太弱、消融不支持完整方法故事；传播升级又已经被实验否定。因此，本次评审不接受“基础实验 GO = 当前开题方案 GO”。

最小而有论文价值的重构是：

> **将第一章提升为证据约束、歧义感知的责任主体归因；将第二章提升为样本外责任证据引导的动作排序与执行验证。**

这条路线没有发明新理论，也没有把现有模块简单并列。它围绕一个完整、可否证的方法故事组织已有理论和新实验：

```text
完整可观测证据
    → 可信的责任主体与证据集合
    → 未见任务责任分布
    → 责任动作排序
    → 执行结果验证
```

**最终判定：修改后 GO。**  
若 Gate 0 的 Random/Shuffled 或 Gate 1 的责任—证据标注失败，则应立即降为 **NO-GO**，不再围绕现有两章继续包装。
