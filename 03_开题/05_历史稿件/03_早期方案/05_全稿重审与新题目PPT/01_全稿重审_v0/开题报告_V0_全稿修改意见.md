# 开题报告V0全稿修改意见

## 一、审查范围与总判断

本次审查覆盖以下对象：

- 主审版本：`开题报告_v15第三章重构与附录版_v16.pptx`，共69页；
- 回退参照：`开题报告_v13审定意见落实版_v15.pptx`，共75页；
- 内容依据：本地开题定稿、研究现状与技术设计说明、论文与方法追溯材料、实验设计清单、参考文献目录和原任务完整历史约束。

总体判断：v16已经形成“研究现状—RQ1—RQ2—实验”的基本骨架，模板风格、章节页、页脚导航和多数方法图可以保留；但它仍把内部实现语汇、前期研究结果和正式开题实验设计混在一起，且评价指标公式的位置不符合章节职责。V0应以正式开题报告为唯一身份，保留题目与六章结构，重写第三章的证据融合表述，重构第五章的指标、对照、前期结果与预期效果，并把维度展开和训练细节集中到附录。

## 二、全局问题与落实方案

### 2.1 内容身份与时态

问题：v16第46、50页直接出现内部实验编号、运行窗口和执行条数，容易把前期研究结果误读为完整实验已经结束；多处“冻结、解封、审计、协议锁定”等管理语汇压过研究设计。

落实：正文区分“前期研究结果”与“正式实验设计/预期效果”；保留一页能够支撑可行性的前期方向性结果，删除内部实验编号、运行日志和门控叙事。数据划分、超参数和公平条件改写为“预先设定”“在对照条件间保持一致”“由训练/开发数据确定”“外层测试仅评价一次”。

### 2.2 RQ1与RQ2的连续逻辑

问题：部分页面虽画出串行流程，但前文仍提前并列罗列两组指标，弱化“RQ1输出完整责任排序，RQ2读取排序构造计划”的单向接口。

落实：第一章提出接口缺口；第二章明确两个RQ及可证伪命题；第三章按“轨迹证据—局部排序—关系聚合—证据融合—完整排序—恢复计划—隔离执行—双边验收”推进；第五章只在串行主链相应节点向下分出诊断、桥接和恢复评价支路。

### 2.3 术语与英文缩写

问题：B2、A+B、0.5/0.5、OOF、MRR、RSR、Harm、TNR等在不同页面以代码标签或缩写直接出现；“结构先验、短程过程、图效用”等表达缺少可验证定义。

落实：删除内部条件代号和固定权重展示；把两类证据统一命名为“局部行为排序证据”和“跨步骤关系排序证据”，把最终步骤称为“任务组外预测融合”。英文缩写首次出现时给出中文全称、英文全称、缩写和研究作用。评价指标首次集中出现在第五章。

### 2.4 公式位置与编号

问题：v16附录A8、A12才解释MRR、RSR和Harm，正文实验章缺少就近公式；方法公式编号按内部实现键跳号，附录又重复主文公式编号。

落实：第三章只保留方法本身的公式；第五章集中给出平均倒数排名、前K命中率、任务恢复成功率、错误干预率、执行成本和配对置信区间公式，并逐项解释符号、统计单位、方向与对应RQ。附录使用“A1—A7”编号补充表示维度、关系聚合和训练细节；重复主文公式时沿用主文编号。

术语规则：专业评测指标保留英文名称与通行缩写。首次出现写出英文全称、缩写和中文含义，后续统一使用MRR、R@K、RSR、TNR、Harm与Cost，不改写成纯中文指标名。

### 2.5 数据集与实验总体

问题：v16第38—39页仍偏向本地样本规模和数据边界管理，未充分回答数据集名称、公开来源、任务构成、轨迹/步骤/故障标注和本研究用途；诊断任务组与可执行恢复任务的统计总体容易混淆。

落实：5.1按AFTraj、Who&When和可执行软件恢复任务三类来源说明公开入口、数据内容、标注、研究用途和划分方式；明确RQ1以轨迹/任务组为单位，RQ2以可执行任务及任务×随机种子执行为单位，两类指标分别报告。

### 2.6 基线、对照、消融与预期效果

问题：现有恢复条件混有内部条件名；范围对照、排序对照和机制消融的识别目标未完全分开；先导结果与正式预期混写。

落实：诊断基线按启发式定位、直接归因、局部学习排序和时序关系建模组织；恢复对照按无诊断固定/随机次序、保留首位但替换尾部、完整预测排序和理想上界组织。单点、等规模和依赖范围属于范围对照；移除局部证据、关系证据、任务组外预测或事务机制属于组件/训练/机制消融。正式结果页只写有理论依据的方向和比较关系。

### 2.7 版式与对象

问题：v16部分公式页仍使用装饰性线条；第24页框内标签过长且层级依赖内部代号；第五章表格信息密度高；附录多页的表格与公式距离紧张。

落实：公式上下不加装饰线；图名紧邻图；同层级框体统一字号与高度；红色只标研究重点。所有实验表采用原生PowerPoint表格对象和严格三线表，只保留表顶线、表头下分隔线和表底线，不设竖线、色块或表内引文。

## 三、章节级逻辑调整

### 第一章：背景与现状

## 五、术语清单

| 术语 | V0统一定义与使用方式 |
|---|---|
| 完整责任排序 | 对任务内全部候选步骤按责任分数形成的有序列表，记为π_q。 |
| 局部行为排序证据 | 由单步骤可观察动作、结果、角色和位置特征形成的相对责任证据。 |
| 跨步骤关系排序证据 | 由四类关系通道和两轮邻域聚合形成的跨步骤相对责任证据。 |
| 任务组外预测 | Out-of-Fold prediction；每个融合训练样本由未使用该任务组拟合的基模型生成。 |
| 事务式恢复 | 候选计划从一致状态执行，验收通过才提交，否则撤销其状态变化。 |
| 非目标一致性条件 | 目标恢复之外，对参考状态、允许差分和新增冲突的联合约束。 |
| 等规模范围 | 与依赖范围在动作数量和前向跨度上匹配，但不使用目标依赖身份的控制范围。 |
| 平均倒数排名 | Mean Reciprocal Rank，MRR；人工标注责任步骤名次倒数的任务组平均，越大越好。 |
| 前K命中率 | Recall at K，R@K；责任步骤位于前K位的任务组比例，越大越好。 |
| 任务恢复成功率 | Recovery Success Rate，RSR；预算内至少一个候选通过双边验收的任务比例，越大越好。 |
| 错误干预率 | Harm Rate，Harm；实际执行中发生非目标回归或新增冲突的比例，越小越好。 |
| 执行成本 | 候选尝试数、运行时长、调用/Token、回滚次数和状态差分规模的联合报告。 |

禁用或替换：删除内部实验编号、pilot、各类“门”、B2、A+B、0.5/0.5；“冻结”按语义替换为预先设定、保持一致、固定模型结构/超参数或由训练数据确定；删除“短程过程、图效用、结构先验”等未经定义表达。

## 六、实验口径清单

- RQ1输入：失败执行轨迹及全部候选步骤；输出：完整责任排序π_q。
- RQ2输入：π_q、可执行故障状态、候选计划池和验收约束；输出：候选提交/撤销与任务级恢复结果。
- RQ1与RQ2构成串行方法链，但使用各自对应的评价指标和统计单位。
- 数据划分按任务组隔离；同任务和近重复轨迹不跨训练、开发与外层测试分区。
- 外层测试只用于最终评价；字段、模型结构、超参数和融合函数由训练/开发数据确定。
- 桥接实验保持任务、候选池、范围规则、预算、权限、执行器和验收器一致，只改变候选次序来源。
- 范围实验保持候选次序一致，比较单点、等规模和依赖范围。
- 事务机制实验保持执行结果和候选条件一致，消融撤销、非目标一致性或冲突检查。
- 正式实验结果统一写预期方向；前期研究结果单独标注，不用其替代正式实验效应量。
- 主要差异采用任务级配对自举置信区间；同时报告效应量、分层结果、安全性和资源成本。
