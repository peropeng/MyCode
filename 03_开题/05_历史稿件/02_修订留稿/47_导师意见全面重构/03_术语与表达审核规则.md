# 术语与表达审核规则

本规则用于继续修改本目录的开题正文及技术讲解。与`manuscript-writing-review`和`anti-defensive-writing`共同使用；下面的检查不能替代论文、数据清单和实现的事实核对。

正文按段分行。每段在`08_逐段溯源与学术表达核查.md`保留原文、行位置、直接依据与论断性质：已有论文事实、基于来源的比较、本文操作约定与设计、本地记录或研究计划。来源可以不是论文，正式编号引用必须是论文。不能用相关论文的一个引文替代对整段的证明，也不能用自写说明循环证明科学事实。

正式引用保持30—40篇论文，主体满足既定年份与CCF要求，预印本少于10%；数据卡与代码不计篇数。高质量中文论文用于核准专业表达，国内期刊评价与国际A/B分开记录。少列研究现状中的代表工作不等于删掉定义、方法和实验所需的论文依据。

## 1. 新增或修改一段话时，先确定它的作用

段落应当承担明确任务：说明研究对象，给出已有研究证据，指出与本课题直接相关的不足，提出研究问题，解释方法选择，或者说明实验怎样检验主张。

先写这一段要让读者理解的事实和关系，再写正文。删去没有增加定义、证据、推理或实际操作的解释。第一章的相关研究围绕已定题目及研究内容组织；论文的不足要具体到它的对象、输入、操作或评价条件，并直接支撑本课题的问题。

不能通过编造已有方法的缺陷来增强论证。StepFinder已有时序与全局交互建模，Agentless等方法已有补丁验证；本课题应说明自己的具体设计与需要检验的作用。

第一章从智能体执行轨迹直接展开。后续修改不再补回LLM、Agent的基础介绍。

正文小节标题使用概括内容的学术名称，如“研究背景与意义”“根因排序模型”“数据划分与使用原则”。不用“从……说明……”“……分别验证什么”“……为何分开”等写作提示或讲解式标题，模块数量在正文交代。

研究现状保留“国内外研究现状”总节，内部按两项研究内容分小节。仅保留直接支持论证的代表工作，取消论文逐篇列点；段落重心是相关方法的具体不足、影响及其与本课题的关系。方法名、作者与年份随论述保留。MAST等无直接作用的文献移出正式引用。

章节衔接必须包含实际推理：背景明确分析对象，现状分析相关方法的不足，1.3之前归结这些不足分别影响排序与恢复的什么环节，再提出RQ。不得用“上述研究提供基础，本文进一步研究……”替代这条推理。

三张方法图保留原结构并同步文字；基线表保留已确认字段，指标用表外文字说明。正文删除Moto案例图。

## 2. 核心术语固定含义

| 术语 | 本文中的含义 | 后续修改要求 |
| --- | --- | --- |
| 智能体运行故障 | 一次智能体任务执行结束后未满足任务完成要求 | 在首章给出任务失败条件；恢复部分明确限定软件任务 |
| 执行工作流 | 智能体围绕任务选择动作、调用工具、接收反馈的执行过程 | 用来交代步骤产生的背景，避免与报告章节或研发阶段混用 |
| 执行轨迹 | 一次任务实际执行过程的有序记录，包含中间推理、动作与可见环境观察 | 与某一原始任务对应，保留步骤编号及来源边界 |
| 步骤 | 轨迹中可逐项分析的决策或交互活动；具体边界按数据源保留 | 先解释行为含义，在数据适配中说明编号、上下文与动作边界；不能更改原标注粒度 |
| 根因候选 | 轨迹中可能对任务失败起决定作用、需要检查的历史步骤 | 以步骤为候选单位；标注位置的含义遵循各数据来源 |
| 根因排序 | 对根因候选评分，形成优先检查次序 | 交代输入、输出及使用场景；评分不自动成为因果效应或完整责任真值 |
| 失败任务恢复 | 从失败后留下的代码和环境继续修正，完成原任务 | 说明起点、允许信息、停止及最终验收条件 |
| 步骤表示 | 将步骤的文本、执行者及结构信息编码成数值向量 | 说明各字段来自哪里；不使用标签、参考答案或诊断理由作输入 |
| 多关系消息传递 | 沿预先构造的几类步骤关系汇集邻居向量并更新当前向量 | 明确关系判据、门控及融合操作；结构相同不自动成为因果依赖 |
| 全局自注意力聚合 | 每个步骤读取同一完整轨迹中的相关信息，形成自己的上下文 | 说明查询对象与读取范围；不能把注意力权重当作最终排序分数 |
| 历史编辑 | 失败执行中实际改变项目源码的既往操作及其代码差异 | 从排序中筛选并去重；使用前核对当前实现 |
| 目标测试 | 检查本次任务要求的预先确定的反馈测试 | 开始恢复前固定，不能由独立验收反馈补充 |
| 回归测试 | 检查需要保留的已有行为的反馈测试 | 保护初态已通过且应保持的测试项 |
| 累计测试保持 | 新候选继续通过已受保护的回归项和已通过目标项，才更新当前代码 | 按测试标识逐项检查；允许没有新增通过项的候选，不写成每轮必然改善 |
| 独立验收 | 与生成过程隔离，对选定交付进行的最终测试 | 验收结果不反馈给正在生成补丁的模型 |

## 3. 专业词汇与符号的准入条件

新增专业词必须同时说明：它指什么、作用于什么对象、在当前研究中做什么，以及与前后内容的关系。已有稳定名称保持一致，不能为避免重复而换成另一术语。

不恢复“源码缺陷定位”这一无关对比段，也不为了讲清本文而额外展开无关研究方向。必须使用相邻领域的方法时，直接说明本研究实际借用的操作及来源。

符号应在首次出现的同一句或紧邻句中定义，交代所属对象和取值。正文用中文可以清楚表达时优先用中文。技术讲解中的`y`只表示某条训练轨迹的标注错误位置；预测时没有这个标签，恢复器也不读取它。

模块命名跟随实际运算。当前模型使用单标签位置交叉熵，不能改称成对排序损失；当前注意力来自同一轨迹，不能改称跨模态交叉注意力；基于测试更新代码不能改称已实现通用事务恢复。

当前配对是日志中可识别的显式决策上下文及其后续动作，不能泛化为任意工具请求与返回。当前原型仅编码步骤记录字段及匿名角色，没有原始任务说明的独立编码支路；背景中的任务要求分析动机不能冒充已经实现的输入机制。步骤边界沿原数据源保留，不能用无来源的一条消息/一次调用及反馈作为跨来源通用定义。

## 4. 数据、数字与证据的维护

- 数字必须写清单位、来源、用途和状态，区分发布总量、筛选后的实际数量、计划样本数及已完成运行数。
- 不用“几折”或A/B/C遮蔽数据职责。训练、验证、开发比较与独立评价分别说明；按原问题隔离派生轨迹。
- 旧实验被反复用于选择方法后，仍保留为开发证据。重新划分或重新命名不能使旧数据变成未使用的独立评价材料。
- 既有320、294、492、122等数量按真实清单和筛选程序解释；整齐的20题是研究计划规模，不能与公开数据集规模混为一谈。
- 完整方法、去除模块的消融、排序替换和重复初始化分别计数，运行次数与问题数分别报告。
- 文献效果、当前实现和拟研究方案分别陈述。示意例子不写成已完成实验；不同运行的片段不拼接成同一条成功过程。

## 5. 每次实质修改的审核过程

1. **内容核对：** 核对所改主张的论文或实现依据，检查它是否仍服务于两个研究问题。
2. **五轮写作审核：** 依次检查冗余；主语与动作；句段结构；术语一致性；数字和引文。记录确实发现的原句、修订及理由。
3. **防御性表达复核：** 删除重复澄清、空泛限定和与论证无关的比较；保留会改变研究含义的适用条件与真实不足。
4. **跨文件核对：** 对齐正文、技术讲解、术语表和参考文献；更改模块名称或数据方案时检查相关章节。
5. **交付核对：** 统计“参考文献”节之前的正文非空白字符数；完整参考文献直接列在文末，不计入正文限制。检查正文引用与文末条目对应、符号定义及学校要求是否覆盖。将待核实事项写入审核记录，不以润色掩盖。

局部修改审核修改段落及其上下文；影响研究对象、主张、术语或实验设计时，扩大到相关章节。完整重构执行全文审核。

## 6. 本轮需要持续保留的判断

开题正文直接说明连续行为、错误传播、分散反馈与根因排序之间的关系，陈述排序怎样组织检查次序并服务于恢复。不预设反对者，不以“若已有唯一错误步骤则无需排序”等反向假设开启论证，也不突然插入场景来限定“哪些地方才有必要”。具体例子保留在方法说明或独立技术讲解中。

排序是否有助于恢复，要检查筛选后的历史编辑和实际修复输入是否改变，并用共同条件下的结果检验。

预期创新要落在具体的信息组织或状态更新设计及其证据上。消息传递、自注意力、反馈修复和测试验证都是已有基础技术；技术名称的专业程度不能代替研究贡献。

## 题目一致与引用位置（2026年10月29日补充）

1.1只围绕已定题目解释执行轨迹、步骤、运行故障、根因排序与恢复的关系。删除无关的通用软件智能体工作流背景，不使用突兀的“失败归因”叙述；具体论文、作者、方法及其特定错误定义在1.2介绍。执行轨迹先交代完整过程，步骤先交代具体决策或交互活动，编号与来源边界放到数据适配。专业中文的组织方式实际查读高质量中文论文，英文论文支撑专业对象和做法，不能将中文来源没有给出的定义强加给它。

引用紧贴其直接支撑的论断，避免段末堆列多篇。综合比较和本文设计的依据可以保留在逐段溯源，不用一组论文替整段背书。文献比例分别报告全部CCF A/B、非理论文献的年份合规比例及预印本占比；按本稿引用用途，ReAct、Reflexion及排序学习、图表示、自注意力等基础机制计入理论/基础文献。
