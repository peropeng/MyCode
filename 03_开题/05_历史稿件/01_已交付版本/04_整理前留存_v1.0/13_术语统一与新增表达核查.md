# 术语统一与新增专业表达核查

| 固定用语 | 含义及使用位置 |
| --- | --- |
| 运行故障 | 理解、决策或操作偏离任务要求并造成错误结果或任务未完成 |
| 运行故障恢复 | 从故障发生后保留的代码与环境继续求解原任务 |
| 根因步骤 | 研究中优先排查的历史步骤，监督评价时明确为数据集中标注的根因步骤 |
| 角色标识、角色编号 | 前者为日志中的记录归属，后者为轨迹内转换得到的编码输入 |
| 步骤文本 | 实际保存的内容、动作和推理记录组成的统一文本 |
| 相邻步骤、同一角色 | 根据执行顺序及日志角色标识连接记录 |
| 记录结构相同、动作结构相同 | 根据字段的数据类型、数量及嵌套形式分组，动作字段非空才参与后一类 |
| 步骤上下文 | 为每个待评分步骤从完整轨迹汇集的相关信息 |
| 目标测试、回归测试、保护集合 | 分别检查原任务要求、保留已有行为，并将已通过项作为后续代码更新条件 |

本轮新增或改写的专业表达均已按上述对象核对。未将记录格式解释为语义相同，未将角色编号解释为真实身份或职责语义，未将数据标签解释为人工标注。任务类别差异与记录形式差异分别陈述，不把不同数据集自然视为无重叠的独立来源。

全量可见文字检查覆盖完整正文、技术讲解、三张SVG与六张表。执行者、身份、标注错误、关键错误、失败任务和分号检出数均为0。PPT另在导出后扫描并逐页检查。


本轮将关系名统一为同一角色，并同步其定义、图和讲解。修复依据、候选生成条件、代码状态更新及阶段成果保持均按已有对象说明。难点直接围绕排序质量和恢复效果，5.2正文不再逐项复述表中设置。


本轮输入特征统一为角色标识、角色编号及同一角色，StepFinder介绍、目标、方法与图文均已更新。执行工作流的背景引入已删除。根因步骤界定与14.2%的定位结果分句呈现。PPT待后续同步。

全文范围以执行轨迹中的跨步骤证据为主线。角色标识表示记录归属，目标和方法采用角色编号。StepFinder原文介绍采用角色标识，避免把本地匿名编号规则写成原论文的统一设定。相关论文和外部基线的智能体设定不转述为本文自有架构。
